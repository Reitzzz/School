# 第五章 中断系统详解笔记

## 一、中断的概念与中断源分类

### 1.1 中断的概念

**专业术语描述**  
中断是指中央处理器（CPU）在顺序执行程序指令流的过程中，由于内部或外部的随机突发事件（即中断源）发出请求，CPU 暂停当前正在执行的**主程序**（后台程序/进程），保护当前的运行状态（现场保护），转而执行一段预先设计好的、用于处理该突发事件的**中断服务程序（ISR）**。处理完毕后，CPU 恢复先前保护的状态（现场恢复），并返回主程序**断点处**继续执行后续指令。其核心机制是**硬件级的异步响应**，具有以下作用：

- **提高执行效率**：CPU 无需轮询查询外设状态，可利用等待时间处理其他任务。  
- **实现实时处理**：能够对外部紧急事件或硬件请求做出快速响应。  
- **故障与异常处理**：遇到掉电、内存错误等致命问题时，系统能立刻采取保护措施。

**通俗概念讲解**  
想象你正在**看书**（主程序）。突然，你设定的**闹钟响了**（中断请求）。你无法同时看书和关闹钟，于是你在正在读的那一行**折个角做记号**（保存现场/断点），放下书去**关闹钟**（执行中断服务程序）。关完闹钟后，你回到桌前翻开书找到那个折角，继续往下读（恢复现场/中断返回）。这种机制的好处是你不用每隔几秒抬头看闹钟（轮询效率低），只管专心看书，闹钟自己会提醒你。

### 1.2 中断源的分类

**专业术语描述**  

中断源通常分为 **硬中断（外部中断）** 和 **软中断（内部异常）** 两大类。

- **硬中断（外部中断）**：由 CPU 内核外部的硬件电路产生，信号通过特定物理引脚传入，产生时刻与处理器工作时钟异步。在 STM32 中包括：
    - **片内外设中断**：如定时器 TIM、DMA、ADC 等外设产生，大部分直接连向 NVIC。
    - **片外用户设备中断**：如外部按键、传感器，这类设备需要借助于 EXTI 接口模块向 NVIC 请求中断。

- **软中断（内部异常）**：在执行指令时 CPU 内部产生，与处理器工作时钟同步。引发原因包括：
    - 编译器设置的断点或单步调试。
    - 系统调用指令（如 SVC）。
    - 执行指令时发生的各种故障（如除零操作、堆栈溢出、内存访问错误等）。

**通俗概念讲解**  

- **硬中断**：好比**身体外部的物理刺激**。片内外设就像身体内部器官发出的信号（胃饿了、腿抽筋），大脑（CPU）直接感知；片外引脚就像皮肤接触外界（有人戳你一下），皮肤神经末梢（EXTI）整理成电信号再传给大脑。
- **软中断**：好比**大脑自己胡思乱想出的问题**。例如你算错一个数（除零），大脑自己发现逻辑崩了；或者在脑子里对自己说“读到这里停一下”（调试断点）。

## 二、中断嵌套与优先级排队方法

### 2.1 中断嵌套的概念

**专业术语描述**  
当 CPU 正在处理某一低抢占优先级中断的服务程序时，系统又接收到了抢占优先级更高的新中断请求，CPU 会暂停当前的中断处理，优先去响应并执行那个优先级更高的任务。高级别中断执行完毕后，再返回原先低级别中断的服务程序继续执行，这就形成了**中断嵌套**。

**通俗概念讲解**  
你是一个**急诊室医生**（CPU）。你正在给一个**崴脚的病人**（低优先级中断）看诊。突然，救护车送来一个**心脏骤停的病人**（高优先级中断）。你肯定会立刻放下崴脚的病人，先去抢救心脏骤停的病人（中断嵌套发生）。等把危重病人抢救回来送进病房后（高优先级结束），你再回来继续给崴脚的病人上药包扎（返回低优先级继续执行）。

### 2.2 中断优先级的排队方法

**专业术语描述**  
由于多个中断源可能同时发出请求，CPU 必须按照一定调度方式确定响应次序。常见的优先级排队方法有：

1. **软件查询方法**：将所有中断请求信号存入寄存器，由软件顺序读取状态。**优先级的确定完全取决于程序查询的先后顺序，先查到的优先级高**。
2. **硬件排队电路**：通过菊花链或比较器等专门硬件电路，优先级由中断请求信号物理连接的**引脚位置**直接决定。
3. **专用中断控制器**：使用可编程的中断控制器件（如 ARM 架构中的 NVIC 控制器），软件可以通过**写入寄存器灵活设定和修改各个中断源的优先级**。

**通俗概念讲解**  

1. **软件查询**：老师（CPU）问“谁有问题？”。第一排举手（先查）→回答；第二排举手（后查）→后回答。顺序是老师**问的顺序**决定的。
2. **硬件排队**：像银行的 VIP 通道。最尊贵的客人坐在离门最近的物理位置上，门一开他先进，这是**物理位置**决定的特权。
3. **可编程控制器（NVIC）**：NVIC 就像老师手里的一块白板。
白板上写着今天回答问题的顺序：“1号小明，2号小红，3号小刚”。<br>
**老师可以随时擦掉重写**，比如发现小刚今天有急事，就把他改成1号。
第二天又可以改成别的顺序。
每个中断源的优先级，就是白板上的数字，**软件想怎么写就怎么写，随时能改**。

## 三、CM3 中断源优先级划分与优先级分组

### 3.1 中断优先级划分

**专业术语描述**  

- **负数优先级**：在 Cortex-M3 内核中，复位（Reset）、不可屏蔽中断（NMI）和硬故障（HardFault）这三种系统内部异常拥有绝对最高的权限，其优先级被硬件固定为不变的负数（如 -3、-2、-1），软件无法修改和屏蔽。
- **可编程优先级**：其余的外部中断和部分内部异常为正数优先级，可通过 NVIC 中的优先级寄存器组（IPRx）设置。优先级排队原则是：**数值越小，代表的优先级别越高**（如 0 优先于 1）。STM32 精简了原本的 8 位优先级设计，仅使用了高 4 位，因此最多支持 16 个可编程的中断优先级别（0 至 15）。

**通俗概念讲解**  

- **负数优先级（复位、NMI、HardFault）**：这是急诊室里的**心脏除颤仪电源总闸**。不管医生在干什么，只要总闸跳了（断电复位）或发生严重火灾（硬故障），所有病人都得让路。这个特权是天生的（硬件固定），医生无法通过软件设置说“别理那个总闸，先看病”。
- **正数优先级（0-15）**：这是普通的挂号单号。数字是 0 号 < 1 号 < 2 号。**号越小的人越有特权插队**（数值越小，优先级越高）。

### 3.2 优先级分组

**专业术语描述**  
STM32 通过配置系统控制模块中的应用程序中断及复位控制寄存器（SCB->AIRCR）的 **PRIGROUP** 位段，将 4 位优先级编码进一步划分为两个部分：**抢占优先级** 和 **子优先级**。

- **抢占优先级**：决定是否可以产生中断嵌套。**只有抢占优先级高的新中断，才能打断当前正在执行的抢占级低的中断服务程序**。
- **子优先级**：*当两个中断的抢占优先级相同时*，它们之间不能互相嵌套。若两者处于挂起状态并等待响应，*CPU 会优先响应子优先级高的那个*（数值小者优先）；若抢占级和子优先级都相同，则按*硬件通道编号（中断向量号）小的优先响应*。

优先级分组的位数划分由 `NVIC_PriorityGroupConfig()` 函数配置，常见分组如下：

- `NVIC_PriorityGroup_0`：抢占优先级占 0 位，子优先级占 4 位。所有中断均不能嵌套，只能按子优先级和硬件编号排队响应。
- `NVIC_PriorityGroup_4`：抢占优先级占 4 位，子优先级占 0 位。允许 16 级全嵌套，适用于实时性要求极高的复杂系统。

**通俗概念讲解**  
优先级数值就像一张**扑克牌**。这 4 位二进制数据好比**花色**（抢占级）和**点数**（子级）。

- **抢占优先级 = 花色**。规则：黑桃（高）可以压住红桃（低），强行出牌（中断嵌套）。
- **子优先级 = 点数**。规则：如果大家都是红桃（抢占级相同），那就比点数大小（A > K > Q），大的先出牌（先响应）。

**分组配置就是规定这张牌哪几位是花色，哪几位是点数**：

- `Group_0`：全是点数，没有花色。大家都是同一花色，**不能压牌（不能嵌套）**，只能按点数顺序出。
- `Group_4`：全是花色，没有点数。**压牌现象极多（嵌套极多）**，谁的牌面花色大谁先出。

## 四、中断服务程序与中断向量

### 4.1 中断服务程序（ISR）

**专业术语描述**  
中断服务程序是为了处理某一特定突发中断事件而专门编写的一段功能代码，当满足触发条件且被响应时由系统自动调用。它与普通子程序的主要区别如下：

- **触发方式**：子程序由主程序主动调用（Call）；**中断程序由硬件随机触发，CPU 被动跳转**。
- **参数传递**：子程序可以有传入参数和返回值；**中断程序既不能传入参数，也不能有返回值**。
- **返回机制**：中断执行完毕必须依赖专门的中断返回指令来恢复内核上下文。编写代码时要求“快进快出”，并且**必须通过软件语句清除对应的中断挂起标志位**（例如 `EXTI_ClearITPendingBit()`），否则退出 ISR 后硬件会认为请求依然有效而重复进入。

**通俗概念讲解**  

- **普通子程序**：你口渴了，**主动**走去厨房倒水喝。你知道倒完水要**回到**沙发（返回地址）。
- **中断服务程序（ISR）**：门铃响了。你**被动** <u>（触发方式）</u>放下书去开门。开门时你手里**不能拿着书** <u>（参数传递）</u>，开门后你**不会给门外的人带一杯水回来** <u>（返回机制）</u>。最重要的是，开完门**必须把门铃的灯按灭** <u>（清除挂起标志）</u>，否则你刚转身坐下，门铃还亮着，系统以为有人还按着门铃，会让你**刚坐下又起来去开门**（死循环）。

### 4.2 中断向量与中断向量表

**专业术语描述**  

- **中断号**：系统为每一个中断源分配的唯一数字标识，通常从 0 开始顺序编号。中断号本身不包含入口地址信息，而是作为“索引”或“编号”，用于定位中断向量表中对应的表项。例如，定时器中断可能被分配为中断号 5，外部按键中断为中断号 8。
- **中断向量**：指代特定中断服务程序的物理入口地址（32 位绝对地址指针）。
- **中断向量表**：系统中所有中断源的入口地址（向量）按照特定的中断号顺序，集中、连续地存放在存储器某个固定区域内（通常是 0x0000 0000 或映射后的 Flash/SRAM 首地址），形成的一张“地址指针表”。当 CPU 响应中断时，硬件会根据中断号查阅此表，将对应的向量加载到程序计数器（R15/PC）中，从而精确实现当前程序向中断处理程序的跳转执行。


**通俗概念讲解**  
- **中断号**：这是**房间号**（比如 15 号房间）。
- **中断向量表**：这是一本**大楼的楼层索引簿**。
- **中断向量**：这是**房间里的具体坐标**，或者**通向房间的那扇门**。当 CPU 要去 15 号房间处理事情时，它**不自己找路**，而是翻开索引簿第 15 页，上面写着“15 号房入口在坐标 XXX”，然后 CPU **瞬间传送到那个坐标**。

## 五、中断处理过程（五个阶段）

一次完整的中断处理机制由硬件与软件协同配合，共分为五个主要阶段。

### 阶段一：中断请求

**专业术语描述**  
外设或硬件产生有效的中断请求信号。此时硬件会自动将该中断源标记为 **挂起（Pending）** 状态，保存在中断挂起寄存器中。如果是片外用户设备，先在 EXTI_PR 记录挂起，随后向 NVIC 传递请求并由 NVIC_SETPEND 再次挂起记录。

### 阶段二：中断判优

**专业术语描述**  
针对处于挂起状态的所有请求，NVIC 依据开发者预设的抢占优先级、子优先级规则自动进行硬件调度排队，**挑选出当前优先级最高且未被屏蔽的中断予以响应**。

### 阶段三：中断响应

**专业术语描述**  
CM3 内核**停止当前原程序的执行。由硬件自动完成现场的关键保存工作**：将程序断点（PC 寄存器值）以及核心运算寄存器（如 R0~R3、xPSR、LR 等）压入堆栈，随后查阅向量表获取 ISR 的入口地址并跳转。

### 阶段四：执行中断处理

**专业术语描述**  
CPU **进入中断服务程序运行相应的处理逻辑（如点亮 LED、蜂鸣器发声等）**。若服务程序内部较复杂，可能还包含由软件补充压栈保护 R4~R11 寄存器，并根据逻辑进行嵌套的开关中断控制。

### 阶段五：中断返回

**专业术语描述**  
在代码结束前必须清除此前的**中断挂起**状态标记（如由软件显式清除 EXTI 挂起位）。最后**执行特定的中断返回指令，由硬件负责从堆栈中弹出先前保存的断点与现场寄存器数据，平滑恢复到被中断的原程序继续运行**。

### 通俗概念讲解（快递员送货流程）

1. **请求**：你家**门铃响了**（硬件信号），快递员在门口等着（挂起）。
2. **判优**：你正在吃泡面（当前程序），看了一眼猫眼。如果是送重要文件的（高优先级），你**立刻开门**；如果是发小广告的（低优先级/被屏蔽），你**假装没听见**（不响应）。
3. **响应**：你决定开门。先把**手里的筷子放下，把嘴里的面咽下去，记住看到哪个电视剧镜头**（硬件自动入栈/保护现场）。
4. **处理**：**开门，签字，拿快递**（执行 ISR 代码）。
5. **返回**：关门前把**门铃复位**（清除挂起位），然后**坐回沙发，拿起筷子，盯着电视回想刚才看到哪了**（出栈/恢复现场），继续吃面。

## 六、掌握外部控制程序的编写（以按键触发 LED 为例）

基于外部芯片信号（如独立按键）触发微控制器中断（控制 LED 闪烁或蜂鸣器发声）的编程主要由四个配置流程与中断程序自身组成。

### 6.1 GPIO 与时钟初始化

**专业术语描述**  
针对按键输入设备，需要将其接入的 GPIO 端口配置为相应的输入模式（例如配置为 `GPIO_Mode_IPU` 上拉输入，或 `GPIO_Mode_IPD` 下拉输入），并使能所在的端口时钟。同时也要完成被控制的输出端（如 LED、蜂鸣器使用的引脚）的推挽输出初始化。

**代码示例**  
```c
// 使能 GPIO 和 AFIO 时钟
RCC_APB2PeriphClockCmd(RCC_APB2Periph_GPIOE | RCC_APB2Periph_AFIO, ENABLE);

GPIO_InitTypeDef GPIO_InitStructure;

// 配置按键引脚（PE2）为上拉输入
GPIO_InitStructure.GPIO_Pin = GPIO_Pin_2;
GPIO_InitStructure.GPIO_Mode = GPIO_Mode_IPU; // 上拉输入
GPIO_Init(GPIOE, &GPIO_InitStructure);

// 配置 LED 引脚（PB5）为推挽输出
GPIO_InitStructure.GPIO_Pin = GPIO_Pin_5;
GPIO_InitStructure.GPIO_Mode = GPIO_Mode_Out_PP;
GPIO_InitStructure.GPIO_Speed = GPIO_Speed_50MHz;
GPIO_Init(GPIOB, &GPIO_InitStructure);
```

### 6.2 AFIO 转接映射配置

**专业术语描述**  
因为中断请求信号来源于片外引脚，必须开启 AFIO（复用功能 I/O）模块时钟。随后调用转接函数 `GPIO_EXTILineConfig()` 设定片外中断配置寄存器，将某个具体的 GPIO 口硬件通道（如 PE2）准确转接映射到对应的 EXTI 外部中断线通道上（如 EXTI_Line2）。

**代码示例**  
```c
// 将 PE2 映射到 EXTI 中断线 2
GPIO_EXTILineConfig(GPIO_PortSourceGPIOE, GPIO_PinSource2);
```

### 6.3 EXTI 接口配置

**专业术语描述**  
借助 `EXTI_InitTypeDef` 结构体配置外部中断/事件控制器的通道属性。需要明确指定中断线（EXTI_Line）、配置工作模式为中断模式（`EXTI_Mode_Interrupt`）、设定触发有效电平（例如 `EXTI_Trigger_Falling` 下降沿触发，或 `EXTI_Trigger_Rising` 上升沿触发），并最终开启线路命令（`ENABLE`）以解除该通道的屏蔽状态。

**代码示例**  
```c
EXTI_InitTypeDef EXTI_InitStructure;

EXTI_InitStructure.EXTI_Line = EXTI_Line2;               // 选择中断线 2
EXTI_InitStructure.EXTI_Mode = EXTI_Mode_Interrupt;      // 中断模式
EXTI_InitStructure.EXTI_Trigger = EXTI_Trigger_Falling;  // 下降沿触发
EXTI_InitStructure.EXTI_LineCmd = ENABLE;                // 使能中断线
EXTI_Init(&EXTI_InitStructure);
```

### 6.4 NVIC 控制器配置

**专业术语描述**  
使用 `NVIC_PriorityGroupConfig()` 确立全局的优先级分组策略。之后配置 `NVIC_InitTypeDef` 结构体，分配具体的中断通道标识（例如 `EXTI2_IRQn`），明确赋予其具体的抢占优先级（`PreemptionPriority`）与子优先级数值（`SubPriority`），最后将该通道的状态指令设为 `ENABLE` 允许内核响应。

**代码示例**  
```c
// 设置优先级分组为 Group_2（2 位抢占，2 位子优先级）
NVIC_PriorityGroupConfig(NVIC_PriorityGroup_2);

NVIC_InitTypeDef NVIC_InitStructure;

NVIC_InitStructure.NVIC_IRQChannel = EXTI2_IRQn;          // 指定中断通道
NVIC_InitStructure.NVIC_IRQChannelPreemptionPriority = 1; // 抢占优先级 1
NVIC_InitStructure.NVIC_IRQChannelSubPriority = 1;        // 子优先级 1
NVIC_InitStructure.NVIC_IRQChannelCmd = ENABLE;           // 使能通道
NVIC_Init(&NVIC_InitStructure);
```

### 6.5 编写中断服务程序并清除挂起标志

**专业术语描述**  
所有的环境配置就绪后，在相应的源文件中找到启动文件所规定的中断向量函数名（如 `void EXTI2_IRQHandler(void)`）编写具体响应代码。最为关键的一点：在处理完具体事件（例如控制引脚电平翻转）后，**必须**调用清除函数 `EXTI_ClearITPendingBit()` 强制将 EXTI_PR 挂起寄存器中对应的有效位清零，以防止程序在退出 ISR 后由于挂起位未清除而陷入不断触发执行的死循环。主函数中，仅需在按序调用以上配置函数后提供一个用于阻塞运行的永久循环（`while(1){}`）即可被动等待事件触发。

**代码示例**  
```c
// 中断服务函数（通常写在 stm32f10x_it.c 中）
void EXTI2_IRQHandler(void)
{
    // 检查是否确实是 EXTI_Line2 触发的中断
    if(EXTI_GetITStatus(EXTI_Line2) != RESET)
    {
        // 执行具体处理：翻转 LED 状态
        GPIO_WriteBit(GPIOB, GPIO_Pin_5, 
                     (BitAction)(1 - GPIO_ReadOutputDataBit(GPIOB, GPIO_Pin_5)));
        
        // 关键步骤：清除挂起标志位
        EXTI_ClearITPendingBit(EXTI_Line2);
    }
}

// 主函数结构
int main(void)
{
    // 依次调用初始化函数
    GPIO_Config();   // 包含 6.1 的代码
    AFIO_Config();   // 包含 6.2 的代码
    EXTI_Config();   // 包含 6.3 的代码
    NVIC_Config();   // 包含 6.4 的代码
    
    while(1)
    {
        // 主循环空转，所有工作由中断完成
    }
}
```

### 6.6 通俗理解四步配置法

**通俗概念讲解（如何让门铃控制你屋里的灯）**

1. **GPIO 初始化**：把门铃按钮连上电线（时钟使能），设定它是按下去才通电的那种开关（上拉输入）；把屋里的灯泡插上插座（推挽输出初始化）。
2. **AFIO 映射**：告诉保安室（EXTI）：门口那个按钮（GPIO_Pin）归 2 号保安（EXTI_Line2）管。
3. **EXTI 配置**：告诉保安：只要 2 号保安看到按钮被按下去的那一瞬间（下降沿触发），就立刻拉响警报（中断模式使能）。
4. **NVIC 配置**：告诉大脑总调度中心（NVIC）：如果听到 2 号保安的警报（EXTI2_IRQn），请以 VIP 级别（抢占优先级）处理，别耽误事。
5. **中断服务函数**：这是你大脑听到警报后的反应——伸手按一下灯泡开关（LED 翻转）。**最重要的一步**：伸手把保安室的警报复位按钮按掉（`EXTI_ClearITPendingBit`）。否则保安以为按钮还卡着没弹起来，会不停地拉警报，你就得不停地开关灯直到灯泡烧掉（死循环）。
