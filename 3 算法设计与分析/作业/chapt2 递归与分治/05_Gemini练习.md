# 练习 1：合并并去重

## 题干

**题目描述**
给定两个升序排列的数组 A 和 B，请将它们合并成一个新的升序数组 C，并且合并后的数组中不能包含任何重复的元素。

**输入格式**
第一行为两个正整数 $n$ 和 $m$，分别表示数组 A 和数组 B 的长度。
第二行为 $n$ 个升序排列的整数，表示数组 A。
第三行为 $m$ 个升序排列的整数，表示数组 B。

**输出格式**
输出合并且去重后的升序数组，元素之间以空格分隔。

**数据范围**
$1 \le n, m \le 10^5$，数组元素的值在 $[-10^9, 10^9]$ 范围内。

**输入样例**
```text
4 5
1 2 4 5
2 3 5 6 7
```

**输出样例**
```text
1 2 3 4 5 6 7
```

---

## 解决思路

这道题是基础“双指针合并”算法的变种。我们可以继续沿用双指针 $i$ 和 $j$ 分别指向两个数组开头的逻辑进行比较合并。

**核心变化（去重处理）**：
1. **相同元素跳过**：当发现 `a[i] == b[j]` 时，它们是重复的。只需要把其中一个放进结果数组，同时让 $i$ 和 $j$ **同时**向后移动一步即可。
2. **防连坐（自身有重复）**：为了防止原始数组 A 或者 B 自身里面就有重复元素（比如 `[1, 1, 2]`），最稳妥的判定方法是：每次准备把元素扔进结果数组 `C` 之前，先看看它是不是和 `C` 中**最后一个刚放进去的元素**相等。如果不相等才放进去。

你可以尝试在这个思路下，自己写出对应的 `while` 循环双指针逻辑！

# 练习 2：两数之和（有序版）

## 题干

**题目描述**
给定一个已按照**升序排列**的整数数组 `numbers` ，请你从数组中找出两个数满足相加之和等于目标数 `target` 。
假设每个输入只对应唯一的答案，而且你不可以重复使用相同的元素。
请返回这两个数的下标值（下标从 0 开始）。

**输入格式**
第一行输入两个整数 $n$ 和 $target$，分别表示数组长度和目标和。
第二行输入 $n$ 个升序排列的整数。

**输出格式**
输出两个整数，表示这两个数的下标，中间以空格隔开。

**数据范围**
$2 \le n \le 10^5$，$-10^9 \le numbers[i] \le 10^9$，时间限制为 1s。

**输入样例**
```text
4 9
2 7 11 15
```

**输出样例**
```text
0 1
```

---

## 解决思路

因为数组**已经排好序**了，我们可以使用**对撞双指针**的方法，把时间复杂度从暴力的 $O(N^2)$ 降到惊人的 $O(N)$。

**算法步骤**：
1. 将左指针 $L$ 指向数组最左端（下标 0，即最小值），右指针 $R$ 指向数组最右端（下标 $n-1$，即最大值）。
2. 计算两个指针指向的数字之和 $Sum = a[L] + a[R]$。
3. **比较与移动**：
   - 如果 $Sum == target$，说明找到了，直接返回 $L$ 和 $R$。
   - 如果 $Sum < target$，说明当前的和太小了。由于右边已经是最大值了，唯一的办法是**让左边的数字变大**，所以左指针向右移动（$L++$）。
   - 如果 $Sum > target$，说明当前的和太大了。由于左边已经是最小值了，唯一的办法是**让右边的数字变小**，所以右指针向左移动（$R--$）。
4. 循环直到找到答案为止。

# 练习 3：小和问题（逆序对的镜像版）

## 题干

**题目描述**
在一个数组中，每一个数左边比当前数小的数累加起来，叫做这个数组的**小和**。求一个数组的小和。

例如，数组 `[1, 3, 5, 2, 4, 6]` 的小和：
- 1 的左边没有比它小的数，小和为 0；
- 3 的左边比它小的数有：1，小和为 1；
- 5 的左边比它小的数有：1, 3，小和为 1 + 3 = 4；
- 2 的左边比它小的数有：1，小和为 1；
- 4 的左边比它小的数有：1, 3, 2，小和为 1 + 3 + 2 = 6；
- 6 的左边比它小的数有：1, 3, 5, 2, 4，小和为 15。
所以数组的总小和为 `0 + 1 + 4 + 1 + 6 + 15 = 27`。

**输入格式**
第一行为 $n$，表示序列长度；接下来的 $n$ 行，每行表示序列中的一个数。

**输出格式**
输出所有元素的小和的总和。

**数据范围**
$N \le 10^5$。

**输入样例**
```text
6
1 3 5 2 4 6
```

**输出样例**
```text
27
```

---

## 解决思路

这道题是“04_逆序对”作业的**绝对镜像**，不需要像“翻转对”那样把逻辑拆开，它完全可以像逆序对一样在 $O(N \log N)$ 时间内边合并边统计！

**思维反转**：
题目的原意是：对于每一个数，去右边找**左边有哪些数比自己小**。
用分治法把它反过来看：对于左半区的每一个数 $a[i]$，去看看**右半区有多少个数比 $a[i]$ 大**！如果右半区有 $k$ 个数比 $a[i]$ 大，说明 $a[i]$ 会作为“小和”被加 $k$ 次！

**统计逻辑**：
经过代码前半部分的两次递归调用 `mergesort(左半区)` 和 `mergesort(右半区)`，此时交到我们手里的左右两半，**已经被底层的递归强制排成了完美的升序**。

在合并这两个升序数组时：
当 `a[i] < a[j]` 时：
既然右半区此时已经是绝对的升序，那么只要 $a[j]$ 比 $a[i]$ 大，它后面的所有数字肯定也都比 $a[i]$ 大！
也就是说，从当前指针 $j$ 到右边界 $r$ 共有 `r - j + 1` 个数，这 `r - j + 1` 个数在计算小和的时候，都要把 $a[i]$ 加进去。
所以，**总小和直接批量增加 `a[i] * (r - j + 1)`**。然后再把较小的 $a[i]$ 放进临时数组，$i++$。

你会发现，这道题的伪代码，和逆序对的代码可以说是只改了一行！去感受一下这种镜像的对称美吧！

> **灵魂拷问：排序会不会打乱原本的小和结果？**
> 很多初学者会疑惑：既然要求原数组的小和，可 `mergesort` 把数组的相对位置都打乱（排序）了，这难道不会影响最终结果吗？
> 答案是：**绝对不会！** 它的精妙之处在于“过河拆桥”：
> 1. **内部的相对位置：算完之后才改变！** 在对左半区内部排序前，程序已经把左半区内部所有的小和都算完并存进总成绩了。“证据”已经安全入档，这时候再打乱内部顺序完全没关系。
> 2. **跨越边界的相对位置：即使内部排序，也没有人跨界！** 当左半区和右半区准备跨界合并时，**左半区的全体成员依然集体排在右半区的全体成员前面**。不管左半区内部怎么洗牌，它们去和右半区比对时，“左边的人依然在左边，右边的人依然在右边”，跨越鸿沟的宏观相对位置根本没有改变。因此跨界统计出来的小和，绝对是原汁原味的！

# 练习 4：多数元素（强制分治法）

## 题干

**题目描述**
给定一个大小为 $N$ 的数组，找到其中的多数元素。多数元素是指在数组中出现次数**严格大于** $\lfloor N/2 \rfloor$ 的元素。
你可以假设数组是非空的，并且给定的数组总是存在多数元素。
**强制要求：本题必须使用分治算法求解。**

**输入格式**
第一行输入一个整数 $n$，表示数组长度。
第二行输入 $n$ 个整数，元素之间以空格分隔。

**输出格式**
输出该数组的多数元素。

**数据范围**
$1 \le N \le 5 \times 10^4$，$-10^9 \le A_i \le 10^9$。

**输入样例**
```text
7
2 2 1 1 1 2 2
```

**输出样例**
```text
2
```

---

## 解决思路

寻找多数元素有很多种解法（比如哈希表、摩尔投票法），但作为算法课第二章的巩固，我们尝试使用**分治法**来解决它。

**分治法的核心定律**：
如果我们把数组从中间分成左右两半：
如果整个数组有一个“多数元素”（也就是真正的老大），那么它**必定**是左半边的“多数元素”，或者是右半边的“多数元素”！
*(因为如果它连一半的选票都赢不了，合在一起绝不可能赢得全场的选票)*

**算法伪代码框架**：
```text
函数 找多数(左边界, 右边界):
    // 1. 递归终止条件
    如果 左边界 == 右边界:
        只剩一个数了，那它自己就是多数元素，直接返回 这个数

    // 2. 分治拆分
    中点 = (左边界 + 右边界) / 2
    左边老大 = 找多数(左边界, 中点)
    右边老大 = 找多数(中点 + 1, 右边界)

    // 3. 合并与裁决
    如果 左边老大 == 右边老大:
        双方推举了同一个人，那这个人必定是全场的老大，返回 左边老大
    否则:
        双方推举的人不同。
        此时我们需要裁判：在这个具体的 [左边界, 右边界] 区间内，去老老实实地数一数“左边老大”出现了几次，“右边老大”出现了几次。
        谁出现的次数多，谁就是这个区间的最终老大，返回 胜利者
```

这个算法时间复杂度为 $O(N \log N)$。快去试试把它翻译成真正的代码吧！
