**题目描述**
设有 $N$ 堆沙子排成一排，其编号为 $1, 2, 3, \dots, N$ ($N \le 300$)。每堆沙子有一定的数量，可以用一个整数来描述，现在要将这 $N$ 堆沙子合并成为一堆，**每次只能合并相邻的两堆**，合并的代价为这两堆沙子的数量之和，合并后与这两堆沙子相邻的沙子将和新堆相邻，合并时由于选择的顺序不同，合并的总代价也不相同，如有 $4$ 堆沙子分别为 $1\ 3\ 5\ 2$ 我们可以先合并 $1$、$2$ 堆，代价为 $4$，得到 $4\ 5\ 2$ 又合并 $1$、$2$ 堆，代价为 $9$，得到 $9\ 2$，再合并得到 $11$，总代价为 $4+9+11=24$，如果第二步是先合并 $2$、$3$ 堆，则代价为 $7$，得到 $4\ 7$，最后一次合并代价为 $11$，总代价为 $4+7+11=22$；问题是：找出一种合理的方法，使总的代价最小。输出最小代价。

**输入格式**
第一行一个数 $N$ 表示沙子的堆数。第二行 $N$ 个数，表示每堆沙子的质量。 $\le 1000$

**输出格式**
合并的最小代价

**输入样例**
```text
4
1 3 5 2
```

**输出样例**
```text
22
```

# 解决思路

### 1. 核心算法：为什么是区间DP？为什么不能用贪心？
很多初学者看到求“最小代价”，第一反应是贪心算法：每次挑两堆最小的沙子合并就行了。但是本题有一个极其致命的限制条件——**“每次只能合并相邻的两堆”**。
如果一味地寻找全局最小的两堆，它们大概率并不相邻，无法直接合并。因此，这种受限于“空间位置（相邻）”的合并问题，必须利用**区间动态规划（Interval DP）**。它的核心思想是：从小区间开始，逐步把小块拼成大块，最终拼成整个大区间。

### 2. 状态定义：理解为“拼图游戏”
在区间DP中，我们可以把合并过程想象成 **“从小到大拼凑连续拼图”** 的过程：
* **$i$（左端点）和 $j$（右端点）**：锁定了一段连续的沙子区间，即从第 $i$ 堆到第 $j$ 堆。
* **$dp[i][j]$**：**代表“把区间 $[i, j]$ 内的所有沙子合并成唯一一堆，所需要花费的最小总代价”**。
* **初始状态**：当 $i = j$ 时，也就是区间里只有一堆沙子，不需要合并，代价为 $0$。即 $dp[i][i] = 0$。

### 3. 状态转移方程（核心逻辑：寻找最佳分割点）
现在假设我们要计算大区间 $dp[i][j]$ 的最小代价。我们要思考：**这最后合并成一堆的动作，是由哪两小堆合并而来的？**

既然是从中间某处把两堆拼起来的，我们就可以假设在区间 $[i, j]$ 内存在一个分割点 $k$（$i \le k < j$）。
这个分割点把大区间劈成了两个小区间：左半边 $[i, k]$ 和右半边 $[k+1, j]$。
* 左半边早已合并好，花费的最小代价是 $dp[i][k]$。
* 右半边也早已合并好，花费的最小代价是 $dp[k+1][j]$。
* 现在要把左右这两大块进行最终合并。**这一次“大合并”的代价，就是这两块的沙子总质量，即整个区间 $[i, j]$ 的沙子总和**。

所以，对于某个特定的分割点 $k$，其总代价为：
$$代价 = dp[i][k] + dp[k+1][j] + 区间[i, j]的沙子总和$$

因为我们不知道从哪里切一刀才是最优的，所以我们要**遍历所有可能的分割点 $k$**，从中挑一个总代价最小的。
**状态转移方程为：**
$$dp[i][j] = \min_{i \le k < j} \{dp[i][k] + dp[k+1][j]\} + \sum_{x=i}^{j} a[x]$$

### 4. 优化技巧：前缀和
在状态转移方程中，我们需要频繁计算“区间 $[i, j]$ 的沙子总和”。如果每次都用 for 循环去累加，会导致大量的重复计算。
为了加速，我们可以引入 **前缀和** 数组：
令 $prefix[x]$ 表示前 $x$ 堆沙子的质量总和。
那么，区间 $[i, j]$ 的沙子总和可以在 $O(1)$ 的时间内通过公式直接算出：
$$sum(i, j) = prefix[j] - prefix[i-1]$$

### 5. 遍历顺序与边界控制：按“区间长度”从小到大遍历
对于二维数组 $dp$，我们**不能**简单地按 $i$ 和 $j$ 从小到大使用双重 for 循环。因为计算长区间 $dp[i][j]$ 时，必须保证它内部的短区间 $dp[i][k]$ 和 $dp[k+1][j]$ 已经被计算过了。
正确的遍历姿势是**以区间长度 $len$ 为第一层循环**：
1. 先计算所有长度 $len = 2$ 的区间（合并相邻的 2 堆）。
2. 再计算所有长度 $len = 3$ 的区间（依赖于长度 1 和 2 的区间）。
3. 逐步推导，直到 $len = N$，此时算出的 $dp[1][N]$ 就是全局最优解。


* **为什么右端点 $j = i + len - 1$？** 这里是在已知起点 $i$ 和框的长度 $len$ 时，推算终点的位置。因为起点 $i$ 自身已经占据了 $1$ 个单位的长度，所以在加上长度 $len$ 之后，必须减去多算的那个 $1$。例如起点是第 $2$ 堆，框长度是 $3$，框住的是 $2, 3, 4$，右边界就是 $4$。

* **为什么左端点的限制是 $i \le n - len + 1$？**
这里是在限制你的框最多能向右滑动到哪里。沙子总共只有 $n$ 堆，所以右边界绝对不能越界，即 $j \le n$。把前面推导的右端点公式代入这个不等式，得到 $i + len - 1 \le n$。做一个简单的移项，就变成了 $i \le n - len + 1$。这就是一道安全防线，保证在固定的区间长度下，你的起点无论怎么向右走，终点都永远停留在有效范围内。

# 最终代码

```cpp
#include <bits/stdc++.h>

using namespace std;

const int INF = 1e9; // 设定一个极大的值代表初始的无穷大代价

int main() {
    int n;
    

    vector<int> a(n + 1);
    vector<int> prefix(n + 1, 0);

    // 读取数据并计算前缀和
    for (int i = 1; i <= n; i++) {
        cin >> a[i];
        prefix[i] = prefix[i - 1] + a[i];
    }

    // dp[i][j] 表示合并区间 [i, j] 的最小代价
    // 默认初始化为 0，刚好满足了 dp[i][i] = 0 的初始状态
    vector<vector<int>> dp(n + 1, vector<int>(n + 1, 0));

    // 第一层循环：枚举区间长度 len（从 2 开始，因为长度为 1 不需要合并）
    for (int len = 2; len <= n; len++) {
        // 第二层循环：枚举区间的左端点 i
        for (int i = 1; i <= n - len + 1; i++) {
            int j = i + len - 1; // 根据左端点和长度，算出右端点 j
            dp[i][j] = INF;      // 准备求最小值，先初始化为极大值
            
            // 第三层循环：枚举区间 [i, j] 内的分割点 k  不能写在双循环外面
            for (int k = i; k < j; k++) {
                // 状态转移：左部分代价 + 右部分代价 + 最后一次合并的代价(区间沙子总和)
                dp[i][j] = min(dp[i][j], dp[i][k] + dp[k + 1][j] + prefix[j] - prefix[i - 1]);
            }
        }
    }

    // 输出把第 1 堆到第 n 堆全部合并的最小代价
    cout << dp[1][n] << "\n";

    return 0;
}
```
