## 二、 算法的核心概念 (第7-17页)
* **算法的定义 (第7-8页)**：算法是指解决问题时，按照确定的机械步骤，一定可以得到结果的处理过程。课件中举了个很生动的例子：“在森林迷路走一步看一步”只是建议，而“顺着溪流往下走直到城镇”是一个明确的算法。
* **算法的五大特征 (第9-14页)**：
    > **闭卷重点：算法五大特征** 常考选择/填空：有穷性、确定性、能行性、输入、输出；其中“至少有一个输出”“可以有 0 个输入”容易设陷阱。
    * **有穷性**：必须在有限步内结束。比如一个死循环就缺乏有穷性。
    * **确定性**：每一步必须没有歧义。比如要求“输出自然数”，但没指明是哪个自然数，就缺乏确定性。
    * **能行性 (可行性)**：每一步都能通过笔纸算出结果。比如给负数开偶次平方根，在实数范围内算不出，就缺乏能行性。
    * **输入输出**：可以有0个或多个输入（比如固定求半径为2的圆面积，不需要外部输入），但至少有一个输出。
* **流程图与词源 (第15-17页)**：介绍了用标准流程图（如椭圆代表开始/结束，菱形代表判断，矩形代表处理）来描述算法。Algorithm一词来源于9世纪波斯数学家花拉子米的音译。

## 三、 程序与算法的区别 (第18-21页)
* **程序 = 数据结构 + 算法**。
* **核心区别**：程序可以不满足算法的“有穷性”。例如电脑的操作系统也是一个程序，但它会在无限循环中执行以等待指令，所以操作系统本身不是一个算法（但它内部包含很多子算法）。
> **闭卷重点：程序 vs 算法** 判断题常考：程序可以无限执行，算法必须有穷；不要把“程序一定是算法”当真。

## 四、 为什么要设计算法？两个经典案例 (第22-35页)
* **案例1：调度问题 (第23-26页)**。在一台机器上安排多个任务。如果采用“贪心法”（永远让加工时间最短的任务先做），可以严谨地证明这能让所有任务的总完成时间达到最短。这里直觉和算法完美契合。
* **案例2：投资问题 (第27-35页)**。有固定资金和多个投资项目，类似经典的背包问题。如果继续依靠直觉用“贪心法”（比如优先投性价比最高的项目），课件证明了这样找出的可能不是总收益最大的最优解。如果采用把所有分配方案都列举出来的“蛮力法”，方案数量会呈指数级爆炸，计算机根本算不过来。结论：直觉不一定对，蛮力算不过来，所以我们需要系统地学习算法设计。

## 六、 复杂性分析 (第44-51页)
这部分是整个算法复杂性分析的敲门砖。衡量一段程序好坏的标准不能仅仅是“能跑通”，更要看它消耗的资源多寡。

### 1. 复杂性分析的核心概念 (第44-46页)
算法复杂性本质上是在评估算法运行所需的计算机资源量。主要分为两大维度：
> **闭卷重点：复杂性定义** `T(n)` 表示时间复杂性，`S(n)` 表示空间复杂性；规模 `n` 在图问题中可能与边数一起描述，不能机械理解为“数组长度”。
* **时间复杂性 $T(n)$**：算法运行所需要的运算次数。注意，这里不是看绝对的“秒数”，而是看“基本运算”执行了多少次（比如比较了几次、加减乘除了几次等）。
* **空间复杂性 $S(n)$**：算法运行时所占用的额外存储空间大小。

这两个复杂性都是输入规模 $n$ 的函数。不同的问题，$n$ 代表的意义不同：
* 如果是排序或检索，$n$ 就是数组中的元素个数。
* 如果是矩阵相乘，$n$ 可能是矩阵的行列数。
* 如果是图的遍历，规模可以用图的顶点数 $n$ 和边数 $m$ 来共同衡量。

### 2. 衡量时间复杂性的三种情况 (第47页)
即使输入规模 $n$ 完全一样，数据本身排列的不同也会导致算法运行时间大相径庭。因此，分析算法时通常会讨论三种情况：
> **闭卷重点：三种时间情况** 最坏情况给上限、最好情况给下限、平均情况要按输入概率加权；选择题容易把最坏/平均的含义互换。
* **最坏情况 $T_{max}(n)$**：在所有规模为 $n$ 的输入中，让算法执行基本运算次数最多（运气最差）的那种情况。这是我们在工程中最关注的，因为它保证了算法运行时间的上限。
* **最好情况 $T_{min}(n)$**：在所有规模为 $n$ 的输入中，算法执行最快（运气最好）的情况。
* **平均情况 $T_{avg}(n)$**：考虑所有可能出现的输入情况，以及每种情况在实际应用中出现的概率 $P(I)$，计算出的加权平均加总时间 $\sum_{I \in D_n} P(I)T(n,I)$。这是最贴近实际业务表现的指标，但计算起来也最复杂。

### 3. 实例剖析：顺序检索 (第48-50页)
问题场景：在一个非降序（从小到大）排列的数组 $L$ 中，寻找指定的数字 $x$。这里的“基本运算”就是“将 $x$ 与数组中的元素进行比较”。

基础的顺序检索算法流程：
从数组的第一个元素 ($j=1$) 开始，挨个向后比较。如果当前元素等于 $x$，停机并输出位置；如果不等，接着往后看；如果找完了整个数组 ($j>n$) 还没找到，就输出0表示不存在。

针对这个基础算法进行复杂性分析：
* **最好情况**：要找的 $x$ 刚好在数组第一个位置，只比较 1 次就找到了，$T_{min}(n) = 1$。
* **最坏情况**：要找的 $x$ 在数组最后，或者压根不在数组里，必须把整个数组遍历完，比较 $n$ 次，$T_{max}(n) = n$。
* **平均情况**：假设 $x$ 在数组中的概率是 $p$，且在每个位置的概率相等。如果 $x$ 存在，平均比较次数是 $\frac{p(n+1)}{2}$；如果不存在，遍历全表比较了 $(1-p)n$ 次。当 $p = 1/2$ 时，代入公式可得平均比较次数约为 $\frac{3n}{4}$。

### 4. 算法优化的威力：改进的顺序检索 (第51页)
改进思路：在挨个查找时，如果发现 $x < L[j]$，说明我们要找的 $x$ 比当前元素还小。既然数组是从小到大排的，那说明当前元素后面的所有数字都会比 $x$ 大，$x$ 绝对不可能出现在后面了。此时可以直接提前停机并输出0。

优化的实际效果：假设有一个数组包含 5 个元素，我们要找 $x = 2.5$。
* 使用基础算法：程序傻乎乎地比完整个数组，发现没有，总共比较 5 次。
* 使用改进算法：当程序对比到数字 3 时，发现 $2.5 < 3$，触发了提前停机机制，此时只比较了 3 次。
这就证明了，充分挖掘问题本身的数据特征，可以显著降低算法在实际运行时的常数级时间消耗。

## 七、 算法的渐近复杂性符号 (第52-65页)
这里引入了五个关键的数学符号，用来描述当输入规模 $n$ 趋向于无穷大时，算法运行时间的增长趋势。

### 1. 五大核心渐近符号详解
为了方便理解，我们可以把 $f(n)$ 当作你要评估的算法的实际运行时间，$g(n)$ 当作一个用来作为参照的标准函数（比如 $n$、$n^2$）。

* **$O$：渐近上界（最坏情况）**
    > **闭卷重点：渐近符号含义** `O` 是上界，`\Omega` 是下界，`\Theta` 是紧确界；小 `o`/`\omega` 是严格上/下界。
    * **数学定义**：如果存在正数 $c$ 和 $n_0$，使得只要 $n \ge n_0$，就一定有 $0 \le f(n) \le c g(n)$，那么记作 $f(n) = O(g(n))$。
    * **通俗解释**：表示 $f(n)$ 的增长率小于等于 $g(n)$ 的增长率。它给出了算法运行时间的上限。例子：对于 $f(n) = n^2 + n$，因为当 $n$ 足够大时，它的增长速度不会超过 $n^2$ 乘以某个常数，所以 $f(n) = O(n^2)$。
  
  ![1](https://bsyimg.luoca.net/imgtc/20260608/ed59712e852a534898ed08ca45e479e4.webp)
* **$\Omega$：渐近下界（最好情况）**
    * **数学定义**：存在正数 $c$ 和 $n_0$，当 $n \ge n_0$ 时，有 $0 \le c g(n) \le f(n)$。
    * **通俗解释**：表示 $f(n)$ 的增长率大于等于 $g(n)$ 的增长率。它给出了下限。例子：同样是 $f(n) = n^2 + n$，它的耗时下限至少是 $n^2$ 级别，所以 $f(n) = \Omega(n^2)$。

![2](https://bsyimg.luoca.net/imgtc/20260608/95dbed595f6045e195407bde8da255bb.webp)
* **$\Theta$：紧确界（准确量级）**
    * **数学定义**：当 $f(n)$ 既满足 $O(g(n))$，又满足 $\Omega(g(n))$ 时，就记作 $f(n) = \Theta(g(n))$。
    * **通俗解释**：表示 $f(n)$ 和 $g(n)$ 的增长率完全相等（同阶）。这是对算法复杂度最精确的评估。

![3](https://bsyimg.luoca.net/imgtc/20260608/79a123892a24771c1833ed512e944b22.webp)
* **$o$ 严格上界与 $\omega$严格下界：严格的界限**
    * **通俗解释**：大 $O$ 和大 $\Omega$ 包含“等于”的情况，而小写的 $o$ 和 $\omega$ 则是严格的不等号。
        * **$o$**：表示 $f(n)$ 的阶严格低于 $g(n)$。例如 $n^2 + n$ 严格低于 $n^3$，即 $f(n) = o(n^3)$。
        * **$\omega$**：表示 $f(n)$ 的阶严格高于 $g(n)$。例如 $n^2 + n$ 严格高于 $n$，即 $f(n) = \omega(n)$。

### 2. 图像直观理解
结合课件第62页的图，我们可以更直观地看到这三者的关系：
* 图(a)是 $\Theta$ 紧确界：在某个临界点 $n_0$ 之后，$f(n)$ 的曲线被紧紧夹在 $c_1 g(n)$ 和 $c_2 g(n)$ 两条曲线之间。
* 图(b)是 $O$ 上界：在 $n_0$ 之后，$c g(n)$ 的曲线像天花板一样，永远压在 $f(n)$ 的上方。
* 图(c)是 $\Omega$ 下界：在 $n_0$ 之后，$c g(n)$ 的曲线像地板一样，永远垫在 $f(n)$ 的下方。

### 3. 实战解题技巧：求极限法 (定理1.1)
在考试或做题时，用定义去找那个常数 $c$ 和 $n_0$ 是极其繁琐的。课件第63-65页给出了一个极其好用的方法：通过求极限来直接判断复杂度的阶。

**关键技巧（如何选取 $g(n)$）：** 要找已有公式中，在“常见复杂度全景图”（见下文）里**复杂度最高的一项**来作为 $g(n)$。

只需要计算极限：$L = \lim_{n \to \infty} \frac{f(n)}{g(n)}$。在复杂度分析中，一般默认 $f(n)$、$g(n)$ 最终都为正。

* **若 $L = 0$**：说明 $f(n)$ 的增长阶严格低于 $g(n)$。
    > **闭卷重点：极限判阶法** `0 -> o/O`，正常数 `-> Θ`，`+∞ -> ω/Ω`；填空题可能直接给极限让判断符号。
    * 直接得出 $f(n) = o(g(n))$。**（严格上界）**
    * 因此也有 $f(n) = O(g(n))$。（渐近上界）
* **若 $L = c$，其中 $0 < c < +\infty$**：说明 $f(n)$ 和 $g(n)$ 同阶，只差一个常数倍。
    * 直接得出 $f(n) = \Theta(g(n))$。**（紧确界）**
    * 因此同时有 $f(n) = O(g(n))$ 和 $f(n) = \Omega(g(n))$。
* **若 $L = +\infty$**：说明 $f(n)$ 的增长阶严格高于 $g(n)$。
    * 直接得出 $f(n) = \omega(g(n))$。**（严格下界）**
    * 因此也有 $f(n) = \Omega(g(n))$。（渐近下界）

实战运用 (第65页 例4)：假设要评估算法时间函数 $f(n) = 0.5n^2 - 3n$ 的复杂度。根据上述技巧，公式中复杂度最高的一项是 $n^2$，因此选取 $g(n) = n^2$。我们把它除以 $n^2$ 求极限：$\lim_{n \to \infty} \frac{0.5n^2 - 3n}{n^2} = \frac{1}{2}$。因为 $\frac{1}{2}$ 是一个大于0的常数，根据定理立刻就能得出结论：$f(n) = \Theta(n^2)$。

## 八、 常见函数的阶与实战演练 (第66-82页)
这部分的主要目的是让你建立起对不同函数增长速度的直觉，掌握算法复杂度的排位规律。

### 1. 复杂度的排位与基本运算法则 (第66-68页)
> **闭卷重点：复杂度排序与运算法则** 常见阶从低到高：`1 < log n < n < n log n < n^2 < n^3 < 2^n < n!`；串行取最大，嵌套/乘法相乘，常数忽略。
* **阶的高低规律**：对数函数的阶低于幂函数（即多项式），多项式函数的阶又远远低于指数函数。
* **传递性法则**：如果 $f$ 的耗时比 $g$ 长，$g$ 的耗时比 $h$ 长，那么 $f$ 的耗时一定比 $h$ 长。这个规律同样适用于 $O$、$\Omega$ 和 $\Theta$。
* **抓大放小法则（加法与乘法规则）**：当两部分代码串行执行时，总复杂度由最慢的那部分决定，即 $O(f) + O(g) = O(\max(f,g))$。如果代码内部嵌套了其他逻辑，复杂度相乘，即 $O(f)O(g) = O(fg)$。常数系数在渐近分析中可以直接忽略。

### 2. 核心数学工具：对数与阶乘 (第71-75页)
* **对数函数 (第72页)**：在算法分析中，我们通常不关心对数的底数是多少。因为根据换底公式，不同底数的对数之间只相差一个常数倍数，而在大 $O$ 符号下常数是被忽略的。所以写 $\log n$ 即可，它代表一种极其高效的算法量级。
* **阶乘函数 (第73页)**：当遇到需要穷举所有排列组合的算法时，复杂度往往是 $n!$。课件引入了斯特灵公式 (Stirling's approximation) 来估算阶乘的大小。最重要的一个转化结论是：$\log(n!) = \Theta(n \log n)$。
    > **闭卷重点：对数与阶乘** 对数底数可忽略；`\log(n!) = Θ(n log n)` 是常见填空/判断点。
* **取整函数 (第75页)**：向下取整和向上取整在二分查找或构建树结构划分数据时经常用到，课件列举了它们放缩时的基本数学性质。

### 3. 常见复杂度全景图 (第69, 70, 74, 76-79页)
按照运行时间从快到慢（即渐近阶由低到高），标准排位如下：
1. **$O(1)$** - 常数阶（最理想状态，比如直接通过索引访问数组）
2. **$O(\log n)$** - 对数阶（非常高效，比如二分查找）
3. **$O(n)$** - 线性阶（比如遍历一遍数组）
4. **$O(n \log n)$** - 线性对数阶（比如主流的高级排序算法：归并排序、快速排序）
5. **$O(n^2)$** - 平方阶（比如两层嵌套 for 循环的冒泡排序）
6. **$O(n^3)$** - 立方阶
7. **$O(2^n)$** - 指数阶（开始变得不可接受，算力黑洞）

### 4. 经典灵魂拷问：硬件升级能拯救烂算法吗？ (第80-81页)
这是这门课极其经典的一道思考题，将算法理论与底层的微处理器算力结合在了一起。

假设目前用 ABC 公司的处理器，1 小时能处理规模为 $n$ 的数据。现在 XYZ 公司推出了运算速度暴增 100倍 的新处理器，在同样的 1 小时内，新处理器能处理多大规模的数据？
* 如果你的算法是 **$O(n)$**，数据处理规模可以直接提升 100 倍，达到 $100n$。
* 如果是 **$O(n^2)$**，算力提升 100 倍，因为要开平方，处理规模只能提升 10 倍，变为 $10n$。
* 如果是糟糕的 **$O(2^n)$** 甚至 **$O(n!)$** 算法，算力提升 100 倍，处理规模仅仅只是在原来的基础上增加了寥寥几个单位（例如增加 6.64）。

核心结论：单纯依靠堆砌 CPU 主频和算力，在指数级复杂度的算法面前是杯水车薪的。这也是为什么我们在工程开发中，必须死磕数据结构与算法优化的原因。

## 九、 拓展阅读与作业 (第83-87页)
* **P与NP问题 (第83-85页)**：
    * **P类**：计算机能在多项式时间内解决的问题。
    * **NP类**：多项式时间内不一定能解开，但只要别人给出一个答案，计算机能在多项式时间内验证得出正确解的问题。
    * **NPC / NP-Hard**：最难的NP问题，如果NPC问题被证明能在多项式时间内解开，那所有的NP问题就都能解开了。
    > **闭卷重点：P/NP/NPC/NP-Hard** `P` 强调多项式时间求解，`NP` 强调多项式时间验证；`NP` 不是“非多项式”的缩写。
* **作业 (第87页)**：要求不使用STL库，自己手写归并排序(Mergesort)的程序，并分析它的复杂性。
