## 一、 贪心算法的思想与基本要素
* **核心思想**：贪心算法总是作出在当前看来最好的选择。它并不从整体最优考虑，所作出的选择只是在某种意义上的局部最优选择。对于单源最短路径、最小生成树等问题，它能产生整体最优解；即使在不能得到最优解的情况下，也往往能获得最优解的很好近似。
* **与动态规划算法的差异**：
    > **闭卷重点：贪心与动态规划差异** 二者都需要最优子结构；贪心还要求贪心选择性质，通常自顶向下逐步选择；动态规划通常自底向上填表。
    * 贪心算法和动态规划算法都要求问题具有最优子结构性质。
    * 动态规划通常以自底向上的方式解各子问题，而贪心算法通常以自顶向下的方式进行，通过迭代作出相继的贪心选择，不断将问题规模缩小。
    * **背包问题对比**：部分背包问题可用贪心算法求解（每次装入单位重量价值最高的物品），而 0-1 背包问题不能用贪心算法求解（部分闲置的背包空间会使整体空间价值降低），需要用动态规划解决。
* **两大基本要素**：
    > **闭卷重点：贪心两大基本要素** 贪心选择性质 + 最优子结构性质；不要选“重叠子问题”或“子问题相互独立”。模拟卷已考。
    1. **贪心选择性质**：所求问题的整体最优解可以通过一系列局部最优的选择（贪心选择）来达到。
    2. **最优子结构性质**：问题的最优解包含其子问题的最优解。

## 二、 贪心算法的理论基础：拟阵 (Matroid)
* **拟阵的定义**：拟阵 $M$ 定义为一个序对 $(S, I)$，满足：
    > **闭卷重点：拟阵三条件** 非空有限集、遗传性质、交换性质；偏概念，适合选择/判断。
    1. $S$ 是非空有限集。
    2. $I$ 是 $S$ 的一类具有遗传性质的独立子集族。
    3. 交换性：若 $A \in I, B \in I$ 且 $|A| < |B|$，则 $\exists x \in B-A$，使得 $A \cup \{x\} \in I$。
* **带权拟阵最优子集**：许多贪心算法求解的问题都可归结为求带权拟阵的最优子集问题。带权拟阵的最优子集也一定是极大独立子集。贪心算法求解带权拟阵最优子集的时间复杂度通常为 $O(n \log n + n f(n))$。

## 三、 经典应用：活动安排问题
* **问题描述**：在所给的活动集合中选出最大的相容活动子集合，要求同一时间内只有一个活动能使用某公共资源。
* **贪心策略**：将输入活动按结束时间 $f[i]$ 的非减序排列。每次总是选择具有最早完成时间的相容活动，从而为未安排活动留下尽可能多的时间。
> **闭卷重点：活动安排贪心策略** 按结束时间非减序排序，每次选最早结束且相容的活动；不是按开始时间早或持续时间短。
```cpp
template<class Type>
void GreedySelector(int n, Type s[], Type f[], bool A[]) {
    // 各活动的起始时间和结束时间存储于数组s和f中，且按结束时间的非减序排列
    A[1] = true;
    int j = 1;
    for (int i = 2; i <= n; i++) {
        if (s[i] >= f[j]) { 
            A[i] = true; 
            j = i; 
        }
        else {
            A[i] = false;
        }
    }
}
```
* **复杂度**：若活动已排序，算法仅需 $O(n)$ 的时间；若未排序则需要 $O(n \log n)$ 进行重排。

## 四、 经典应用：最优装载问题
* **问题描述**：将尽可能多的集装箱装上载重量为 $c$ 的轮船，装载体积不受限制。
* **贪心策略**：采用重量最轻者先装的策略，可以保证最终产生装载问题的最优解。
> **闭卷重点：最优装载贪心** 为装最多个集装箱，应按重量从小到大装；排序代价 `O(n log n)`。
* **复杂度**：主要计算量在于对集装箱按重量进行排序，需要 $O(n \log n)$ 的计算时间。

## 五、 经典应用：哈夫曼编码 (Huffman Coding)
* **前缀码**：对每一个字符规定一个 $0$ 或 $1$ 的代码串，并要求任一字符的代码都不是其它字符代码的前缀，以保证译码时不混淆。
* **贪心策略**：以自底向上的方式构造表示最优前缀码的完全二叉树。使用优先队列（最小堆），每次挑出频率最小的两棵树进行合并，新树的频率为两树频率之和。该策略使得频率越高的字符离根节点越近，从而编码越短。
> **闭卷重点：哈夫曼编码** 前缀码定义、每次合并频率最小的两棵树、总复杂度 `O(n log n)` 都是闭卷概念题高频点。
* **复杂度**：优先队列的初始化和 $n-1$ 次合并操作，总共需要 $O(n \log n)$ 的计算时间。

## 六、 经典应用：单源最短路径 (Dijkstra 算法)
* **基本思想**：设置顶点集合 $S$，并不断作贪心选择来扩充这个集合。初始时 $S$ 中仅含有源顶点。每次从 $V-S$ 中取出具有最短特殊路长度的顶点 $u$，将其添加到 $S$ 中，并利用新加入的顶点 $u$ 对剩余顶点的最短距离作必要修改。
* **复杂度**：对于含有 $n$ 个顶点的图，算法主循环需要执行 $n-1$ 次，每次在数组中寻找最小值，时间复杂度为 $O(n^2)$。
> **闭卷重点：Dijkstra** 每次选当前最短特殊路径顶点扩充集合；数组实现时间复杂度 `O(n^2)`；通常要求边权非负。

## 七、 经典应用：最小生成树 (Prim 与 Kruskal 算法)
* **最小生成树性质 (MST性质)**：设连通带权图的顶点被分割为 $U$ 和 $V-U$ 两部分，如果边 $(u,v)$ 是横跨两集合且权值最小的边，那么一定存在一棵包含边 $(u,v)$ 的最小生成树。
* **Prim 算法**：从孤立的根节点开始，利用 `closest` 和 `lowcost` 数组，每次贪心选择横跨已选集合与未选集合之间权值最小的边，不断扩展树。时间复杂度为 $O(n^2)$。
* **Kruskal 算法**：将所有边按权值从小到大排序。依序考察每条边，若该边连接的两个端点属于不同的连通分支（利用并查集判断），则用该边合并它们。时间复杂度为 $O(e \log e)$，在稀疏图下表现优于 Prim 算法。
> **闭卷重点：最小生成树** MST 性质、Prim `O(n^2)`、Kruskal `O(e log e)` 很适合选择题；模拟卷已考 Prim 复杂度。

## 八、 多机调度问题
* **问题描述**：使 $n$ 个作业在 $m$ 台机器上尽可能短地完成处理（不能拆分，不可中断）。这是一个 NP 完全问题。
* **贪心近似算法**：采用**最长处理时间作业优先**的调度策略。将作业按处理时间从大到小排序，依次将其分配给当前最早空闲的处理机。时间复杂度主要受排序影响，为 $O(n \log n)$。
> **闭卷重点：多机调度** 多机调度是 NP 完全问题，但具有最优子结构；常用近似贪心是最长处理时间优先。模拟卷已考“是否具有最优子结构”。
