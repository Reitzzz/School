## 一、 贪心算法的思想与基本要素
* **核心思想**：贪心算法总是作出在当前看来最好的选择。<u>它并不从整体最优考虑</u>，所作出的选择只是在某种意义上的局部最优选择。<br>
  **对于部分问题，它能产生整体最优解；即使在不能得到最优解的情况下，也往往能获得最优解的很好近似。**
* **与动态规划算法的差异**：
    > **闭卷重点：贪心与动态规划差异** 二者都需要最优子结构；**贪心还要求贪心选择性质，通常自顶向下逐步选择；动态规划通常自底向上填表**。
    * 贪心算法和动态规划算法都要求问题具有最优子结构性质。
    * 动态规划通常以自底向上的方式解各子问题，而贪心算法通常以自顶向下的方式进行，通过迭代作出相继的贪心选择，不断将问题规模缩小。
    * **背包问题对比**：0-1 背包问题不能用贪心算法求解（因为无法保证最终能将背包填满，部分闲置的背包空间会使每公斤整体空间的价值降低），需要用动态规划解决；而部分背包问题可用贪心算法求解（每次装入单位重量价值最高的物品）。
* **两大基本要素**：
    > **闭卷重点：贪心两大基本要素** 贪心选择性质 + 最优子结构性质
    1. **贪心选择性质**：所求问题的整体最优解可以通过**一系列局部最优的选择（贪心选择）来达到**。这是贪心算法可行的第一个基本要素，也是与动态规划的主要区别。
    2. **最优子结构性质**：问题的**最优解包含其子问题的最优解**。

## 二、 经典应用：活动安排问题
* **问题描述**：设有 $n$ 个活动的集合 $E=\{1,2,...,n\}$，每个活动都要求使用同一公共资源。每个活动 $i$ 都有一个要求使用该资源的起始时间 $s_i$ 和结束时间 $f_i$。若区间 $[s_i, f_i)$ 与 $[s_j, f_j)$ 不相交，则称活动 $i$ 与活动 $j$ 是相容的。目标是在所给的活动集合中选出最大的相容活动子集合。
* **贪心策略**：将输入活动按**结束时间 $f_i$ 的非减序（从小到大）排列**。每次总是选择具有最早完成时间且与已选活动相容的活动。
* **策略意义**：直观上，按这种方法选择相容活动，能**为未安排的活动留下尽可能多的时间**。也就是说，该算法贪心选择的意义是使剩余的可安排时间段极大化。
> **闭卷重点：活动安排贪心策略** 按结束时间非减序排序，每次选最早结束且相容的活动；不是按开始时间早或持续时间短。
```cpp
template<class Type>
void GreedySelector(int n, Type s[], Type f[], bool A[]) {
    // 各活动的起始时间和结束时间存储于数组s和f中，且按结束时间的非减序排列
    A[1] = true;
    int j = 1;
    for (int i = 2; i <= n; i++) {
        if (s[i] >= f[j]) { // 若活动 i 的开始时间晚于等于最近选择的活动的结束时间
            A[i] = true; 
            j = i; 
        }
        else {
            A[i] = false;
        }
    }
}
```
* **复杂度**：若活动已按结束时间排序，算法仅需 $O(n)$ 的时间；若未排序则需要 $O(n \log n)$ 进行重排。

## 三、 经典应用：最优装载问题
* **问题描述**：有一批集装箱要装上一艘载重量为 $c$ 的轮船，其中集装箱 $i$ 的重量为 $W_i$。最优装载问题要求确定在装载体积不受限制的情况下，将尽可能多的集装箱装上轮船。
* **贪心策略**：采用**重量最轻者先装**的策略，可产生最优装载问题的最优解。
> **闭卷重点：最优装载贪心** 为装最多个集装箱，应按重量从小到大装；算法的核心计算量在于排序，代价为 `O(n log n)`。
* **算法步骤**：首先将所有集装箱依其重量从小到大排序，然后依次尝试装入。若当前集装箱的重量加上已装入的总重量不超过 $c$，则将其装入；否则跳过或结束。
* **复杂度**：主要计算量在于对集装箱按重量进行排序，需要 $O(n \log n)$ 的计算时间。算法其余部分仅需 $O(n)$。

## 四、 经典应用：哈夫曼编码 (Huffman Coding)
* **前缀码**：对每一个字符规定一个 $0$ 或 $1$ 的代码串，并要求任一字符的代码都不是其它字符代码的前缀，以保证译码时不混淆。
* **变长编码**：对频率高的字符赋以短编码，对频率低的字符赋以长编码，可以大大缩短总码长，实现有效的数据压缩。
* **贪心策略**：以**自底向上**的方式构造表示最优前缀码的完全二叉树。每次从当前森林中挑选出**频率最小的两棵树（或节点）进行合并**，新树的频率为两树频率之和，并作为它们的新父节点。重复此过程 $n-1$ 次，直到只剩下一棵树（即哈夫曼树）。
> **闭卷重点：哈夫曼编码** 前缀码定义、每次合并频率最小的两棵树、总复杂度 `O(n log n)` 都是闭卷概念题高频点。哈夫曼算法具有贪心选择性质和最优子结构性质。
* **实现与复杂度**：算法通常使用 **最小堆（优先队列）** 来实现。初始化最小堆需要 $O(n)$ 时间；接下来进行 $n-1$ 次合并，每次合并需要两次 `Extract-Min` 和一次 `Insert` 操作，单次合并耗时 $O(\log n)$。因此，总共需要 $O(n \log n)$ 的计算时间。

## 五、 经典应用：单源最短路径 (Dijkstra 算法)
* **问题描述**：给定带权有向图 $G=(V,E)$，其中每条边的权是**非负实数**。给定一个源点，计算从源点到所有其它各顶点的最短路径长度。
* **贪心策略**：设置顶点集合 $S$（用于保存已找到最短路径的顶点），并不断作贪心选择来扩充这个集合。初始时 $S$ 中仅含有源顶点。声明一个数组 `dist` 来记录源点到每个顶点的最短特殊路径长度。每次从 $V-S$ 中取出具有**最短特殊路长度的顶点 $u$**，将其添加到 $S$ 中，并利用新加入的顶点 $u$ 对剩余顶点在 `dist` 中的距离作必要修改（松弛操作）。
> **闭卷重点：Dijkstra** 每次选当前最短特殊路径顶点扩充集合；数组实现时间复杂度 `O(n^2)`；**要求边权必须非负**，否则贪心策略失效。
* **常见特殊图情况**：
    1. **是否存在负数边**：**绝对不行**。如果存在负权边，Dijkstra 的贪心选择（即一旦加入集合S，其最短路径就已确定的假设）将被打破，可能导致算法得出错误结果。含负权边的图应使用 Bellman-Ford 等其他算法。
    2. **是否存在环**：**可以存在**。只要不是“负权环”，普通的正权环不会影响 Dijkstra 的正确执行（因为正权环只会增加路径总长，寻找最短路的贪心策略会自然避开它）。
    3. **是否可以为非连通图**：**可以**。对于无法从源点到达的孤立顶点，其最终最短路径长度将保持为初始化的无穷大 ($\infty$)。
* **复杂度**：对于含有 $n$ 个顶点的图，算法主循环需要执行 $n-1$ 次，每次在数组中寻找最小值需要 $O(n)$，因此时间复杂度为 $O(n^2)$。

## 六、 经典应用：最小生成树 (Prim 与 Kruskal 算法)
* **问题描述**：设 $G=(V,E)$ 是无向连通带权图，寻找一棵包含 $G$ 的所有顶点且代价（所有边权之和）最小的生成树。
* **最小生成树性质 (MST性质)**：设图的顶点被分割为 $U$ 和 $V-U$ 两部分，如果边 $(u,v)$ 是横跨两集合且权值最小的边，那么一定存在一棵包含边 $(u,v)$ 的最小生成树。
> **闭卷重点：最小生成树** MST 性质是 Prim 和 Kruskal 算法正确性的共同理论基础；Prim 复杂度为 `O(n^2)`，Kruskal 复杂度为 `O(e log e)` 很适合选择题。
* **常见特殊图情况**：
    1. **是否存在负数边**：**完全可以**。Prim 和 Kruskal 都是基于边权的相对大小进行贪心选择（每次挑最小的边），哪怕边权是负数，只要它是当前所有可选边中最小的，策略就成立。因此**即便图中有负权边，这两种算法依然完全有效**。
    2. **是否存在环**：**原始图必定包含环**（否则图本身就是一棵树了），但这两个算法的本质就是**“破环成树”**。Kruskal 利用并查集主动剔除任何会使当前森林构成环的边；Prim 则是通过不断寻找“横跨集合内外”的边来扩展，天然避免了在同一集合内成环。最终生成的 MST 中绝对没有环。
* **Prim 算法**：
    * **策略**：从孤立的单个节点开始，不断向外扩展。每次贪心选择**横跨已选集合 $S$ 与未选集合 $V-S$ 之间权值最小的边**，将其对应顶点加入树中。
    * **实现**：利用 `closest` 数组（记录 $V-S$ 中顶点到 $S$ 中顶点的最近顶点）和 `lowcost` 数组（记录对应的最小边权）。时间复杂度为 $O(n^2)$。
* **Kruskal 算法**：
    * **策略**：将所有边按**权值从小到大排序**。依序考察每条边，若该边连接的两个端点属于不同的连通分支（即不会构成环），则用该边合并这两个连通分支，将边加入树中。
    * **实现**：使用**并查集 (Union-Find)** 抽象数据类型来判断两个端点是否在同一连通分支中。时间复杂度主要取决于边排序，为 $O(e \log e)$，在稀疏图下表现优于 Prim 算法。

## 七、 多机调度问题
* **问题描述**：要求给出一种作业调度方案，使所给的 $n$ 个独立作业在 $m$ 台相同的机器上尽可能短地完成处理（作业不能拆分，且不可中断）。这是一个 **NP 完全问题**，目前还没有有效的多项式时间精确解法。
* **贪心近似算法**：采用**最长处理时间作业优先 (LPT)** 的调度策略，以求得一个较好的近似算法。
> **闭卷重点：多机调度** 多机调度是 NP 完全问题，但具有最优子结构；常用近似贪心策略是**最长处理时间优先**。
* **算法步骤**：
    1. 当 $n \le m$ 时，只要将作业分别分配给每台机器即可，耗时 $O(1)$。
    2. 当 $n > m$ 时，首先将 $n$ 个作业依其处理时间**从大到小排序**。然后依次顺序将作业分配给**当前最早空闲的处理机**。
* **复杂度**：算法的主要计算时间在于对作业的处理时间进行排序，因此时间复杂度为 $O(n \log n)$。
