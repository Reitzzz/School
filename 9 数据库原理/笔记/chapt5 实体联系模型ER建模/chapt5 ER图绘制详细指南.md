## <a id="ch0"></a>0. 认识基本构件

画ER图之前，必须先认识三种基本构件：**实体（矩形）**、**属性（椭圆）**、**联系（菱形）**。

### <a id="ch0-1"></a>0.1 实体

#### <a id="ch0-1-1"></a>0.1.1 强实体类型

![实体](https://bsyimg.luoca.net/imgtc/20260523/13e2c5f574105a252a6621c3edb40e44.webp)

- **含义**：现实世界中可独立存在、可相互区分的对象（如一个学生、一门课程）
- **数据库对应**：表

#### <a id="ch0-1-2"></a>0.1.2 弱实体类型

![弱实体](https://bsyimg.luoca.net/imgtc/20260523/b61313b2b8c075e8e1bcb2058b0f660d.webp)

- **含义**：没有自身主码，**必须依赖父实体存在的实体**（如家属依赖于员工）
- **数据库对应**：依赖父表的子表
- **关键特征**：用**虚下划线**表示部分键

---

### <a id="ch0-2"></a>0.2 属性

#### <a id="ch0-2-1"></a>0.2.1 普通属性

![属性](https://bsyimg.luoca.net/imgtc/20260523/a8fb32720e3e8b7ce06ba17a82ce127e.webp)

- **含义**：实体或联系所具有的某种特性
- **数据库对应**：列

#### <a id="ch0-2-2"></a>0.2.2 主属性 / 主码

![主属性](https://bsyimg.luoca.net/imgtc/20260523/9a63fead74cdef166acf53f18953733a.webp)

- **含义**：唯一标识一个实体的属性（如学号、课程号）
- **数据库对应**：主键
- **画法**：椭圆内的文字加**实线下划线**

#### <a id="ch0-2-3"></a>0.2.3 部分键 (弱实体)

![部分键](https://bsyimg.luoca.net/imgtc/20260523/7a07cac78e513eb7e8ee188c29b7bdbf.webp)

- **含义**：部分键是弱实体用于在同一父实体下区分不同弱实体的属性
- **举例**：公司里可能有不少员工的**孩子小名都叫“大宝”，但根据员工的主键即可确定是谁**
- **数据库对应**：部分键（弱实体专用）
- **画法**：椭圆内的文字加**虚线下划线**

#### <a id="ch0-2-4"></a>0.2.4 多值属性

![多值属性](https://bsyimg.luoca.net/imgtc/20260523/f620aedccd63249501289ef611c60e43.webp)

- **含义**：一个实体在该属性上可以同时拥有多个值（如一个人有多个电话号码）
- **数据库对应**：需要拆成独立表
- **画法**：用**双层椭圆**表示

#### <a id="ch0-2-5"></a>0.2.5 派生属性

![派生属性](https://bsyimg.luoca.net/imgtc/20260523/d14ee5d9af77fcbcc91befa62b818c47.webp)

- **含义**：无需直接存储，可通过其他属性计算得出（如通过出生日期算出年龄）
- **数据库对应**：可计算得出，不存储
- **画法**：用**虚线椭圆**表示

---

### <a id="ch0-3"></a>0.3 联系

#### <a id="ch0-3-1"></a>0.3.1 联系类型

![联系](https://bsyimg.luoca.net/imgtc/20260523/b96c7ec5ca3949ff17a8e3b804da246e.webp)

- **含义**：多个实体集之间的相互关联关系（如学生"选修"课程）
- **数据库对应**：外键关联 / 中间桥梁表

#### <a id="ch0-3-2"></a>0.3.2 弱实体的识别联系

![弱联系](https://bsyimg.luoca.net/imgtc/20260523/24faa0b7471665f97b9460ef70e649a8.webp)

- **含义**：弱实体与父实体之间的依赖联系
- **数据库对应**：弱实体与父表的依赖关系
- **画法**：弱实体必须通过双层菱形连接到它的父实体

---

## <a id="ch1"></a>1. 第一步：识别实体

拿到题目后，第一件事是找出所有**实体**。

### 方法

1. 读题时用**下划线**标出所有名词
2. 排除明显是属性的名词（如"姓名"、"年龄"、"学分"）
3. 剩下的就是实体候选

### 判断标准

- **能独立存在**、**有唯一标识** → 实体（画矩形）
- **依附于其他东西**才能存在 → 属性（画椭圆）
- **描述两个实体之间的关系** → 联系（画菱形）

### 举例

> "每个学生可以选多门课，每门课程有多个学生选修"

- "学生" → 实体（能独立存在，有学号标识）
- "课程" → 实体（能独立存在，有课程号标识）
- "选修" → 联系（描述学生和课程的关系）

---

## <a id="ch2"></a>2. 第二步：判断属性类型

找到实体后，为每个实体列出属性，并判断每个属性的类型。

### <a id="ch2-1"></a>2.1 简单属性 vs 复合属性（原子性）

| 类型 | 特征 | 举例 | 画法 |
|------|------|------|------|
| **简单属性** | 绝对不可分割 | 身高、年龄 | 单个椭圆 |
| **复合属性** | 可以套娃拆分 | 出生日期 → 年/月/日 | 主椭圆延伸子椭圆 |

**考场速判**：看到"可分"或"有组成部分" → 立即锁定复合属性

### <a id="ch2-2"></a>2.2 存储属性 vs 派生属性（存储性）

| 类型 | 特征 | 举例 | 画法 |
|------|------|------|------|
| **存储属性** | 需要直接存储 | 出生日期 | 实线椭圆 |
| **派生属性** | 可通过计算得出 | 年龄 = 当前日期 - 出生日期 | **虚线椭圆** |

**考试陷阱**：派生属性必须用**虚线椭圆**，漏掉虚线直接扣分！

### <a id="ch2-3"></a>2.3 单值属性 vs 多值属性（值的个数）

| 类型 | 特征 | 举例 | 画法 |
|------|------|------|------|
| **单值属性** | 一个实体只有一个值 | 姓名、年龄 | 单层椭圆 |
| **多值属性** | 一个实体可以有多个值 | 电话号码、学历 | **双层椭圆** |

---

## <a id="ch3"></a>3. 第三步：识别联系与基数

### <a id="ch3-1"></a>3.1 联系的基数类型

| 基数 | 含义 | 举例 |
|------|------|------|
| **1:1（一对一）** | A的一个实例对应B的一个实例 | 一个人对应一个身份证号 |
| **1:N（一对多）** | A的一个实例对应B的多个实例 | 一个班级有多个学生 |
| **M:N（多对多）** | A的多个实例对应B的多个实例 | 一个学生选多门课，一门课被多个学生选 |

### <a id="ch3-2"></a>3.2 三元联系怎么画

三元联系不是画成三个菱形，也不是画成三条二元关系，而是：

> **一个菱形，同时连接三个实体。**

**基本画法**：

![三元联系](https://bsyimg.luoca.net/imgtc/20260621/d3a79c2ce3763836d2f42f1aa603b074.webp)

**读图方法**：
- 中间的"销售"是一个**三元联系菱形**
- "供应商、商品、购买者"三个实体都直接连到这个菱形
- 如果有"销售日期、数量、价格"这类属性，挂在"销售"菱形上
- `M`、`N`、`P` 都表示"多"，只是用不同字母区分三条边上的多重性

**什么时候必须画三元联系**：
- **题目表达的是"三方共同决定一件事"**
- 去掉任何一方，语义都会不完整
- 例如："某购买者从某供应商购买某商品"，必须同时知道购买者、供应商、商品

**考试防错**：
- 不能为了图简单，把三元联系拆成三个二元联系
- **拆开后只能知道两两之间有关，无法知道三方是不是发生在同一次业务事件里**
- 具体为什么不能拆，见 4.2 的理论辨析

### <a id="ch3-3"></a>3.3 联系的属性挂在哪儿

这是考试的高频陷阱：

![M:N](https://bsyimg.luoca.net/imgtc/20260620/a63850b6bd134c97849fb16d7570898e.webp)

![1:N](https://bsyimg.luoca.net/imgtc/20260620/d5e7d32f166fb1a09bfe644fc2c3083a.webp)

**经典案例**：学生选课的"成绩"
- 学生和课程是 M:N 联系
- "成绩"既不属于学生，也不属于课程，而是选课时产生的
- 所以"成绩"必须挂在"选课"菱形上

## <a id="ch4"></a>4. 第四步：特殊结构处理

### <a id="ch4-1"></a>4.1 弱实体

弱实体是考试大型高频考点。

#### 弱实体的"三位一体"判定

1. **身份判定**：没有自己的主键，必须依附于父实体
2. **图形死律**：
   - 弱实体本身 → **双层矩形**
   - 与父实体之间的联系 → **双层菱形**
   - 部分键 → **虚下划线**
3. **连线误区**：弱实体**只能**连父实体？**错！**
   - 弱实体不仅可以与父实体建立标识联系
   - 还可以根据业务需求与其他普通实体连线

#### 举例

> "一个员工有多个家属，家属依赖员工存在"

- 家属没有独立主键 → 弱实体（双层矩形）
- 家属与员工之间是识别联系（双层菱形）
- 家属的"姓名"是部分键（虚下划线）

---

### <a id="ch4-2"></a>4.2 三元联系 vs 三个二元联系

这是期末/考研最爱考的理论辨析大题。

#### 核心定理

> **在一般情况下，一个三元联系绝对不等价于三个二元联系。**

#### 案例解剖：销售关系

**三元联系**：供应商 + 商品 + 购买者 通过一个菱形连接
- 含义：某个购买者从某个供应商买了某个商品
- 这是三方同时在场的"一次性闭环事件"

**拆成三个二元联系的灾难**：
1. 供应商 - 商品（供应商能提供哪些商品）
2. 购买者 - 商品（购买者买过哪些商品）
3. 供应商 - 购买者（购买者去过哪些供应商）

**信息丢失**：查询"张三从李四那里买了什么"时，做连接会产生**伪露**
- 二元表只能告诉你：张三买过电脑，李四卖过电脑，张三去过李四的店
- 但你无法推断"张三的电脑**是不是**在李四店里买的"

#### 得分金句

> 拆解会丢失"多方实体间强绑定的特异性关联信息"，导致数据语义降维，连接时产生错误组合。因此，多方同时决定一个业务动作时，必须使用三元联系！

---

### <a id="ch4-3"></a>4.3 继承（超类/子类）

当一个实体可以分为几种子类型，并且子类型会继承父类型的共同属性时，使用继承。

#### 超类和子类分别是什么

- **超类**：更一般的实体类型，保存所有子类共有的属性
- **子类**：更具体的实体类型，继承超类属性，并且可以有自己的特殊属性

**例子**：
- "艺术品"是超类：编号、标题、创作年份、价格是共同属性
- "绘画"是子类：除了继承艺术品属性，还有"绘画技法"
- "雕塑"是子类：除了继承艺术品属性，还有"材料"

一句话记忆：

> 子类是超类的一种，子类自动拥有超类的属性。

#### 判断方法

- 题目说"只收藏绘画或雕塑" → 绘画和雕塑是艺术品的子类
- 子类有**特殊属性**（绘画有"绘画技法"，雕塑有"材料"）
- 子类继承父类的所有属性

#### 画法

![超类和子类继承示意图](./超类子类-继承示意图.svg)

**画图步骤**：
1. 超类画在上方，仍然用矩形
2. 子类画在下方，也用矩形
3. 超类和子类之间用一个小三角形连接，三角形里常写 **ISA**
4. 共同属性挂在超类上，特殊属性挂在对应子类上

**不要这样画**：
- 不要把"绘画"和"雕塑"画成"艺术品"的普通属性
- 不要把继承画成普通菱形联系
- 不要在每个子类里重复写超类已经有的共同属性

#### 继承约束

继承题里常见两组约束：

| 约束 | 含义 | 画图提示 |
|------|------|------|
| **互斥继承** | 一个超类实例最多属于一个子类 | 艺术品要么是绘画，要么是雕塑 |
| **重叠继承** | 一个超类实例可以同时属于多个子类 | 一个员工既是教师，也是管理员 |
| **完全继承** | 每个超类实例都必须属于某个子类 | 艺术品必须是绘画或雕塑 |
| **部分继承** | 超类实例可以不属于任何子类 | 员工不一定都是教师或管理员 |

考试里如果题目没有明确要求，可以先画基本 ISA 结构，再用文字标注"互斥/重叠、完全/部分"。

---

### <a id="ch4-4"></a>4.4 参与约束怎么画

参与约束描述的是：某个实体实例是否**必须参加**某个联系。

| 约束 | 含义 | 画法 |
|------|------|------|
| **全部参与** | 每个实体实例都必须参加该联系 | 实体到联系之间画**双线** |
| **部分参与** | 有些实体实例可以不参加该联系 | 实体到联系之间画**单线** |
 
**例子**：

> "顾客必须至少购买过一件艺术品"

这是顾客对"购买"联系的**全部参与**，画图时用**双线连接**顾客和购买联系。

**注意**：
- 基数约束回答"最多/通常对应几个"
- 参与约束回答"是否必须参加"
- `1:N`、`M:N` 不等于参与约束，二者要分开判断

---

### <a id="ch4-5"></a>4.5 联系实体 / 关联实体

当一个 M:N 联系本身有很多属性，或者后续还要和别的实体发生联系时，可以把联系提升为一个**联系实体**。

**典型例子**：学生选课
- 原本是：学生 M:N 课程，中间联系叫"选课"
- 如果"选课"有成绩、选课时间、重修标记等属性，就可以把"选课"画成联系实体
- 转换后变成：学生 1:N 选课，课程 1:N 选课

**考场判断**：
- 只是简单描述两个实体有关 → 画普通菱形联系
- 联系有自己的属性 → 属性挂在菱形上
- 联系属性很多，或需要单独编号、再连接其他实体 → 考虑画成联系实体

## <a id="ch5"></a>5. 实战演练：三道作业题详解

> 学完第0-6节的理论后，用以下三道题检验掌握程度。每道题逐步演示完整的画图流程。

### <a id="ch7-1"></a>5.1 题目1：学校管理系统（基础）

**考查范围**：实体识别、属性判断、1:N和M:N联系、联系属性归属
**不涉及**：弱实体、三元联系、继承

**题目原文**：
> 一个学校有若干个系，每个系有若干个教研室和若干个班级，每个班级有若干个学生，每个教研室有若干个教师，其中有的教授和副教授，指导若干个研究生。每个学生可以选多门课，每门课程有多个学生选修，每个学生选修了一门课，经过考试，就有一个成绩。请画出该学校管理系统的E-R图。

**Step 1：识别实体**

| 实体 | 说明 |
|------|------|
| 系 | 学校的行政单位 |
| 教研室 | 教师的工作单位 |
| 班级 | 学生的班级 |
| 学生 | 在校学生 |
| 教师 | 教职员工 |
| 课程 | 开设的课程 |

**Step 2：识别联系及基数**

```
系 1 ──── 1:N ──── 教研室
系 1 ──── 1:N ──── 班级
教研室 1 ── 1:N ── 教师
班级 1 ──── 1:N ──── 学生
教师 1 ──── 1:N ──── 研究生（特殊身份）
学生 M ──── N:M ──── 课程  ← 注意：这是多对多联系！
```

**Step 3：识别属性**

- **系**：系名(主键)、系主任
- **教研室**：教研室名(主键)、地点
- **班级**：班级号(主键)、人数
- **学生**：学号(主键)、姓名、性别、年龄
- **教师**：教师号(主键)、姓名、职称(教授/副教授)
- **课程**：课程号(主键)、课程名、学分
- **选课联系**：成绩 ← **必须挂在菱形上**（M:N联系）

**Step 4：画图要点**

```
        ┌──────┐
        │  系  │
        └──┬───┘
           │ 1:N
     ┌─────┴─────┐
     │           │
┌────┴────┐  ┌───┴─────┐
│ 教研室  │  │  班级   │
└────┬────┘  └───┬─────┘
     │ 1:N       │ 1:N
┌────┴────┐  ┌───┴─────┐
│  教师   │  │  学生   │
└─────────┘  └───┬─────┘
                 │ M:N
            ┌────┴────┐
            │选课(成绩)│  ← 成绩挂在菱形上
            └────┬────┘
                 │
            ┌────┴────┐
            │  课程   │
            └─────────┘
```

### <a id="ch5-2"></a>5.2 题目2：艺术画廊（继承）

**考查范围**：实体识别、继承（超类/子类）、M:N联系、参与约束
**涉及第4节内容**：4.3 继承

**题目翻译**：
> 用一个或多个关系来表示艺术画廊的信息，包括艺术家、他们的作品和顾客。艺术家用姓名、出生地、年龄和艺术风格来描述。画廊保存艺术家的信息，无论该博物馆是否展出或曾经出售过该艺术家的作品。
>
> 对于画廊展出或曾经出售的每件艺术品，必须存储艺术家、创作年份、标题和价格。
>
> 博物馆只收藏绘画或雕塑两种艺术品。对于绘画，必须记录绘画技法；对于雕塑，必须存储使用的材料。
>
> 画廊还跟踪顾客购买艺术品的情况，以及顾客对特定艺术家的兴趣。记录的顾客可能没有表明对特定艺术家的兴趣，但必须至少购买过一件艺术品。
>
> 请画出该博物馆的概念数据模型E-R图。

**Step 1：识别实体**

| 实体 | 说明 |
|------|------|
| 艺术家 | 创作者 |
| 艺术品 | 画廊收藏的作品 |
| 绘画 | 艺术品的子类（继承） |
| 雕塑 | 艺术品的子类（继承） |
| 顾客 | 购买者 |

**Step 2：识别联系及基数**

```
艺术家 1 ──── 1:N ──── 艺术品（一个艺术家创作多件作品）
艺术品 1 ──── N:1 ──── 顾客（一件作品被一个顾客购买）
顾客 M ──── N:M ──── 艺术家（顾客对艺术家的兴趣）
```

**Step 3：识别属性**

- **艺术家**：姓名(主键)、出生地、年龄、艺术风格
- **艺术品**：标题(主键)、创作年份、价格
- **绘画**：绘画技法（特殊属性）
- **雕塑**：材料（特殊属性）
- **顾客**：姓名(主键)、地址、电话

**Step 4：画图要点**

```
            ┌──────────┐
            │  艺术家  │
            └────┬─────┘
                 │ 1:N
            ┌────┴─────┐
            │  艺术品  │
            └────┬─────┘
                 │ 继承（超类→子类）
           ┌─────┴──────┐
           │            │
      ┌────┴─────┐ ┌───┴──────┐
      │   绘画   │ │   雕塑   │
      └──────────┘ └──────────┘
        (绘画技法)    (材料)

            ┌──────────┐
            │   顾客   │
            └────┬─────┘
                 │ N:M（兴趣联系）
                 │
            ┌────┴────┐
            │  艺术家 │
            └─────────┘
```

**关键考点**：
- 艺术品是一个**超类**，绘画和雕塑是**子类**
- 这体现了**继承**关系
- 绘画有特殊属性"绘画技法"，雕塑有特殊属性"材料"
- 顾客对艺术家的兴趣是 M:N 联系
- "顾客必须至少购买过一件艺术品" → 参与约束，画图时用双线连接

### <a id="ch5-3"></a>5.3 题目3：铁路时刻表（弱实体）

**考查范围**：实体识别、M:N联系分解、弱实体/联系实体
**涉及第4节内容**：4.1 弱实体

**题目翻译**：
> 用E-R图表示火车站出发时刻表中包含的信息。显示每趟出发列车的车次、时间、终点站、类别和停靠站。

**Step 1：识别实体**

| 实体 | 说明 |
|------|------|
| 列车 | 每趟列车 |
| 车站 | 铁路上的站点 |
| 停靠站 | 列车在某站的停靠信息 |

**Step 2：识别联系及基数**

```
列车 1 ──── 1:N ──── 停靠站（一趟列车有多个停靠站）
车站 1 ──── 1:N ──── 停靠站（一个车站被多趟列车停靠）
```

**Step 3：识别属性**

- **列车**：车次(主键)、发车时间、终点站、类别
- **车站**：站名(主键)、所在城市
- **停靠站**：停靠顺序号、到达时间、出发时间

**Step 4：画图要点**

```
        ┌────────┐
        │  列车  │
        └───┬────┘
            │ 1:N
       ┌────┴─────┐
       │  停靠站  │  ← 停靠站是联系实体（或弱实体）
       └────┬─────┘
            │ N:1
       ┌────┴─────┐
       │   车站   │
       └──────────┘
```

**关键考点**：
- 停靠站是一个**联系实体**，它连接列车和车站
- 每个停靠站记录了列车在某个站的到达时间、出发时间、停靠顺序号
- 这是一个典型的 **M:N 联系的分解**：列车和车站之间是 M:N 关系
- 停靠站也可以视为**弱实体**，因为它没有独立的主键，需要依赖"列车+车站"的组合来唯一标识
