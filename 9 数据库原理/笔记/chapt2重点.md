# 核心知识点极简提炼 (你的前置笔记)

要看懂这章，你只需要建立三个维度的概念映射：

**1. 术语的“黑话”翻译**
学术教材喜欢用严谨的数学词汇，但在实际数据库中它们都有非常接地气的对应概念：
* Relation (关系) = Table (表)
* Tuple (元组) = Row / Record (行/记录)
* Attribute (属性) = Column / Field (列/字段)
* Domain (域) = 一列数据允许的取值范围（比如：必须是整数、必须是“男/女”）
* Degree (度) = 列数；Cardinality (基数) = 行数

**2. 键与完整性 (Keys & Integrity)**
这是数据库设计的核心，用于保证数据不乱套。
* **Primary Key (主码)**：唯一标识一行数据的列（比如学号）。规定主码不能有空值，这叫**实体完整性 (Entity Integrity)**。
* **Foreign Key (外码)**：一张表里包含了另一张表的主码，用来把两张表“连”起来。外码要么为空，要么必须能在对应的表里找到，这叫**参照完整性 (Referential Integrity)**。

**3. 关系代数 (Relational Algebra)**
这是作业的绝对重头戏。它其实就是**纯数学符号版的 SQL 语句**。你只需要记住以下五个核心符号：
* **$\sigma$ (选择 Select)**：按**行**过滤，相当于 SQL 里的 `WHERE`。公式：$\sigma_{\text{条件}}(\text{表})$。
* **$\Pi$ (投影 Project)**：按**列**筛选，相当于 SQL 里的 `SELECT 列名`。公式：$\Pi_{\text{列名}}(\text{表})$。
* **$\bowtie$ (自然连接 Natural Join)**：把两张有关联的表拼在一起，自动根据同名列进行匹配。
* **$-$ (差集 Difference)**：在集合 A 里但不在集合 B 里，通常用来解决包含“没有”、“不”字眼的查询。
* **$\div$ (除法 Division)**：用来解决包含“全部”、“所有”字眼的查询。

## 作业解题套路与思路拆解

根据你提供的三份作业，难度是递进的。在做关系代数题目时，保持一个核心思维：**由内向外剥洋葱**。先找到需要的表，再做联合或过滤，最后提取需要的列。

### 模块 2-1：概念强化与简单翻译
这份作业主要考察你对概念的死记硬背和简单的公式翻译。

* **概念题 (3.1 - 3.7)**：答案已经非常标准。你可以直接将这些总结提炼到你的私人笔记中。理解视图 (View) 是一张不存数据的“虚拟表”，而基本表 (Base relation) 是物理存在的。
* **公式翻译题 (3.9)**：解题思路是从括号最里面往外读。
    * 例如 3.9(c)：先看最里面 $\sigma_{price>50}(Room)$，意思是找到价格大于50的房间；然后 $\bowtie$ 连接了 Hotel 表，意味着把这些房间的信息和它们所属的酒店信息拼起来；最外层是 $\Pi_{hotelName, City}$，意思是最后只抽取酒店名和城市这两列。
* **需求转公式题 (3.10)**：先明确需要哪几张表，通过外码将它们 $\bowtie$ 起来，然后用 $\sigma$ 加上条件，最后外层套上 $\Pi$。

### 模块 2-2：基础组合查询
这份作业开始要求你自己写公式，重点是**多表连接**。

* **思路示例 (题5)**：要求列出所有由教授 (professors) 教授的课程的编号和名称。
    1.  找线索：“教授”在 lecturer 表的 Title 字段；“教授的课”通过 contact 表关联；“课程编号和名称”在 course 表。
    2.  连接表：需要 `lecturer` $\bowtie$ `contact` $\bowtie$ `course`。
    3.  加过滤：只要教授，所以是 $\sigma_{Title='professor'}$。
    4.  提取列：最外层加 $\Pi_{Cno, Cname}$。
    5.  最终组合：$$\Pi_{Cno, Cname}(\sigma_{Title='professor'}(lecturer) \bowtie contact \bowtie course)$$

### 模块 2-3：高阶查询（除法与差集）
这份作业是考试的重灾区，里面包含了三个必须掌握的“大招套路”：

* **大招 1：“全部/所有”问题用除法 $\div$**
    * **特征**：题目出现 "acted all the films" (参演了所有电影)。
    * **套路**：$$(\text{关系表}) \div (\text{全集表})$$。
    * **实战 (1.e)**：演员与电影的关系在 `Roles` 表，2021年的所有电影是条件全集。先求全集：$\Pi_{FilmID}(\sigma_{Year=2021}(Films))$；再用关系表去除以它：$\Pi_{ActorID, FilmID}(Roles) \div \text{刚才的全集}$；最后把得出的 ActorID 去 Artists 表里查出名字。
* **大招 2：“没有/不包含”问题用差集 $-$**
    * **特征**：题目出现 "do not have any" 或 "no actors"。
    * **套路**：$$(\text{所有人}) - (\text{有记录的人})$$。
    * **实战 (2.b)**：找没有借书的人。先列出所有人 $\Pi_{Name}(Borrower)$，再减去借了书的人 $\Pi_{Name}(Borrower \bowtie BookLoans)$。
* **大招 3：“自身属性比较”用自连接与更名 $\rho$**
    * **特征**：比如找出“同性别的所有演员参演的电影”。这种题目不仅逻辑绕，而且需要把同一张表当作两张表来对比。由于作业 1.c 的答案中出现了一些小瑕疵和复杂化，这里建议你理清思路：把 Roles 和 Artists 连起来，然后自己跟自己比较，排除掉性别不同的，剩下的就是全是同性的。

### 技术栈视角：为什么这章很重要？

在扎实 SQL 语法和 JDBC 底层机制的过程中，你会发现，关系代数就是数据库查询优化器的核心原理。

当你在后端手写了一条包含多个 `JOIN` 和 `WHERE` 的复杂 SQL 语句，发送给数据库引擎后，引擎做的第一件事，就是把你的 SQL 转换成一棵**关系代数语法树**。理解了先做 $\sigma$（在底层这叫谓词下推，提前缩小数据量）再做 $\bowtie$（减少笛卡尔积带来的内存消耗），你以后在排查慢查询或者设计表结构时，就能直接透过代码看到本质的执行开销。

建议你准备一张 A4 纸，把五个基本代数符号（$\sigma, \Pi, \times, -, \cup$）以及它们组合出来的衍生符号（$\bowtie, \div$）列出来，写上它们对应的 SQL 关键字。先尝试自己推导作业 2-2 和 2-3 的公式，遇到卡壳的步骤，再去对照我上面拆解的洋葱模型，这样吸收效率最高。
