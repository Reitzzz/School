# ER图绘制完全指南：从作业到考场

> 本文档结合 `chapt5.md` 和 `chapt5重点.md` 两份笔记，配合三道作业题，详细讲解ER图的绘制方法。

---

## 一、ER图的核心构件：先认识"零件"

在画ER图之前，你必须先认识这些标准图形符号（来自 `chapt5.md:82-93`）：

### 1.1 强实体类型 (Entity Type)

```
┌───────────┐
│           │
│  实体名称  │
│           │
└───────────┘
    矩形
```

**含义**：现实世界中可独立存在、可相互区分的对象（如一个学生、一门课程）
**数据库对应**：表 (Table)

---

### 1.2 弱实体类型 (Weak Entity Type)

```
┌───────────┐
│ ┌───────┐ │
│ │ 弱实体 │ │
│ │  名称  │ │
│ └───────┘ │
└───────────┘
   双层矩形
```

**含义**：没有自身主码，必须依赖父实体存在的实体（如家属依赖于员工）
**数据库对应**：依赖父表的子表
**关键特征**：用**虚下划线**表示部分键(Partial Key)

---

### 1.3 联系类型 (Relationship Type)

```
      ┌───┐
     ╱     ╲
    ╱ 联系  ╲
    ╲  名称 ╱
     ╲     ╱
      └───┘
      菱形
```

**含义**：多个实体集之间的相互关联关系（如学生"选修"课程）
**数据库对应**：外键关联 / 中间桥梁表

---

### 1.4 弱实体的识别联系 (Identifying Relationship)

```
      ┌───┐
     ╱ ┌─┐ ╲
    ╱  │联│  ╲
    ╲  │系│  ╱
     ╲ └─┘ ╱
      └───┘
    双层菱形
```

**含义**：弱实体与父实体之间的依赖联系
**数据库对应**：弱实体与父表的依赖关系
**画法**：弱实体必须通过双层菱形连接到它的父实体

---

### 1.5 属性 (Attribute)

```
      ╭───────╮
      │ 属性名 │
      ╰───────╯
       椭圆
```

**含义**：实体或联系所具有的某种特性
**数据库对应**：列 (Column / Field)

---

### 1.6 主属性 / 主码 (Key Attribute)

```
      ╭───────╮
      │ 属性名 │
      ╰───┬───╯
          ▔▔▔
      下划线椭圆
```

**含义**：唯一标识一个实体的属性（如学号、课程号）
**数据库对应**：主键 (Primary Key)
**画法**：椭圆内的文字加**实线下划线**

---

### 1.7 弱实体的部分键 (Partial Key / Discriminator)

```
      ╭───────╮
      │ 属性名 │
      ╰───┄───╯
          ┊┊┊
      虚下划线椭圆
```

**含义**：弱实体用于在同一父实体下区分不同弱实体的属性
**数据库对应**：部分键（弱实体专用）
**画法**：椭圆内的文字加**虚线下划线**

---

### 1.8 多值属性 (Multi-valued Attribute)

```
      ╭───────╮
      │ ╭───╮ │
      │ │属性│ │
      │ ╰───╯ │
      ╰───────╯
      双线椭圆
```

**含义**：一个实体在该属性上可以同时拥有多个值（如一个人有多个电话号码）
**数据库对应**：需要拆成独立表
**画法**：用**双层椭圆**表示

---

### 1.9 派生属性 (Derived Attribute)

```
      ╭┄┄┄┄┄┄┄╮
      ┊ 属性名 ┊
      ╰┄┄┄┄┄┄┄╯
      虚线椭圆
```

**含义**：无需直接存储，可通过其他属性计算得出（如通过出生日期算出年龄）
**数据库对应**：可计算得出，不存储
**画法**：用**虚线椭圆**表示

---

### 符号速查总表

| # | 符号 | 英文名称 | 中文名称 | 对应数据库概念 |
|---|------|----------|----------|----------------|
| 1 | 矩形 | Entity Type | 强实体类型 | 表 (Table) |
| 2 | 双层矩形 | Weak Entity Type | 弱实体类型 | 依赖父表的子表 |
| 3 | 菱形 | Relationship Type | 联系类型 | 外键关联/中间表 |
| 4 | 双层菱形 | Identifying Relationship | 识别联系 | 弱实体与父表的依赖 |
| 5 | 椭圆 | Attribute | 属性 | 列 (Column) |
| 6 | 下划线椭圆 | Key Attribute | 主属性/主码 | 主键 (Primary Key) |
| 7 | 虚下划线椭圆 | Partial Key | 部分键 | 弱实体的区分标志 |
| 8 | 双线椭圆 | Multi-valued Attribute | 多值属性 | 需要拆成独立表 |
| 9 | 虚线椭圆 | Derived Attribute | 派生属性 | 可计算得出，不存储 |

### 记忆口诀（来自 `chapt5重点.md`）：
- **矩形 = 表，菱形 = 连线枢纽，椭圆 = 字段**
- 实体类型 = 表，实体实例 = 行，属性 = 列
- **看到虚线 → 派生（不存）；看到双线 → 多值（拆表）**

## 二、属性的"扣字眼"判断法

画ER图前，必须先判断每个属性的类型。核心对比（来自 `chapt5重点.md:15-22`）：

### 1. 原子性对比：Simple vs Composite

| 类型 | 特征 | 举例 | 画法 |
|------|------|------|------|
| **Simple（简单属性）** | 绝对不可分割 | 身高(Height)、年龄(Age) | 单个椭圆 |
| **Composite（复合属性）** | 可以套娃拆分 | 出生日期(DOB) → 年/月/日 | 主椭圆延伸子椭圆 |

**考场速判**：看到"可分"或"有组成部分" → 立即锁定 Composite

### 2. 存储性对比：Stored vs Derived

| 类型 | 特征 | 举例 | 画法 |
|------|------|------|------|
| **Stored（存储属性）** | 需要直接存储 | 出生日期(DOB) | 实线椭圆 |
| **Derived（派生属性）** | 可通过计算得出 | 年龄(Age) = 当前日期 - DOB | **虚线椭圆** |

**考试陷阱**：派生属性必须用**虚线椭圆**，漏掉虚线直接扣分！

## 三、联系的属性：挂在菱形还是矩形上？

这是考试的高频陷阱（来自 `chapt5重点.md:26-30`）：

### 黄金法则

```
┌─────────────────────────────────────────────────────┐
│  联系类型    │  属性挂在哪儿？          │  原因      │
├─────────────────────────────────────────────────────┤
│  1:N（一对多）│  移到 N 端实体上        │  N端独占    │
│  M:N（多对多）│  必须挂在菱形上         │  双方共有    │
└─────────────────────────────────────────────────────┘
```

**经典案例**：学生选课的"成绩"
- 学生和课程是 M:N 联系
- "成绩"既不属于学生，也不属于课程，而是选课时产生的
- 所以"成绩"必须挂在"选课"菱形上

## 四、弱实体的"无房户之痛"

弱实体是考试大型高频考点（来自 `chapt5重点.md:33-40`）：

### 弱实体的"三位一体"判定

1. **身份判定**：没有自己的主键，必须依附于父实体(Owner)
2. **图形死律**：
   - 弱实体本身 → **双层矩形**
   - 与父实体之间的联系 → **双层菱形**
   - 部分键(Partial Key) → **虚下划线**
3. **连线误区**：弱实体**只能**连父实体？**错！**
   - 弱实体不仅可以与父实体建立标识联系
   - 还可以根据业务需求与其他普通实体连线

---

## 五、三元联系 vs 三个二元联系

这是期末/考研最爱考的理论辨析大题（来自 `chapt5重点.md:43-54`）：

### 核心定理

> **在一般情况下，一个三元联系（Ternary Relationship）绝对不等价于三个二元联系（Binary Relationships）。**

### 案例解剖：销售关系(Sale)

**三元联系**：Vendor + Item + Purchaser 通过一个菱形连接
- 含义：某个 Purchaser 从某个 Vendor 买了某个 Item
- 这是三方同时在场的"一次性闭环事件"

**拆成三个二元联系的灾难**：
1. Vendor - Item（供应商能提供哪些商品）
2. Purchaser - Item（购买者买过哪些商品）
3. Vendor - Purchaser（购买者去过哪些供应商）

**信息丢失**：查询"张三从李四那里买了什么"时，做 Join 会产生**伪露(Spurious Tuples)**
- 二元表只能告诉你：张三买过电脑，李四卖过电脑，张三去过李四的店
- 但你无法推断"张三的电脑**是不是**在李四店里买的"

### 得分金句

> 拆解会丢失"多方实体间强绑定的特异性关联信息"，导致数据语义降维，连接时产生错误组合。因此，多方同时决定一个业务动作时，必须使用三元联系！

## 六、实战演练：三道作业题详解

### 题目1：学校管理系统

**题目原文**：
> 一个学校有若干个系，每个系有若干个教研室和若干个班级，每个班级有若干个学生，每个教研室有若干个教师，其中有的教授和副教授，指导若干个研究生。每个学生可以选多门课，每门课程有多个学生选修，每个学生选修了一门课，经过考试，就有一个成绩。请画出该学校管理系统的E-R图。

**Step 1：识别实体**

| 实体 | 说明 |
|------|------|
| 系(Department) | 学校的行政单位 |
| 教研室(Office) | 教师的工作单位 |
| 班级(Class) | 学生的班级 |
| 学生(Student) | 在校学生 |
| 教师(Teacher) | 教职员工 |
| 课程(Course) | 开设的课程 |

**Step 2：识别联系及基数**

```
系 1 ──── 1:N ──── 教研室
系 1 ──── 1:N ──── 班级
教研室 1 ── 1:N ── 教师
班级 1 ──── 1:N ──── 学生
教师 1 ──── 1:N ──── 研究生（特殊身份）
学生 M ──── N:M ──── 课程  ← 注意：这是多对多联系！
```

**Step 3：识别属性**

- **系**：系名(主键)、系主任
- **教研室**：教研室名(主键)、地点
- **班级**：班级号(主键)、人数
- **学生**：学号(主键)、姓名、性别、年龄
- **教师**：教师号(主键)、姓名、职称(教授/副教授)
- **课程**：课程号(主键)、课程名、学分
- **选课联系**：成绩 ← **必须挂在菱形上**（M:N联系）

**Step 4：画图要点**

```
        ┌──────┐
        │  系  │
        └──┬───┘
           │ 1:N
     ┌─────┴─────┐
     │           │
┌────┴────┐  ┌───┴─────┐
│ 教研室  │  │  班级   │
└────┬────┘  └───┬─────┘
     │ 1:N       │ 1:N
┌────┴────┐  ┌───┴─────┐
│  教师   │  │  学生   │
└─────────┘  └───┬─────┘
                 │ M:N
            ┌────┴────┐
            │选课(成绩)│  ← 成绩挂在菱形上
            └────┬────┘
                 │
            ┌────┴────┐
            │  课程   │
            └─────────┘
```

### 题目2：艺术画廊

**题目翻译**：
> 用一个或多个关系来表示艺术画廊的信息，包括艺术家、他们的作品和顾客。艺术家用姓名、出生地、年龄和艺术风格来描述。画廊保存艺术家的信息，无论该博物馆是否展出或曾经出售过该艺术家的作品。
>
> 对于画廊展出或曾经出售的每件艺术品，必须存储艺术家、创作年份、标题和价格。
>
> 博物馆只收藏绘画或雕塑两种艺术品。对于绘画，必须记录绘画技法；对于雕塑，必须存储使用的材料。
>
> 画廊还跟踪顾客购买艺术品的情况，以及顾客对特定艺术家的兴趣。记录的顾客可能没有表明对特定艺术家的兴趣，但必须至少购买过一件艺术品。
>
> 请画出该博物馆的概念数据模型E-R图。

**Step 1：识别实体**

| 实体 | 说明 |
|------|------|
| 艺术家(Artist) | 创作者 |
| 艺术品(Artwork) | 画廊收藏的作品 |
| 绘画(Painting) | 艺术品的子类（继承） |
| 雕塑(Sculpture) | 艺术品的子类（继承） |
| 顾客(Customer) | 购买者 |

**Step 2：识别联系及基数**

```
艺术家 1 ──── 1:N ──── 艺术品（一个艺术家创作多件作品）
艺术品 1 ──── N:1 ──── 顾客（一件作品被一个顾客购买）
顾客 M ──── N:M ──── 艺术家（顾客对艺术家的兴趣）
```

**Step 3：识别属性**

- **艺术家**：姓名(主键)、出生地、年龄、艺术风格
- **艺术品**：标题(主键)、创作年份、价格
- **绘画**：绘画技法（特殊属性）
- **雕塑**：材料（特殊属性）
- **顾客**：姓名(主键)、地址、电话

**Step 4：画图要点**

```
            ┌──────────┐
            │  艺术家  │
            └────┬─────┘
                 │ 1:N
            ┌────┴─────┐
            │  艺术品  │
            └────┬─────┘
                 │ 继承（超类→子类）
           ┌─────┴──────┐
           │            │
      ┌────┴─────┐ ┌───┴──────┐
      │   绘画   │ │   雕塑   │
      └──────────┘ └──────────┘
        (绘画技法)    (材料)

            ┌──────────┐
            │   顾客   │
            └────┬─────┘
                 │ N:M（兴趣联系）
                 │
            ┌────┴────┐
            │  艺术家 │
            └─────────┘
```

**关键考点**：
- 艺术品是一个**超类(Superclass)**，绘画和雕塑是**子类(Subclass)**
- 这体现了**继承(Inheritance)**关系
- 绘画有特殊属性"绘画技法"，雕塑有特殊属性"材料"
- 顾客对艺术家的兴趣是 M:N 联系（一个顾客可以对多个艺术家感兴趣，一个艺术家可以被多个顾客关注）
- 注意："顾客必须至少购买过一件艺术品" → 这是参与约束(Participation Constraint)，画图时用双线连接顾客和购买联系

### 题目3：铁路时刻表

**题目翻译**：
> 用E-R图表示火车站出发时刻表中包含的信息。显示每趟出发列车的车次、时间、终点站、类别和停靠站。

**Step 1：识别实体**

| 实体 | 说明 |
|------|------|
| 列车(Train) | 每趟列车 |
| 车站(Station) | 铁路上的站点 |
| 停靠站(Stop) | 列车在某站的停靠信息 |

**Step 2：识别联系及基数**

```
列车 1 ──── 1:N ──── 停靠站（一趟列车有多个停靠站）
车站 1 ──── 1:N ──── 停靠站（一个车站被多趟列车停靠）
```

**Step 3：识别属性**

- **列车**：车次(主键)、发车时间、终点站、类别
- **车站**：站名(主键)、所在城市
- **停靠站**：停靠顺序号、到达时间、出发时间

**Step 4：画图要点**

```
        ┌────────┐
        │  列车  │
        └───┬────┘
            │ 1:N
       ┌────┴─────┐
       │  停靠站  │  ← 停靠站是联系实体（或弱实体）
       └────┬─────┘
            │ N:1
       ┌────┴─────┐
       │   车站   │
       └──────────┘
```

**关键考点**：
- 停靠站是一个**联系实体(Relationship Entity)**，它连接列车和车站
- 每个停靠站记录了列车在某个站的到达时间、出发时间、停靠顺序号
- 这是一个典型的 **M:N 联系的分解**：列车和车站之间是 M:N 关系（一趟列车停靠多个站，一个车站被多趟列车停靠）
- 停靠站也可以视为**弱实体**，因为它没有独立的主键，需要依赖"列车+车站"的组合来唯一标识

## 七、画ER图的完整流程（考场SOP）

按照以下步骤，保证不遗漏任何要素：

### Step 1：识别实体（找矩形）
- 读题时用**下划线**标出所有名词
- 排除明显是属性的名词（如"姓名"、"年龄"）
- 剩下的就是实体候选

### Step 2：识别联系（找菱形）
- 找出动词或动词短语（如"选修"、"创作"、"购买"）
- 判断联系的基数：1:1、1:N、M:N
- 特殊情况：三元联系（三个实体通过一个菱形连接）

### Step 3：识别属性（找椭圆）
- 为每个实体列出所有属性
- 判断属性类型：Simple/Composite、Single/Multi-valued、Stored/Derived
- 为主键画下划线

### Step 4：检查弱实体
- 是否有实体没有自己的主键？
- 如果有，用双层矩形 + 双层菱形 + 虚下划线

### Step 5：检查联系的属性
- M:N 联系的属性 → 挂在菱形上
- 1:N 联系的属性 → 移到 N 端实体

### Step 6：检查三元联系
- 是否有三个实体同时参与一个业务动作？
- 如果有，用三元联系，不要拆成三个二元联系

### Step 7：最终检查
- 所有矩形是否都有属性？
- 所有菱形是否都连接了正确的实体？
- 主键是否都画了下划线？
- 派生属性是否用了虚线椭圆？
- 多值属性是否用了双线椭圆？

## 八、常见扣分点速查表

| 扣分点 | 正确做法 |
|--------|----------|
| 派生属性没画虚线椭圆 | 用**虚线椭圆**表示 |
| 多值属性没画双线椭圆 | 用**双线椭圆**表示 |
| 弱实体没画双层矩形 | 用**双层矩形**表示 |
| 弱实体的联系没画双层菱形 | 用**双层菱形**表示 |
| 部分键没画虚下划线 | 用**虚下划线**表示 |
| M:N联系的属性挂在实体上 | 必须挂在**菱形**上 |
| 三元联系拆成三个二元联系 | 保持**三元联系** |
| 复合属性没画子椭圆 | 主椭圆延伸**子椭圆** |
| 主键没画下划线 | 用**实线下划线**表示 |

## 十、考试答题模板

### 选择题/判断题常见问法

1. "以下哪个是Composite Attribute？"
   - 找可以拆分的属性（如DOB → 年/月/日）

2. "以下哪个是Derived Attribute？"
   - 找可以通过计算得出的属性（如Age = 当前日期 - DOB）

3. "三元联系能否拆成三个二元联系？"
   - 不能！会丢失语义，产生伪露

4. "弱实体的主键是什么？"
   - 弱实体没有主键，只有部分键(Partial Key)

### 设计题答题步骤

1. 画出所有实体（矩形）
2. 画出所有联系（菱形）
3. 画出所有属性（椭圆）
4. 标注主键（下划线）
5. 标注特殊属性（虚线/双线椭圆）
6. 检查基数标注（1:1、1:N、M:N）
7. 检查弱实体（双层矩形+双层菱形）
8. 检查联系属性的归属
