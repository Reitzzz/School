## 3.1 结构化查询语言(SQL)简介

结构化查询语言(SQL)已成为处理关系数据库的标准语言。

主要特性：
- 相对容易学习
- 非过程化——指定需要什么信息，而不是如何获取
- 本质上是自由格式的
- 由标准单词组成，如查询、插入、更新
- 可被各类用户使用

结构化查询语言(SQL)分为两个主要部分：
- **数据定义语言(DDL)**：定义数据库结构
- **数据操纵语言(DML)**：查询和操作数据库中的数据

结构化查询语言(SQL)是一个面向转换的语言，有两个主要组件：
- 用于定义数据库结构的数据定义语言(DDL)
- 用于检索和更新数据的数据操纵语言(DML)

直到第三版标准，结构化查询语言(SQL)不包含流程控制命令（不是计算完备的）。结构化查询语言(SQL)可以交互式使用或嵌入高级语言（如C语言、C++语言）中使用。

### 编写命令

代码语句由保留字和用户定义词组成。

- **保留字**：代码的固定部分，必须精确拼写，不能跨行分割
- **用户定义词**：由用户创建，表示数据库对象（如表、列、视图）的名称

## 3.2 数据操纵语言(DML)

数据库上最常见的操作是查询数据。结构化查询语言(SQL)中只有一个用于查询数据的命令——查询命令。

### 查询基本语法

```sql
SELECT 属性或者表达式
FROM 表名
WHERE 筛选条件;
```

**条件筛选**用于过滤行，有效地实现关系代数中的"选择"操作。条件筛选子句中允许的基本操作包括：
- 算术运算：+、-、*、/
- 关系比较：=、>、<、$\geq$、$\leq$、$\neq$
- 逻辑连接：与、或、非

### 查询子句顺序

```sql
SELECT      -- 所要查询的信息（或 *）
FROM        -- 信息来源
WHERE       -- 筛选条件
GROUP BY    -- 分组标准
HAVING      -- 分组筛选条件
ORDER BY    -- 排序关键字
```

**注意：**
- 各子句的顺序不能改变
- 只有查询和信息来源是强制的
- 分组标准用于按标准对查询结果进行分组，可利用它进行分组汇总
- 分组筛选条件必须跟随分组标准使用，用来对分组统计的结果进行筛选，只有满足分组筛选条件的结果才能放到结果表中
- 排序关键字用来对查询结果按指明的关键字排序，可升序或降序

### 3.2.1 查询所有列所有行

**示例 1**：列出所有员工的完整详细信息。

```sql
SELECT 员工编号, 名字, 姓氏, 职位, 性别, 出生日期, 薪水, 部门编号
FROM 员工表;
```

可以使用 * 作为"所有列"的缩写：

```sql
SELECT *
FROM 员工表;
```

**示例 2**：查询全体学生的详细记录。

```sql
SELECT *
FROM 学生表;
```

**示例 3**：查询全部课程记录。

```sql
SELECT *
FROM 课程表;
```

---

### 3.2.2 查询指定列所有行

**示例 4**：生成所有员工的工资列表，只显示员工编号、名字、姓氏和薪水详情。

```sql
SELECT 员工编号, 名字, 姓氏, 薪水
FROM 员工表;
```

关系代数表示：$\Pi_{员工编号, 名字, 姓氏, 薪水}(员工表)$

**示例 5**：查询全体学生的学号与姓名。

```sql
SELECT 学号, 姓名
FROM 学生表;
```

关系代数表示：$\Pi_{学号,姓名}(学生表)$

### 3.2.3 去重的使用

列出所有已被查看过的房产编号。

```sql
SELECT 房产编号
FROM 看房记录表;
```

使用去重关键字消除重复：

```sql
SELECT DISTINCT 房产编号
FROM 看房记录表;
```

**示例 6**：求已经开始招生的系的名称。

假设学生表数据如下：

| 学号 | 姓名 | 所在系 | 性别 | 年龄 |
|-----|-------|-------|------|------|
| 95001 | 李勇 | 计算机科学(CS) | 男 | 20 |
| 95002 | 刘晨 | 信息系统(IS) | 女 | 19 |
| 95003 | 王名 | 数学系(MA) | 女 | 18 |
| 95004 | 张立 | 信息系统(IS) | 男 | 19 |

已经开始招生的系也就是已经有在读学生的那些系。由于一个系包括多个学生，所以要去掉重复的系名。

关系代数表达式：$\Pi_{所在系}(学生表)$

```sql
SELECT DISTINCT 所在系
FROM 学生表;
```

**注意**：如果查询结果包含了重复的行，要去掉表中的重复行，必须指定去重关键字。没有指定该关键字，则缺省保留取值重复的行。

### 3.2.4 计算字段

目标列不仅可以是算术表达式，还可以是字符串常量、函数等。

**示例**：因为在学生表中没有出生年月的信息，而有学生的年龄信息，所以可以通过当前年份减去学生的年龄，计算出出生年份。

```sql
SELECT 姓名, YEAR(GETDATE()) - 年龄
FROM 学生表;
```

或：

```sql
SELECT 姓名, 2025 - 年龄
FROM 学生表;
```

**更复杂的示例**：

```sql
SELECT 姓名 AS 学生姓名,
       2025 - 年龄 AS 出生年份,
       LOWER(所在系) AS 院系名称
FROM 学生表;
```

查询结果：

| 学生姓名 | 出生年份 | 院系名称 |
|------|------------|------------|
| 李勇 | 2005 | 计算机科学(cs) |
| 刘晨 | 2006 | 信息系统(is) |
| 王名 | 2007 | 数学系(ma) |
| 张立 | 2006 | 信息系统(is) |

**注意**：在不同数据库管理系统(DBMS)中，各种查询语句的格式会有所不同。

### 3.2.5 比较搜索条件

列出薪水大于 10000 的所有员工。

```sql
SELECT 员工编号, 姓名, 职位, 薪水
FROM 员工表
WHERE 薪水 > 10000;
```

**多条件查询示例**：

查询信息系统(IS)的学生：

```sql
SELECT *
FROM 学生表
WHERE 所在系 = '信息系统(IS)';
```

查询信息系统(IS)的女生：

```sql
SELECT *
FROM 学生表
WHERE 所在系 = '信息系统(IS)' AND 性别 = '女';
```

查询信息系统(IS)年龄小于 20 岁的学生：

关系代数表达式：$\Pi_{学号,姓名}(\sigma_{所在系='信息系统(IS)' \land 年龄<20}(学生表))$

```sql
SELECT 学号, 姓名
FROM 学生表
WHERE 所在系 = '信息系统(IS)' AND 年龄 < 20;
```

### 3.2.6 范围搜索条件

**范围限制**的使用：

```sql
SELECT 员工编号, 姓名, 职位, 薪水
FROM 员工表
WHERE 薪水 BETWEEN 45000 AND 50000;
```

也有否定版本（不在范围内）。

范围限制并没有给代码增加太多表达能力，也可以写成：

```sql
SELECT 员工编号, 姓名, 职位, 薪水
FROM 员工表
WHERE 薪水 >= 45000 AND 薪水 <= 50000;
```

但对于一系列值来说，范围限制很有用。

### 3.2.7 集合成员资格

列出所有经理和主管。

```sql
SELECT 员工编号, 名字, 姓氏, 职位
FROM 员工表
WHERE 职位 IN ('经理', '主管');
```

**示例 18**：查询不在信息系统(IS)、数学系(MA)和计算机科学(CS)的学生的姓名和性别。

```sql
SELECT 姓名, 性别
FROM 学生表
WHERE 所在系 NOT IN ('信息系统(IS)', '数学系(MA)', '计算机科学(CS)');
```

### 3.2.8 模式匹配

使用模糊匹配进行通配符搜索：
- `%`：匹配任意长度（包括零长度）的字符串
- `_`：匹配单个字符

查询姓"刘"的学生：

```sql
SELECT 姓名, 学号, 性别
FROM 学生表
WHERE 姓名 LIKE '刘%';
```

查询姓"刘"且名字只有两个字的学生的姓名、学号和性别：

```sql
SELECT 姓名, 学号, 性别
FROM 学生表
WHERE 姓名 LIKE '刘_';
```

**注意**：例如语句 `WHERE 姓名 = "王%"`，执行时会查出姓名为"王%"的学生，而不是姓王的学生。要使用模糊匹配才能进行模式匹配。

### 3.2.9 空值(NULL)搜索条件

必须使用特殊关键字显式测试是否为空值(NULL)。

```sql
SELECT 学号, 课程编号
FROM 成绩表
WHERE 成绩 IS NULL;
```

**注意**：空值(NULL)前面只能用为空判断或者不为空判断。例如直接使用等号连接是错误的写法。

### 3.2.10 列排序

使用排序关键字对结果排序，可以跟多个关键字。

```sql
SELECT 学号, 课程编号, 成绩
FROM 成绩表
ORDER BY 学号, 课程编号;
```

默认升序排列，降序使用降序关键字：

```sql
SELECT 学号, 课程编号, 成绩
FROM 成绩表
ORDER BY 学号 ASC, 成绩 DESC;
```

### 3.2.11 聚合函数

代码聚合函数：

| 函数 | 说明 |
|------|------|
| COUNT(*) | 统计元组个数 |
| COUNT(DISTINCT 列名) | 统计列中不同值的个数 |
| SUM(列名) | 计算列值总和 |
| AVG(列名) | 计算列值平均值 |
| MAX(列名) | 求列值最大值 |
| MIN(列名) | 求列值最小值 |

**示例**：假设有关系选课表，确定课程编号为"ACSC7101"的最高分、最低分和平均分：

```sql
SELECT MAX(成绩), MIN(成绩), AVG(成绩)
FROM 选课表
WHERE 课程编号 = 'ACSC7101';
```

**示例 27**：列出员工的最低、最高和平均薪水。

```sql
SELECT MIN(薪水) AS 最低薪水,
       MAX(薪水) AS 最高薪水,
       AVG(薪水) AS 平均薪水
FROM 员工表;
```

**注意**：如果查询列表包含聚合函数并且没有分组标准子句，则查询列表不能使用非聚合函数。

### 限定属性

使用限定词来区分不同表中的同名属性。

### 别名

使用别名关键字为表或列指定别名。

### 分组数据

使用**分组标准**子句获取分类汇总。

**规则**：查询列表中的所有列名必须出现在分组标准子句或聚合函数中。

如果使用条件筛选，则首先应用条件筛选，然后从满足谓词的行组成组。国际标准化组织(ISO)认为两个空值(NULL)在分组标准中是相等的。

**示例**：查询各个系的在校学生人数。

```sql
SELECT 所在系, COUNT(*)
FROM 学生表
GROUP BY 所在系;
```

或：

```sql
SELECT 所在系, COUNT(学号)
FROM 学生表
GROUP BY 所在系;
```

**注意**：目标列中一定要包括分组标准后面的作为分组标准的属性列。

### 分组筛选

分组筛选条件用于对分组做筛选。在分组筛选子句中出现的列名，必须同时满足以下两个条件之一：
- 包含在分组标准列表中，或
- 出现在聚合函数内（如求和、平均值、计数等）

**示例 31**：查询男、女学生的人数。

```sql
SELECT 性别, COUNT(*)
FROM 学生表
GROUP BY 性别;
```

**示例 32**：查询选修了三门以上课程的学生的学号与平均成绩。

```sql
SELECT 学号, AVG(成绩)
FROM 成绩表
GROUP BY 学号
HAVING COUNT(课程编号) > 3;
```

**示例**：查询学生人数超过 200 人的系。

第一步：
```sql
SELECT 所在系, COUNT(学号)
FROM 学生表
GROUP BY 所在系
HAVING COUNT(学号) > 200;
```

### 3.2.12 多表查询

执行表连接时，需在信息来源子句中包含多个数据表，使用逗号分隔表名，并通过条件筛选子句指定连接条件。或者在信息来源子句完成连接。

**数据库设计示例**：
- 学生表(学号, 姓名, 出生日期, 所在系, 地址, 电话, 性别, 学位)
- 讲师表(教师编号, 姓名, 部门, 地址, 电话, 职称)
- 课程表(课程编号, 课程名称, 先修课程编号, 学分)
- 授课表(教师编号, 课程编号, 课时)
- 选课表(学号, 课程编号, 成绩)

**首选连接语法**（更具结构化特征）：

```sql
SELECT *
FROM 学生表 s JOIN 选课表 e ON s.学号 = e.学号;
```

**替代连接构造**：

```sql
-- 使用连接条件
FROM 学生表 s JOIN 选课表 e ON s.学号 = e.学号

-- 使用相同字段连接
FROM 学生表 JOIN 选课表 USING (学号)

-- 自然连接
FROM 学生表 NATURAL JOIN 选课表
```

**示例 36**：回答"张三选修了哪些课程（按名称）？"

```sql
SELECT 课程名称
FROM 课程表, 选课表, 学生表
WHERE 课程表.课程编号 = 选课表.课程编号
  AND 选课表.学号 = 学生表.学号
  AND 姓名 = '张三';
```

**外连接**

**示例 37**：列出所有课程（编号和名称）及其授课教师（按编号和课时），如果没有授课教师，则列出空值(NULL)。

```sql
SELECT c.课程编号, c.课程名称, t.教师编号, t.课时
FROM 课程表 c LEFT JOIN 授课表 t ON c.课程编号 = t.课程编号;
```

**示例 38**：列出所有教师（姓名、职称）及其所授课程（按编号），如果没有课程，则列出空值(NULL)。

```sql
SELECT 姓名, 职称, 课程编号
FROM 讲师表 LEFT JOIN 授课表 ON 讲师表.教师编号 = 授课表.教师编号;
```

查询没有开课的老师：

```sql
SELECT 姓名, 职称
FROM 讲师表
WHERE 教师编号 NOT IN (SELECT 教师编号 FROM 授课表);
```

或：

```sql
SELECT 姓名, 职称, 课程编号
FROM 讲师表 LEFT JOIN 授课表 ON 讲师表.教师编号 = 授课表.教师编号
WHERE 课程编号 IS NULL;
```

**总结**：
1. 如果查询涉及到两张表以上（即所求信息来自多张表或所求信息和查询条件来自不同的表），则必须有连接条件。
2. 信息来源后面有 $N$ 张表，则连接条件有 $N-1$ 个。

### 3.2.13 子查询

查询可以具有多层结构，即一个查询可包含其他（子）查询。

**示例**：查询某门课程最高分的学生（最高分具体值未知）。

```sql
SELECT 姓名
FROM (学生表 s JOIN 选课表 e ON s.学号 = e.学号)
WHERE 课程编号 = 'ACSC7103'
  AND 成绩 = (SELECT MAX(成绩)
              FROM 选课表
              WHERE 课程编号 = 'ACSC7103');
```

- 外层查询
- 子查询：通过子查询计算最高分

子查询可应用于外部查询语句的信息来源、条件筛选和分组筛选子句。此外，子查询还可用于插入、更新及删除语句中。

#### 数据源中的嵌套

信息来源子句也可嵌套子查询。正如关系代数中可先进行筛选之后再连接。

```sql
-- 先分组求和，再连接
-- 或先连接，再分组求和
```

#### (1) 不相关子查询

内层查询独立于外层查询（子查询本身即可独立执行）。在执行嵌套查询时，内层查询仅需执行一次即可。

**使用包含关键字的子查询**：

```sql
SELECT 姓名
FROM 学生表
WHERE 所在系 IN (SELECT 所在系
                FROM 学生表
                WHERE 姓名 = '张三');
```

**示例 41**：查找选修了"数据库理论"课程的学生。

```sql
SELECT 姓名, 所在系, 地址
FROM 学生表
WHERE 学号 IN (SELECT 学号
              FROM 选课表
              WHERE 课程编号 IN (SELECT 课程编号
                            FROM 课程表
                            WHERE 课程名称 = '数据库理论'));
```

**示例 42**：查找信息系统(IS)专业学生选修的课程（按名称）。

```sql
SELECT 课程名称
FROM 课程表
WHERE 课程编号 IN (SELECT 课程编号
              FROM 选课表
              WHERE 学号 IN (SELECT 学号
                            FROM 学生表
                            WHERE 所在系 = '信息系统(IS)'));
```

**示例 43**：查找平均分大于 80 且最低分不低于 75 的学生（按名称）。

```sql
SELECT 姓名, 所在系
FROM 学生表
WHERE 学号 IN (SELECT 学号
              FROM 选课表
              GROUP BY 学号
              HAVING AVG(成绩) > 80 AND MIN(成绩) >= 75);
```

#### 带比较运算符的子查询

**示例 44**：列出薪水高于平均薪水的所有员工。

```sql
SELECT *
FROM 员工表
WHERE 薪水 > (SELECT AVG(薪水) FROM 员工表);
```

**示例 40**：查找在 '杰斐逊路8号' 分支工作的员工。

```sql
SELECT *
FROM 员工表
WHERE 部门编号 = (SELECT 部门编号
                  FROM 部门表
                  WHERE 街道 = '杰斐逊路8号');
```

#### 带有存在(EXISTS)谓词的子查询

**存在谓词**：
- 存在量词 $\exists$：$(\exists x)P$
- 存在判断 + 子查询：判断子查询是否返回元组
- 若内层查询结果非空，则外层的条件筛选子句返回真值
- 若内层查询结果为空，则外层的条件筛选子句返回假值
- 由存在判断引出的子查询，其目标列表达式通常都用 *，因为带存在判断的子查询只返回真值或假值，给出列名无实际意义

**不存在谓词**：
- 若内层查询结果非空，则外层的条件筛选子句返回假值
- 若内层查询结果为空，则外层的条件筛选子句返回真值

"存在一个"、"至少一个"

#### (2) 相关子查询

内部查询（子查询）需要为外部查询返回的每一行执行。

**示例**：哪些老师（若有）未教授任何课程？

```sql
SELECT 姓名
FROM 讲师表
WHERE NOT EXISTS (SELECT *
                  FROM 授课表
                  WHERE 讲师表.教师编号 = 授课表.教师编号);
```

**示例 45**：哪些学生（若有）未选修课程代码为 ('1', '3', '5', '8') 中任意一门课程？

不相关子查询：
```sql
SELECT 姓名
FROM 学生表
WHERE 学号 NOT IN (SELECT 学号
                  FROM 选课表
                  WHERE 课程编号 IN ('1', '3', '5', '8'));
```

相关子查询：
```sql
SELECT 姓名
FROM 学生表
WHERE NOT EXISTS (SELECT *
                  FROM 选课表
                  WHERE 选课表.学号 = 学生表.学号
                    AND 课程编号 IN ('1', '3', '5', '8'));
```

使用连接：
```sql
SELECT 姓名
FROM (学生表 LEFT JOIN 选课表 ON 学生表.学号 = 选课表.学号)
WHERE 课程编号 IN ('1', '3', '5', '8')
  AND 选课表.学号 IS NULL;
```

查询没有选修任何课程的学生：
```sql
SELECT 姓名
FROM 学生表
WHERE NOT EXISTS (SELECT * FROM 选课表 WHERE 选课表.学号 = 学生表.学号);
```

### 子查询规则

1. 排序子句不能用于子查询（虽然可用于最外层查询）
2. 子查询查询列表必须只包含单个列名或表达式（使用存在判断的子查询除外）
3. 默认情况下，子查询列名引用的是子查询信息来源子句中的表名。可以使用别名引用信息来源中的表

### 代码实现除法

例如，查找选修了大学所有课程的学生（选了所有课的学生）。

分析：这个问题意味着要找到满足以下条件的学生——不存在任何课程，该学生没有选。即：不存在任何课程，该学生没有选修。

```sql
-- 方法1：使用不存在判断
SELECT 姓名
FROM 学生表
WHERE NOT EXISTS (SELECT *
                  FROM 课程表
                  WHERE NOT EXISTS (SELECT *
                                    FROM 选课表
                                    WHERE 选课表.学号 = 学生表.学号
                                      AND 选课表.课程编号 = 课程表.课程编号));
```

**用存在/不存在判断实现全称量词（难点）**

结构化查询语言(SQL)中没有全称量词 $\forall$。可以把带有全称量词的谓词转换为等价的带有存在量词的谓词：

$$(\forall x)P \equiv \neg(\exists x(\neg P))$$

"对所有的"、"对每一个" $\leftrightarrow$ "不存在 $X$：不满足谓词 $P$"

```sql
-- 方法2：使用分组标准和分组筛选
SELECT 姓名
FROM 学生表
WHERE 学号 IN (SELECT 学号
              FROM 成绩表
              GROUP BY 学号
              HAVING COUNT(*) = (SELECT COUNT(*) FROM 课程表));
```

**示例**：查找选修了学生 '95002' 所选所有课程的学生。

```sql
SELECT 姓名
FROM 学生表
WHERE NOT EXISTS (SELECT *
                  FROM 选课表 记录1
                  WHERE 记录1.学号 = '95002'
                    AND NOT EXISTS (SELECT *
                                    FROM 选课表 记录2
                                    WHERE 记录2.学号 = 学生表.学号
                                      AND 记录2.课程编号 = 记录1.课程编号));
```

### 3.2.14 集合运算

三种主要的关系代数集合运算：
- 并集
- 差集
- 交集

差集和交集可以使用其他标准代码构造来完成。

#### 并集

要"并"的两组或多组记录必须是并兼容的，也就是说，它们必须具有相同的结构（对应的属性）。

```sql
SELECT 姓名 AS 名称, 地址, 电话
FROM 讲师表
UNION
SELECT 姓名, 地址, 电话
FROM 学生表;
```

查询来自数学系(MA)的或者大于 18 岁的学生学号、姓名、系别、年龄：

```sql
SELECT 学号 AS 编号, 姓名, 所在系, 年龄
FROM 学生表
WHERE 所在系 = '数学系(MA)'
UNION
SELECT 学号, 姓名, 所在系, 年龄
FROM 学生表
WHERE 年龄 > 18;
```

#### 差集示例

查询哪些讲师（如果有的话）没有教授任何课程？

用集合术语表示，这就是所有讲师的集合减去授课讲师的集合。

```sql
SELECT 教师编号
FROM 讲师表
EXCEPT
SELECT DISTINCT 教师编号
FROM 授课表;
```

#### 交集示例

哪些讲师也是学生？

```sql
SELECT 姓名
FROM 讲师表
WHERE EXISTS (SELECT * FROM 学生表 WHERE 学生表.姓名 = 讲师表.姓名);
```

或使用交集运算：

```sql
SELECT 姓名
FROM 讲师表
INTERSECT
SELECT 姓名
FROM 学生表;
```

## 3.3 数据操纵语言(DML)更新

- 插入语句：插入数据到关系
- 更新语句：修改关系中的数据
- 删除语句：从数据库删除数据

---

### 3.3.1 插入数据

**单行插入**：

```sql
INSERT INTO 表名 [(列名列表)]
VALUES (数据值列表);
```

任何被省略的列在创建表时必须被声明为不为空或者指定了默认值。数据值列表必须与列名列表一一对应。

**插入多行使用嵌套子查询**：

```sql
INSERT INTO 表名 [(列名列表)]
SELECT ...;
```

---

### 3.3.2 更新数据

```sql
UPDATE 表名
SET 列名1 = 值1, 列名2 = 值2, ...
WHERE 条件;
```

**示例**：将选修了"数据库系统导论"课程的每个学生的成绩提高 5%。

```sql
UPDATE 选课表
SET 成绩 = 成绩 * 1.05
WHERE '数据库系统导论' = (SELECT 课程名称
                        FROM 课程表 c
                        WHERE c.课程编号 = 选课表.课程编号);
```

使用了连接更新语法（在多数现代数据库中支持）。

相关数据库语法：
```sql
UPDATE 选课表 e
JOIN 课程表 c ON c.课程编号 = e.课程编号
SET e.成绩 = e.成绩 * 1.05
WHERE c.课程名称 = '数据库系统导论';
```

**示例**：将来自计算机科学(CS)系且选修了"数据库理论"课程的每个学生的成绩提高 5%。

---

### 3.3.3 删除数据

```sql
DELETE FROM 表名
WHERE 搜索条件;
```

表名可以是基本表的名称或可更新视图的名称。搜索条件是可选的；如果省略，则删除表中的所有行。这不会删除表本身。如果指定了搜索条件，则只删除满足条件的行。

**与更新语句类似，如果条件筛选子句缺失，则会删除表中的所有行！**

**多表删除风格**：

```sql
DELETE t1, t2
FROM 表1 t1
JOIN 表2 t2 ON ...
WHERE ...;
```

## 3.4 数据定义语言(DDL)

数据定义语言(DDL)标准中的主要语句：
- 创建表：创建新表
- 删除表：删除表
- 创建视图：创建新视图
- 删除视图：删除视图
- 创建索引：创建索引
- 删除索引：删除索引

| 操作 | 表 | 视图 | 索引 |
|------|-----|------|------|
| 创建 | 创建表 | 创建视图 | 创建索引 |
| 删除 | 删除表 | 删除视图 | 删除索引 |

---

### 3.4.1 创建表

```sql
CREATE TABLE 表名 (
    列名 数据类型 [NOT NULL] [UNIQUE] [DEFAULT 默认值] [CHECK 条件],
    ...
    [PRIMARY KEY (列名列表)],
    [FOREIGN KEY (列名列表) REFERENCES 表名(列名列表)]
);
```

**定义列**：
- 数据类型
- 约束：不为空、唯一、默认值、检查条件

**实体完整性**：通过主键约束来实现。

**参照完整性**：通过外键约束来实现。

**示例**：

```sql
CREATE TABLE 学生表 (
    学号 CHAR(10) NOT NULL UNIQUE,
    姓名 CHAR(20),
    所在系 CHAR(30),
    性别 CHAR(2),
    出生日期 DATETIME,
    电话 CHAR(18),
    学位 CHAR(20),
    CONSTRAINT 主键_学生 PRIMARY KEY (学号)
);
```

```sql
CREATE TABLE 选课表 (
    学号 CHAR(10) NOT NULL,
    课程编号 CHAR(8) NOT NULL,
    成绩 TINYINT,
    PRIMARY KEY (学号, 课程编号),
    FOREIGN KEY (学号) REFERENCES 学生表(学号),
    FOREIGN KEY (课程编号) REFERENCES 课程表(课程编号)
);
```

---

### 3.4.2 删除表

```sql
DROP TABLE 表名;
```

例如：`DROP TABLE 学生表;`

---

### 3.4.3 创建索引

建立索引的目的：加快查询速度。

索引文件中只包含索引项和元组地址。

**作为一般规则**，不应该在一个表上建立太多的索引（一般不超过 2-3 个）。索引能改善查询效果，但也消耗了磁盘空间，降低了更新操作的性能，这是因为系统必须花时间来维护这些索引。除了为数据完整性而建立的唯一索引外，建议在表较大时再建立普通索引，表中的数据越多，索引的优越性越明显。

**创建聚簇索引**：

```sql
CREATE CLUSTERED INDEX 索引名称 ON 学生表(所在系);
```

学生表的数据物理存储顺序和逻辑顺序，均按照所在系排序。一张表只能建一个聚簇索引。

```sql
CREATE TABLE 学生表 (
    学号 CHAR(8),
    姓名 CHAR(20) UNIQUE,
    PRIMARY KEY NONCLUSTERED (学号)
);
```

**为什么使用索引？**
1. 维护数据的唯一性（唯一索引）
2. 提高查询速度（降低更新速度，更新关系表的数据，同时更新索引表的数据）

---

### 3.4.4 删除索引

```sql
DROP INDEX 索引名称;
```

例如：`DROP INDEX 课程编号索引;`

### 3.4.5 创建视图

视图是一种虚拟关系表，它并非物理存储于数据库内，而是根据用户请求实时动态生成。

```sql
CREATE VIEW 视图名称 [(列名列表)]
AS SELECT ...
[WITH CHECK OPTION];
```

其中子查询可以是任意复杂的查询语句，但通常不允许含有排序子句和去重短语。

如果创建视图语句仅指定了视图名，则隐含该视图由子查询中查询目标列中的诸字段组成。但在下列三种情况下必须明确指定组成视图的所有列名：
1. 其中某个目标列不是单纯的属性名，而是集函数或列表达式
2. 多表连接时选出了几个同名列作为视图的字段
3. 需要在视图中为某个列启用新的更合适的名字

**示例**：

```sql
CREATE VIEW 员工部门视图
AS SELECT 员工编号, 姓名, 职位
   FROM 员工表
   WHERE 部门编号 = 'B001';
```

**示例 46**：建立信息系统(IS)系学生的视图。

```sql
CREATE VIEW 信息系统学生视图
AS SELECT 学号, 姓名, 年龄
   FROM 学生表
   WHERE 所在系 = '信息系统(IS)';
```

数据库管理系统(DBMS)执行此语句就相当于建立如下虚表。

**示例 47**：建立信息系统(IS)系学生的视图，并要求进行修改和插入操作时仍保证该视图只有信息系统(IS)系的学生。

```sql
CREATE VIEW 信息系统学生视图
AS SELECT 学号, 姓名, 年龄
   FROM 学生表
   WHERE 所在系 = '信息系统(IS)'
   WITH CHECK OPTION;
```

加了检查选项子句，以后对该视图进行插入、修改和删除操作时，数据库管理系统(DBMS)会自动加上所在系必须匹配的条件。

**注意**：
- 视图的列与子查询的目标列对应
- 子查询不能带有排序子句和去重关键字。数据源后不能用临时表
- 检查选项对视图进行更新时进行检查
- **行列子集视图**：若有一个视图是从单个基本表导出的，并且只是去掉了基本表的某些行和某些列，但保留了码，称之为行列子集视图
- 视图不仅可以建立在单个基本表上，也可以建立在多个基本表上，也可以建立在其它视图上，或者其它基本表和视图上
- 视图一旦定义，就可以像基本表一样被查询

---

### 3.4.6 查询视图

用户角度：查询视图与查询基本表相同，视图定义后，就可以像对待基本表一样对视图进行查询操作。

关系型数据库管理系统(RDBMS)实现视图查询的方法——**视图消解法**：
1. 进行有效性检查：检查查询的表、视图等是否存在。如果存在，则从数据字典中取出视图的定义
2. 转换成等价的对基本表的查询：把视图定义中的子查询与用户的查询结合起来
3. 执行修正后的查询

**示例**：在信息系统(IS)学生的视图中找出年龄小于 20 岁的学生。

```sql
SELECT 学号, 年龄
FROM 信息系统学生视图
WHERE 年龄 < 20;
```

视图消解转换后的查询语句为：

```sql
SELECT 学号, 年龄
FROM 学生表
WHERE 所在系 = '信息系统(IS)' AND 年龄 < 20;
```

---

### 3.4.7 更新视图

对于视图元组的更新操作（插入、删除、更新），有以下三条规则：
1. 如果一个视图是从多个基本表使用连接操作导出的，那么不允许对这个视图执行更新操作
2. 如果在导出视图的过程中，使用了分组和聚集函数操作，也不允许对这个视图执行更新操作
3. 行列子集视图可以执行更新操作

在第二版标准中，允许更新的视图在定义时，必须加上检查选项短语。数据库管理系统(DBMS)在更新视图时会进行检查，防止用户通过视图对不属于视图范围内的基本表数据进行更新。

**示例**：将信息系统(IS)学生视图中学号为 200215122 的学生姓名改为"刘辰"。

```sql
UPDATE 信息系统学生视图
SET 姓名 = '刘辰'
WHERE 学号 = '200215122';
```

转换后的语句：

```sql
UPDATE 学生表
SET 姓名 = '刘辰'
WHERE 学号 = '200215122' AND 所在系 = '信息系统(IS)';
```

---

### 3.4.8 删除视图

```sql
DROP VIEW 视图名称;
```

示例：将女生数据视图删除。

```sql
DROP VIEW 女生视图;
```

### 视图的作用

- 视图能够简化用户的操作，聚焦于所关心的数据上
- 视图使用户能以多种角度看待同一数据，增加灵活性
- 视图对重构数据库提供了一定程度的逻辑独立性
- 视图能够对机密数据提供安全保护
- 适当的利用视图可以更清晰的表达查询

## 3.5 自主访问控制(DAC)

自主访问控制(DAC)：每个用户被授予对特定数据库对象的适当访问权限。通常，用户在创建对象时获得某些权限，并可以酌情将这些权限的部分或全部传递给其他用户。虽然灵活，但这种授权机制可能被狡猾的未授权用户通过欺骗授权用户泄露敏感数据来规避。

结构化查询语言(SQL)仅通过授予权限和收回权限语句支持自主访问控制(DAC)。该机制基于授权标识符、所有权和特权的概念。

### 权限

权限是用户被允许在特定基表或视图上执行的操作。

国际标准化组织(ISO)标准定义的权限：
- **查询权限**：从表中检索数据的权限
- **插入权限**：向表中插入新行的权限
- **更新权限**：修改表中数据行的权限
- **删除权限**：从表中删除数据行的权限
- **引用权限**：在完整性约束中引用命名表的列的权限
- **使用权限**：使用域、排序规则、字符集和转换的权限

### 授予权限

授予权限语句由表的所有者使用，以给予其他用户对数据的访问。

```sql
GRANT {权限列表 | ALL PRIVILEGES}
ON 对象名称
TO {用户列表 | PUBLIC}
[WITH GRANT OPTION];
```

权限列表由以下一个或多个权限组成，用逗号分隔：
- 查询权限
- 删除权限
- 插入权限
- 更新权限
- 引用权限
- 使用权限

**传递授权子句**：
允许授权标识列表中的用户，将已获得的指定对象权限转授给其他用户。其核心规则如下：
- 权限传递链：若用户A通过传递授权子句获得权限并转授给用户B时同样指定该子句，则用户B可继续将权限授予用户C，形成传递链
- 权限封锁：若未指定此子句，被授权用户仅能使用权限，无法二次转授
- 控制权保留：通过限制权限传递，对象所有者能严密管控权限的最终使用者和允许的操作范围

**示例**：给授权标识符为经理的用户员工表的所有权限。

```sql
GRANT ALL PRIVILEGES
ON 员工表
TO 经理
WITH GRANT OPTION;
```

用户经理现在可以从员工表检索行，也可以插入、更新和删除此表中的数据。经理还可以引用员工表，以及在他随后创建的任何表中引用所有员工表列。我们还指定了关键字传递授权选项，以便经理可以将这些权限传递给其他用户。

**示例**：给用户人事和总监关于员工表薪水列的查询和更新权限。

```sql
GRANT SELECT, UPDATE (薪水)
ON 员工表
TO 人事, 总监;
```

没有使用传递授权关键字，因此用户人事和总监不能将这些权限传递给其他用户。

**示例**：给所有用户(PUBLIC)关于部门表的查询权限。

```sql
GRANT SELECT
ON 部门表
TO PUBLIC;
```

使用所有用户关键字意味着所有用户（现在和将来的）都能够检索部门表中的所有数据。

### 收回权限

收回权限语句可以收回之前授予用户的全部或部分权限。

```sql
REVOKE [GRANT OPTION FOR] {权限列表 | ALL PRIVILEGES}
ON 对象名称
FROM {用户列表 | PUBLIC} [RESTRICT | CASCADE];
```

可选的授权选项子句允许单独收回通过授予权限语句传递的权限，而不收回权限本身。

**收回权限的效果**：
通过此语句收回的该用户由其他用户授予的权限不受影响。因此，如果另一个用户已向该用户授予了正在撤销的权限，则该其他用户的授予仍然允许该用户访问该表。

**示例**：从所有用户收回部门表的查询权限。

```sql
REVOKE SELECT
ON 部门表
FROM PUBLIC;
```

**示例**：收回你授予总监的员工表的所有权限。

```sql
REVOKE ALL PRIVILEGES
ON 员工表
FROM 总监;
```
