## 1. 基本概念

| 概念 | 必背解释 |
| --- | --- |
| Data 数据 | 描述事物的符号记录，**是数据库中存储和处理的基本对象**。 `【闭卷重点·常考】` |
| Information 信息 | **对数据加工、解释后形成的有意义内容**。数据库通常存储数据，由应用或用户解释成信息。 |
| Database, DB 数据库 | 长期存储在计算机内、有组织、可共享的**大量数据集合**。 `【闭卷重点·必背】` |
| DBMS 数据库管理系统 | 位于用户/应用程序和操作系统之间的**数据管理软件**，负责定义、组织、存储、维护、查询、更新、安全和恢复。 `【闭卷重点·必背】` |
| Database System, DBS 数据库系统 | 通常由数据库、DBMS、数据库应用程序、用户/管理员、硬件和软件环境**共同构成**。 `【闭卷重点·必背】` |
| View 视图 | 从一个或多个基本表**导出的虚拟表，通常只保存定义**，不实际保存完整数据。 `【闭卷重点·常考】` |

易错点：
- 一个数据库系统可以包含多个数据库应用程序，应用程序访问数据库系统中的数据库。 `【闭卷重点·易错】`
- DB 是数据集合，DBMS 是管理软件，DBS 是包含 DB、DBMS、应用和人员的完整系统。 `【闭卷重点·必背】`

## 2. 数据库系统的目标

数据库方法相比文件系统的优势：
- 降低数据冗余和不一致。
- 支持数据共享和并发访问。
- 加强完整性、安全性、备份和恢复。
- 提供数据独立性，使应用程序尽量不随数据结构变化而频繁修改。

可能缺点：
- DBMS 复杂、成本高。
- 对硬件、管理人员和备份恢复要求更高。
- 数据集中后，故障影响范围更大。

## 3. 数据模型

数据模型是用于描述数据、数据联系、数据语义和一致性约束的一组概念。（**通俗理解**：就像造房子需要图纸一样，建立数据库也需要一套“蓝图”规范，这套规范就是数据模型。）

三要素（以“教务系统”为例）： `【闭卷重点·必背】`
1. **数据结构**：描述数据对象及对象之间的**联系**。
   - **举例**：系统里有“学生”和“课程”这两种数据对象（表），并且规定了“一个学生可以选多门课程”。
2. **数据操作**：描述可执行的查询、插入、删除、修改等**操作**。
   - **举例**：教务处老师能“添加”新生信息，学生能“查询”自己的成绩。
3. **完整性规则**：描述数据必须满足的**约束**。
   - **举例**：学生的“学号”必须唯一不能重复，学生的“年龄”必须在 15-30 岁之间。

主要层次（数据抽象的三个阶段）：
- **概念数据模型**：面向现实世界，如 ER 模型。
   - **举例**：**画出的业务草图**，矩形代表“学生”，椭圆代表“学号”，菱形代表“选课”关系。不涉及具体技术，非技术人员也能看懂。
- **逻辑数据模型**：面向 DBMS，如关系模型。
   - **举例**：将上面的 ER 图转换成了**二维表格结构**，定义了 `Student(ID, Name, Age)` 这样的关系表，准备放在 MySQL 中管理。
- **物理数据模型**：面向存储实现，如文件组织、索引、存取路径。
   - **举例**：决定这张 `Student` 表**在服务器硬盘上怎么存**，并且为了查询快，在 `ID` 列上建立了一个 B+ 树索引。

关系数据模型也由三部分组成：
- 关系数据结构（例如：二维表）。
- 关系操作（例如：SQL 语句的 SELECT、INSERT 等）。
- 完整性约束（例如：主键约束、外键约束）。

## 4. 三级模式与两级映像

三级模式（主要目的是为了实现数据独立性）：
- **外模式 External Schema**（顶层）：用户或应用看到的局部逻辑结构，可对应视图。 `【闭卷重点·常考】`
  - **通俗理解**：每个**具体的应用或用户能看到什么定制化的数据（数据卡片）**。一个数据库可以有多个外模式，保证数据安全和操作简化。
  - **举例**：
    - 面向买家的手机 App：只能看到自己的 `username` 和 `balance`，看不到密码和其他人信息。
    - 快递员派件系统：只能看到用户的 `username`、`phone_number` 和收货地址，看不到账户余额。
- **概念模式 Conceptual Schema**（中间层）：全体数据的整体逻辑结构，**是用户和应用程序都能看到的数据库逻辑结构描述**。 `【闭卷重点·必背】`
  - **通俗理解**：整个系统到底有哪些数据（数据库设计蓝图）。**一个数据库只有一个概念模式。**
  - **举例**：数据库设计师设计出的 `Users` 表，里面有 `user_id`、`username`、`password`、`balance` 等字段，以及它和 `Orders` 表的关联关系。
- **内模式 Internal Schema**（底层）：**数据的物理存储结构和存取方式**。 `【闭卷重点·常考】`
  - **通俗理解**：数据真正在硬盘上长什么样。这部分通常由 DBA 关心。
  - **举例**：淘宝用户的密码用 MD5 加密存储；用户数据存放在服务器硬盘的 `/var/lib/mysql/user_data.ibd` 文件里；为了加快查询，给“用户ID”建立了 B+ 树索引。

两级映像（像“减震器”一样吸收变化带来的影响，连接三级模式）：
- **外模式/概念模式映像**：保证**逻辑数据独立性**。
  - **举例**：如果我们在底层概念模式（`Users` 表）里增加了一个 `age`（年龄）字段，由于有这个映像转换，原来的手机 App 和派件系统（外模式）不需要修改任何代码，依然能正常工作。
- **概念模式/内模式映像**：保证**物理数据独立性**。
  - **举例**：如果 DBA 把数据库的存储硬盘从机械硬盘换成了固态硬盘，或者改变了索引方式（内模式改变），由于有这个映像转换，开发人员写的 SQL 语句（概念模式层面）一行都不用改。

考试句：
```text
数据独立性由数据库系统的三级模式结构及两级映像保证。
```

## 5. 数据独立性

数据独立性指应用程序与数据库中的数据结构相互独立，数据结构变化时应用程序尽量不需要修改。

| 类型 | 面对的变化 | 例子 |
| --- | --- | --- |
| 逻辑数据独立性 | 概念模式变化 | **表增加字段、拆分表、通过视图保持旧程序接口不变**。 `【闭卷重点·必背】` |
| 物理数据独立性 | 内模式变化 | **增加索引、改变存储位置、调整文件组织方式，SQL 不变**。 `【闭卷重点·必背】` |

常考选择题：
- “应用程序不受数据结构变化影响”是数据独立性。
- “应用程序独立于数据库结构”是数据独立性的含义。

## 6. 数据库语言

| 类型 | 作用 | 常见命令 |
| --- | --- | --- |
| **DDL 数据定义语言** | 定义和修改数据库对象结构 | `CREATE TABLE`, `ALTER TABLE`, `DROP TABLE`, `CREATE VIEW`, `CREATE INDEX` `【闭卷重点·常考】` |
| **DML 数据操纵语言** | 查询和更新数据(CRUD) | `SELECT`, `INSERT`, `UPDATE`, `DELETE` `【闭卷重点·常考】` |
| **DCL 数据控制语言** | 权限控制 | `GRANT`, `REVOKE` |

易错点：
- “从表中查找若干行”属于查询，通常归入 DML/DQL，不是 DDL。 `【闭卷重点·易错】`
- 创建表、创建视图、修改表结构属于 DDL。

## 7. 安全性与完整性

| 概念 | 重点 |
| --- | --- |
| Security 安全性 | **防止未授权访问、修改、破坏或泄露。** |
| Integrity 完整性 | **保证数据正确、有效、相容，符合现实世界约束。** |

二者区别：
- 安全性问“谁能访问/修改”。
- 完整性问“数据本身是否合理”。

## 8. 数据库相关人员职责

| 角色 | 职责 |
| --- | --- |
| Data Administrator, DA | 管理组织层面的数据资源，制定数据标准、政策，参与概念/逻辑规划。 |
| Database Administrator, DBA | 数据库日常管理、物理设计、安全、完整性、备份恢复、性能监控。 `【闭卷重点·常考】` |
| Logical Database Designer | 识别实体、属性、联系和约束，设计逻辑结构。 |
| Physical Database Designer | 决定逻辑设计如何在存储设备上实现。 |
| Application Developer | 编写数据库应用程序。 |
| End-users | 通过应用程序或查询语言使用数据库。 |

必记陷阱：
```text
DBA 不负责设计 DBMS 软件本身。 【闭卷重点·易错】
```

## 9. 多用户数据库架构

了解即可，但复习时要能区分：
- 集中式数据库：数据和处理集中在一台主机。
- 文件服务器：文件在服务器，处理多在客户端，网络传输压力大。
- 两层 C/S：客户端直接连接数据库服务器。
- 三层 C/S：客户端、应用服务器、数据库服务器分层。
- 分布式数据库：数据分布在多个节点，逻辑上仍可作为整体使用。

## 10. 本章作业速答模板

1. 问 DB/DBMS/DBS：
```text
DB 是数据集合；DBMS 是管理 DB 的软件；DBS 是由 DB、DBMS、应用程序、人员、硬件等组成的完整系统。
```

2. 问数据模型：
```text
数据模型是描述数据、联系、语义和约束的一组概念，主要包括概念数据模型、逻辑数据模型和物理数据模型；其三要素是数据结构、数据操作和完整性规则。
```

3. 问数据独立性：
```text
数据独立性是应用程序不受数据库数据结构变化影响的能力，包括逻辑数据独立性和物理数据独立性，由三级模式两级映像保证。
```

4. 问视图：
```text
视图是从一个或多个基本表导出的虚拟表，通常只保存定义，用于简化查询、隐藏数据和提供外模式。
```
