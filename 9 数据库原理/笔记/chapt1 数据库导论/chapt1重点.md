## 1. 基本概念

| 概念 | 必背解释 |
| --- | --- |
| Data 数据 | 描述事物的符号记录，是数据库中存储和处理的基本对象。 |
| Information 信息 | 对数据加工、解释后形成的有意义内容。数据库通常存储数据，由应用或用户解释成信息。 |
| Database, DB 数据库 | 长期存储在计算机内、有组织、可共享的大量数据集合。 |
| DBMS 数据库管理系统 | 位于用户/应用程序和操作系统之间的数据管理软件，负责定义、组织、存储、维护、查询、更新、安全和恢复。 |
| Database System, DBS 数据库系统 | 通常由数据库、DBMS、数据库应用程序、用户/管理员、硬件和软件环境共同构成。 |
| View 视图 | 从一个或多个基本表导出的虚拟表，通常只保存定义，不实际保存完整数据。 |

易错点：
- 一个数据库系统可以包含多个数据库应用程序，应用程序访问数据库系统中的数据库。
- DB 是数据集合，DBMS 是管理软件，DBS 是包含 DB、DBMS、应用和人员的完整系统。

## 2. 数据库系统的目标

数据库方法相比文件系统的优势：
- 降低数据冗余和不一致。
- 支持数据共享和并发访问。
- 加强完整性、安全性、备份和恢复。
- 提供数据独立性，使应用程序尽量不随数据结构变化而频繁修改。

可能缺点：
- DBMS 复杂、成本高。
- 对硬件、管理人员和备份恢复要求更高。
- 数据集中后，故障影响范围更大。

## 3. 数据模型

数据模型是用于描述数据、数据联系、数据语义和一致性约束的一组概念。

三要素：
1. 数据结构：描述数据对象及对象之间的联系。
2. 数据操作：描述可执行的查询、插入、删除、修改等操作。
3. 完整性规则：描述数据必须满足的约束。

主要层次：
- 概念数据模型：面向现实世界，如 ER 模型。
- 逻辑数据模型：面向 DBMS，如关系模型。
- 物理数据模型：面向存储实现，如文件组织、索引、存取路径。

关系数据模型也由三部分组成：
- 关系数据结构。
- 关系操作。
- 完整性约束。

## 4. 三级模式与两级映像

三级模式：
- 外模式 External Schema：用户或应用看到的局部逻辑结构，可对应视图。
- 概念模式 Conceptual Schema：全体数据的整体逻辑结构，是用户和应用程序都能看到的数据库逻辑结构描述。
- 内模式 Internal Schema：数据的物理存储结构和存取方式。

两级映像：
- 外模式/概念模式映像：保证逻辑数据独立性。
- 概念模式/内模式映像：保证物理数据独立性。

考试句：
```text
数据独立性由数据库系统的三级模式结构及两级映像保证。
```

## 5. 数据独立性

数据独立性指应用程序与数据库中的数据结构相互独立，数据结构变化时应用程序尽量不需要修改。

| 类型 | 面对的变化 | 例子 |
| --- | --- | --- |
| 逻辑数据独立性 | 概念模式变化 | 表增加字段、拆分表、通过视图保持旧程序接口不变。 |
| 物理数据独立性 | 内模式变化 | 增加索引、改变存储位置、调整文件组织方式，SQL 不变。 |

常考选择题：
- “应用程序不受数据结构变化影响”是数据独立性。
- “应用程序独立于数据库结构”是数据独立性的含义。

## 6. 数据库语言

| 类型 | 作用 | 常见命令 |
| --- | --- | --- |
| DDL 数据定义语言 | 定义和修改数据库对象 | `CREATE TABLE`, `ALTER TABLE`, `DROP TABLE`, `CREATE VIEW`, `CREATE INDEX` |
| DML 数据操纵语言 | 查询和更新数据 | `SELECT`, `INSERT`, `UPDATE`, `DELETE` |
| DCL 数据控制语言 | 权限控制 | `GRANT`, `REVOKE` |

易错点：
- “从表中查找若干行”属于查询，通常归入 DML/DQL，不是 DDL。
- 创建表、创建视图、修改表结构属于 DDL。

## 7. 安全性与完整性

| 概念 | 重点 |
| --- | --- |
| Security 安全性 | 防止未授权访问、修改、破坏或泄露。 |
| Integrity 完整性 | 保证数据正确、有效、相容，符合现实世界约束。 |

二者区别：
- 安全性问“谁能访问/修改”。
- 完整性问“数据本身是否合理”。

## 8. 数据库相关人员职责

| 角色 | 职责 |
| --- | --- |
| Data Administrator, DA | 管理组织层面的数据资源，制定数据标准、政策，参与概念/逻辑规划。 |
| Database Administrator, DBA | 数据库日常管理、物理设计、安全、完整性、备份恢复、性能监控。 |
| Logical Database Designer | 识别实体、属性、联系和约束，设计逻辑结构。 |
| Physical Database Designer | 决定逻辑设计如何在存储设备上实现。 |
| Application Developer | 编写数据库应用程序。 |
| End-users | 通过应用程序或查询语言使用数据库。 |

必记陷阱：
```text
DBA 不负责设计 DBMS 软件本身。
```

## 9. 多用户数据库架构

了解即可，但复习时要能区分：
- 集中式数据库：数据和处理集中在一台主机。
- 文件服务器：文件在服务器，处理多在客户端，网络传输压力大。
- 两层 C/S：客户端直接连接数据库服务器。
- 三层 C/S：客户端、应用服务器、数据库服务器分层。
- 分布式数据库：数据分布在多个节点，逻辑上仍可作为整体使用。

```text

```

2. 问数据模型：
```text
数据模型是描述数据、联系、语义和约束的一组概念，主要包括概念数据模型、逻辑数据模型和物理数据模型；其三要素是数据结构、数据操作和完整性规则。
```

3. 问数据独立性：
```text
数据独立性是应用程序不受数据库数据结构变化影响的能力，包括逻辑数据独立性和物理数据独立性，由三级模式两级映像保证。
```

4. 问视图：
```text
视图是从一个或多个基本表导出的虚拟表，通常只保存定义，用于简化查询、隐藏数据和提供外模式。
```
