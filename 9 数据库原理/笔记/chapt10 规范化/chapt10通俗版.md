## 这章到底在讲什么？

规范化就是在讲一件事：

> 一张表太乱、太重复、太容易出错时，应该怎样把它拆成几张更合理的表。

数据库表如果设计得不好，就会出现三类麻烦：

1. 同样的信息重复写很多遍
2. 改一处忘了改另一处，数据不一致
3. 删除一条记录时，把别的重要信息也删没了

所以规范化的核心不是背概念，而是学会判断：

```text
这张表有没有重复？
这个属性到底应该放在哪张表？
这张表要不要继续拆？
```

## 一个最常见的坏表

假设有这样一张学生选课表：

| 学号 | 姓名 | 系别 | 系主任 | 课程号 | 成绩 |
|---|---|---|---|---|---|
| 001 | 张三 | 计算机系 | 王老师 | C01 | 90 |
| 001 | 张三 | 计算机系 | 王老师 | C02 | 85 |
| 002 | 李四 | 计算机系 | 王老师 | C01 | 88 |

看起来很正常，但其实有问题。

张三的姓名、系别重复出现了。计算机系的系主任“王老师”也重复出现了。

如果王老师换成赵老师，就要改很多行。只要漏改一行，就会出现同一个系有两个系主任的矛盾。

这就是规范化要解决的问题。

---

## 三种异常，用人话理解

### 1. 插入异常

想插入一个新系，比如“人工智能系，主任刘老师”。

但是这张表必须有学号、课程号、成绩。现在还没有学生选课，就插不进去。

这叫插入异常。

意思是：

> 我只想存 A 信息，却被迫必须同时存 B 信息。

### 2. 删除异常

如果某个学生退掉最后一门课，我们删除他的选课记录。

结果这个学生的姓名、系别信息也没了。

这叫删除异常。

意思是：

> 我只想删 A 信息，却把 B 信息也删掉了。

### 3. 修改异常

计算机系主任换人了，表里每一行都要改。

如果有一行没改，就数据矛盾。

这叫修改异常。

意思是：

> 同一件事存了很多遍，所以修改时很容易不一致。

## 函数依赖：谁决定谁

函数依赖就是“谁决定谁”。

例如：

```text
学号 -> 姓名
学号 -> 系别
系别 -> 系主任
(学号, 课程号) -> 成绩
```

翻译成人话：

- 知道学号，就能知道这个学生的姓名
- 知道学号，就能知道这个学生属于哪个系
- 知道系别，就能知道这个系的主任
- 知道学号和课程号，才能知道这门课的成绩

注意最后一个：

```text
(学号, 课程号) -> 成绩
```

只知道学号不够，因为一个学生有很多门课。

只知道课程号也不够，因为一门课有很多学生。

必须同时知道“哪个学生”和“哪门课”，才能确定成绩。

---

## 主键：一行数据靠谁唯一确定

主键就是能唯一确定一行数据的属性。

在学生选课表里：

```text
(学号, 课程号)
```

可以作为主键。

因为一个学生选一门课，只有一个成绩。

但是单独的“学号”不能当这张表的主键，因为一个学生可以选多门课。

单独的“课程号”也不能当主键，因为一门课可以被很多学生选。

---

## 1NF：格子里只能放一个值

第一范式最简单：

> 表格的每个格子里，只能放一个值。

错误例子：

| 学号 | 姓名 | 课程 |
|---|---|---|
| 001 | 张三 | 数据库, 高数, 英语 |

这个“课程”格子里放了多个值，不符合 1NF。

改成：

| 学号 | 姓名 | 课程 |
|---|---|---|
| 001 | 张三 | 数据库 |
| 001 | 张三 | 高数 |
| 001 | 张三 | 英语 |

这样每个格子只有一个值，就符合 1NF。

一句话记：

```text
1NF 看格子：一个格子一个值。
```

---

## 2NF：不能只依赖组合主键的一部分

第二范式专门处理“组合主键”的问题。

还是这张表：

```text
选课表(学号, 姓名, 系别, 系主任, 课程号, 成绩)
主键: (学号, 课程号)
```

成绩依赖整个主键：

```text
(学号, 课程号) -> 成绩
```

这很合理。

但是姓名只依赖学号：

```text
学号 -> 姓名
```

系别也只依赖学号：

```text
学号 -> 系别
```

这就有问题了。因为主键是 `(学号, 课程号)`，但姓名和系别只看“学号”就能确定，根本不需要课程号。

这叫部分依赖。

2NF 要求：

> 非主属性必须依赖整个主键，不能只依赖主键的一部分。

所以要把只依赖 `学号`的属性拆到学生表，把只依赖`课程号`的放到选课表：

```text
学生表(学号, 姓名, 系别, 系主任)
选课表(学号, 课程号, 成绩)
```

这样：

- 学生信息放学生表
- 选课成绩放选课表

一句话记：

```text
2NF 看组合主键：非主属性不能只依赖主键的一半。
```

## 3NF：不能通过别人间接依赖主键

现在有：

```text
学生表(学号, 姓名, 系别, 系主任)
```

主键是：

```text
学号
```

看依赖：

```text
学号 -> 姓名
学号 -> 系别
系别 -> 系主任
```

问题出在：

```text
学号 -> 系别 -> 系主任
```

也就是说，学号并不是直接决定系主任，而是先决定系别，再由系别决定系主任。

这叫传递依赖。

3NF 要求：

> 非主属性不能依赖另一个非主属性。

所以继续拆：

```text
学生表(学号, 姓名, 系别)
院系表(系别, 系主任)
```

这样系主任只在院系表里出现一次。

如果系主任换了，只改院系表一行就行。

一句话记：

```text
3NF 看传话：主键不能通过中间属性去决定另一个属性。
```

---

## BCNF：能决定别人的，必须是候选键

BCNF 比 3NF 更严格。

它的意思是：

> 只要一个属性或属性组合能决定别的属性，它自己就必须能唯一确定一整行。

换句话说：

```text
决定因素必须是候选键。
```

比如有函数依赖：

```text
教师 -> 课程
```

如果一个教师只能教一门课，那教师可以决定课程。

但**如果这个表的一行不能被“教师”唯一确定**(一个老师不只教一节课)，也就是说教师不是候选键，那么它决定课程就可能造成冗余和异常。

BCNF 就会要求继续拆。

一句话记：

```text
BCNF 看左边：每个依赖左边都必须是候选键。
```

## 四个范式怎么快速判断？

考试做题可以按这个顺序：

### 第一步：看 1NF

问自己：

```text
有没有一个格子放多个值？
```

如果有，就不满足 1NF。

### 第二步：看 2NF

问自己：

```text
主键是不是组合主键？
有没有属性只依赖组合主键的一部分？
```

如果有，就是部分依赖，不满足 2NF。

### 第三步：看 3NF

问自己：

```text
有没有非主属性决定另一个非主属性？
```

如果有，就是传递依赖，不满足 3NF。

### 第四步：看 BCNF

问自己：

```text
每个函数依赖左边是不是候选键？
```

如果不是，就不满足 BCNF。

## 用一个完整例子串起来

原始表：

```text
选课总表(学号, 姓名, 系别, 系主任, 课程号, 课程名, 成绩)
```

可能的依赖：

```text
学号 -> 姓名, 系别
系别 -> 系主任
课程号 -> 课程名
(学号, 课程号) -> 成绩
```

主键：

```text
(学号, 课程号)
```

### 先到 2NF

因为：

```text
学号 -> 姓名, 系别
课程号 -> 课程名
```

这些都只依赖组合主键的一部分，所以拆：

```text
学生表(学号, 姓名, 系别, 系主任)
课程表(课程号, 课程名)
选课表(学号, 课程号, 成绩)
```

### 再到 3NF

学生表里还有：

```text
学号 -> 系别
系别 -> 系主任
```

所以 `系主任` 传递依赖于 `学号`。

继续拆：

```text
学生表(学号, 姓名, 系别)
院系表(系别, 系主任)
课程表(课程号, 课程名)
选课表(学号, 课程号, 成绩)
```

这样就清楚多了：

- 学生表只管学生
- 院系表只管院系
- 课程表只管课程
- 选课表只管“谁选了哪门课、得了多少分”

## 最好背的总结

```text
1NF：一个格子一个值。
2NF：非主属性不能只依赖组合主键的一部分。
3NF：非主属性不能依赖另一个非主属性。
BCNF：每个决定因素都必须是候选键。
```

再压缩一点：

```text
1NF 防止格子乱。
2NF 防止主键依赖不完整。
3NF 防止属性之间绕来绕去。
BCNF 防止非候选键乱决定别人。
```

做题时不要先背长定义，先找函数依赖：

```text
谁 -> 谁
```

再看左边是不是主键、是不是主键的一部分、是不是非主属性。

规范化题基本就能做出来。
