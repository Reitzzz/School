#### 讲解过程

- DB system 可以包含多个数据库应用程序，应用程序访问数据库。

- 三级模式两级映像是实现数据独立性的关键。
- 概念模式描述数据库的整体逻辑结构。
- DBA 负责数据库管理，不负责设计 DBMS 软件本身。

- 数据模型通常包括数据结构、数据操作和完整性约束。
- 关系数据模型由关系数据结构、关系操作、完整性约束组成。

### 1.2 简答题：What is a data model?

#### 答案

数据模型是用于描述数据、数据之间的联系、数据语义以及一致性约束的一组概念集合。

主要类型：

```text
概念数据模型
逻辑数据模型
物理数据模型
```

#### 讲解过程

概念数据模型面向现实世界建模，例如 E-R 模型；逻辑数据模型面向 DBMS 的组织方式，例如关系模型；物理数据模型关注数据在存储介质上的组织和访问方式。

### 1.3 名词解释

#### 答案

| 名词 | 解释 |
| --- | --- |
| data | 描述事物的符号记录，是数据库中存储的基本对象。 |
| Database | 长期存储在计算机内、有组织、可共享的大量数据集合。 |
| DBMS | 位于用户与操作系统之间的数据管理软件，用于定义、组织、存储、管理和维护数据。 |
| data independence | 应用程序与数据库数据结构之间相互独立，包括逻辑数据独立性和物理数据独立性。 |
| Security | 防止未授权访问、修改或破坏数据库。 |
| Integrity | 保证数据正确、有效、相容。 |
| Views | 从一个或多个基本表导出的虚拟表，只保存定义，不一定实际存储数据。 |
| data administrator | 管理组织数据资源，制定数据标准、政策并参与概念/逻辑设计的人员。 |
| physical database designer | 决定逻辑设计如何在存储设备上物理实现的人员。 |
| application developer | 编写数据库应用程序，为用户提供业务功能的人员。 |
| end-users | 通过应用程序或查询语言使用数据库的最终用户。 |
| DBA | 负责数据库物理设计、日常管理、安全、备份恢复、完整性和性能监控的人员。 |
| logical database designer | 识别实体、属性、联系和约束，完成数据库逻辑结构设计的人员。 |

#### 讲解过程

这些概念可以按“数据对象、管理软件、使用人员、控制目标”来记忆：Database 是数据集合，DBMS 是管理软件，DBA/设计者/开发者/用户是角色，Security 和 Integrity 是数据库管理目标。
