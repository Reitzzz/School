# 实验六 关系规范化答案

> 阅读顺序：每个小问都先给“答案”，再给“讲解过程”。只核对作业时看答案即可；需要复盘推导时再看讲解。

## 1. 酒店预定关系

### 题目

有一酒店的数据库，包含所有注册过的酒店，以及可以用来网上预订的房间的信息。每个顾客通过注册后，可以预定酒店房间，数据库中需要存储所有客户的信息以及预定信息。

根据以上需求，有人得到以下关系，用来描述以上信息：

```text
酒店预定(酒店号码, 酒店名称, 地址, 房间号码, 类型, 房价, 顾客号码, 顾客姓名, 联系电话, 所在城市, 预定日期, 预计入住日期, 预计入住天数, 特殊需求)
```

---

### 1）要求写出所有的 FD，判断主码、候选码

#### 答案

函数依赖：

```text
酒店号码 -> 酒店名称, 地址
(酒店号码, 房间号码) -> 类型, 房价
顾客号码 -> 顾客姓名, 联系电话, 所在城市
(酒店号码, 房间号码, 顾客号码, 预定日期, 预计入住日期) -> 预计入住天数, 特殊需求
```

候选码：

```text
(酒店号码, 房间号码, 顾客号码, 预定日期, 预计入住日期)
```

主码：

```text
(酒店号码, 房间号码, 顾客号码, 预定日期, 预计入住日期)
```

#### 讲解过程

说明：

- 一个酒店号码确定酒店名称和地址。
- 一个酒店中的某个房间由 `(酒店号码, 房间号码)` 确定，并决定房间类型和房价。
- 一个顾客号码确定顾客姓名、联系电话和所在城市。
- 一次预定由酒店、房间、顾客、预定日期和预计入住日期共同确定。

---

### 2）判断第几范式（要求写出所有的 FD）

#### 答案

所有函数依赖：

```text
酒店号码 -> 酒店名称, 地址
(酒店号码, 房间号码) -> 类型, 房价
顾客号码 -> 顾客姓名, 联系电话, 所在城市
(酒店号码, 房间号码, 顾客号码, 预定日期, 预计入住日期) -> 预计入住天数, 特殊需求
```

该关系属于：

```text
1NF
```

#### 讲解过程

原因：

该关系中每个属性都是原子值，所以满足 1NF。

但主码是组合主码：

```text
(酒店号码, 房间号码, 顾客号码, 预定日期, 预计入住日期)
```

存在部分函数依赖：

```text
酒店号码 -> 酒店名称, 地址
(酒店号码, 房间号码) -> 类型, 房价
顾客号码 -> 顾客姓名, 联系电话, 所在城市
```

这些属性只依赖组合主码的一部分，不依赖完整主码，因此不满足 2NF。

---

### 3）将以上关系规范化到 3NF，并判断是否是 BCNF

#### 答案

分解到 3NF：

```text
酒店(酒店号码, 酒店名称, 地址)
房间(酒店号码, 房间号码, 类型, 房价)
顾客(顾客号码, 顾客姓名, 联系电话, 所在城市)
预定(酒店号码, 房间号码, 顾客号码, 预定日期, 预计入住日期, 预计入住天数, 特殊需求)
```

各关系主码：

```text
酒店: 酒店号码
房间: (酒店号码, 房间号码)
顾客: 顾客号码
预定: (酒店号码, 房间号码, 顾客号码, 预定日期, 预计入住日期)
```

是否是 BCNF：

```text
是 BCNF
```

#### 讲解过程

原因：

分解后每个关系中的非平凡函数依赖，其决定因素都是该关系的候选码，所以分解后的关系不仅满足 3NF，也满足 BCNF。

## 2. sale 供应销售关系

### 题目

关系模式：

```text
sale(sno, sname, saddress, zipcode, cno, cname, cadress, Pno, pname, price, qty, sprice)
```

其中 `sno`、`sname`、`saddress`、`zipcode` 是供应商号、姓名、地址和邮政编码，每一个地址的邮政编码是唯一确定的。

`cno`、`cname`、`cadress` 是客户号、客户名称和客户地址。

`Pno`、`pname`、`price` 是商品的编号、名称和价格。

一个供应商可以给多个客户供应多种商品，一种商品也可以由多个供应商供应给多个客户，每个客户可以由多个供应商给她供应多种商品。每个供应商给某个客户供应某种商品有确定的数量 `qty` 和供应价格 `sprice`。

说明：原题文字中出现了 `scity`、`ctel`，但关系模式中没有这两个属性；这里按关系模式中实际给出的属性作答。

---

### 1）分析函数依赖

#### 答案

函数依赖：

```text
sno -> sname, saddress
saddress -> zipcode
cno -> cname, cadress
Pno -> pname, price
(sno, cno, Pno) -> qty, sprice
```

由前两个依赖还可以推出：

```text
sno -> zipcode
```

#### 讲解过程

说明：

- 供应商号决定供应商姓名和地址。
- 题目说明每一个地址唯一确定邮政编码。
- 客户号决定客户名称和客户地址。
- 商品编号决定商品名称和价格。
- 供应商、客户、商品三者共同确定供应数量和供应价格。

---

### 2）确定候选码，判断第几范式

#### 答案

候选码：

```text
(sno, cno, Pno)
```

主码：

```text
(sno, cno, Pno)
```

该关系属于：

```text
1NF
```

#### 讲解过程

原因：

该关系中每个属性都是原子值，所以满足 1NF。

但主码是组合主码：

```text
(sno, cno, Pno)
```

存在部分函数依赖：

```text
sno -> sname, saddress
cno -> cname, cadress
Pno -> pname, price
```

这些属性只依赖组合主码的一部分，因此不满足 2NF。

同时还存在传递依赖：

```text
sno -> saddress -> zipcode
```

---

### 3）将关系分解到 3NF，并判断是否是 BCNF

#### 答案

分解到 3NF：

```text
Supplier(sno, sname, saddress)
AddressZip(saddress, zipcode)
Customer(cno, cname, cadress)
Product(Pno, pname, price)
SaleSupply(sno, cno, Pno, qty, sprice)
```

各关系主码：

```text
Supplier: sno
AddressZip: saddress
Customer: cno
Product: Pno
SaleSupply: (sno, cno, Pno)
```

是否是 BCNF：

```text
是 BCNF
```

#### 讲解过程

原因：

分解后每个关系中的非平凡函数依赖，其决定因素都是该关系的候选码，所以所有分解后的关系均满足 BCNF。
