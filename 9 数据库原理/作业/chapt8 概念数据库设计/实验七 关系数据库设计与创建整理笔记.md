# 实验七 关系数据库库设计与创建整理笔记

给定背景：有一个艺术长廊，展出艺术作品，并记录艺术家、艺术品以及购买或感兴趣的顾客信息。

### 1. 寻找实体、分析联系并画出ER图

#### 题干

1、请你找出以上系统的实体，分析实体之间的联系，画出ER图；

#### 答案

**1. 实体识别：**
* **艺术家 (Artist)**：属性包括 姓名、特长、代表作等。
* **艺术品 (Artwork)**：属性包括 题目、创作时间、类别、艺术品简介等。
* **顾客 (Customer)**：即艺术爱好者，属性可包含 顾客编号、姓名、联系方式等。
* **展出场所 (Location)**：属性可包含 场所编号、场所名称、位置等（如果将“长廊场所”细化的话）。

**2. 联系分析：**
* **创作 (Create)**：艺术家与艺术品之间是 **1:N** 的联系。一位艺术家可以创作多件作品，但每件作品只有唯一的创作者。
* **展出 (Exhibit)**：艺术品与展出场所之间是 **M:N** 的联系。一件艺术品可以多次展出，一个场所可以展出多件艺术品。该联系带有属性：`开始时间`、`结束时间`。
* **购买 (Buy)**：顾客与艺术品之间是 **1:N** 的联系。一件实物艺术品只能卖给一个顾客，但一个顾客可以购买多件艺术品。该联系带有属性：`购买时间`、`价格`。
* **感兴趣/关注 (Interest)**：顾客与艺术家之间是 **M:N** 的联系。一个顾客可以关注多位艺术家，一位艺术家也可以被多名顾客关注。

**3. ER图绘制描述：**
*(注：此处为文字描述ER图结构，实际作业中需在纸上或软件中画图)*
* **矩形**画出上述四个实体。
* **椭圆**画出各自的属性。
* **菱形**画出四种联系，并连线标注比例（1:N 或 M:N）。将“开始时间”、“结束时间”连在“展出”菱形上；将“购买时间”、“价格”作为属性，如果转为逻辑模型则合并至“艺术品”中。

#### 解析

通过抓取业务场景中的名词（艺术家、艺术品、顾客）作为实体，抓取动词（创作、展出、购买、关注）作为联系。重点在于判断 1:N 和 M:N 的业务限制条件。例如实体艺术品一旦售出就不会再卖给第二个人，故为 1:N。

---

### 2. 设计对应关系，描述实体与联系信息

#### 题干

2、请你设计对应关系，描述实体的信息和实体之间联系的信息。

#### 答案

根据实体和联系，设计以下关系（表结构）：

* **艺术家表 (Artist)** (<u>艺术家编号</u>, 姓名, 特长, 代表作)
* **顾客表 (Customer)** (<u>顾客编号</u>, 姓名, 电话, 地址)
* **展出场所表 (Location)** (<u>场所编号</u>, 场所名称)
* **艺术品表 (Artwork)** (<u>艺术品编号</u>, 题目, 创作时间, 类别, 简介, *艺术家编号*, *顾客编号*, 购买时间, 价格)
* **展出记录表 (Exhibition)** (<u>*艺术品编号*, *场所编号*, 开始时间</u>, 结束时间)
* **关注表 (Interest)** (<u>*顾客编号*, *艺术家编号*</u>)

#### 解析

* **1:N 的联系（创作、购买）**：通常不需要建立单独的联系表，而是将 1 端的实体主码（艺术家编号、顾客编号）作为外码加入到 N 端的实体（艺术品）中；并将联系本身的属性（如购买时间、价格）一并加入 N 端实体。
* **M:N 的联系（展出、关注）**：必须建立独立的联系表，由两端实体的主码组合而成，并附带联系自身的属性。

### 3. 主外码分析与关系创建

#### 题干

3、分析关系的主码和外码，并创建ArtGallery数据库，创建各个关系。

#### 答案

**主外码分析：**
* **Artist 表**：主码为 `艺术家编号`。
* **Customer 表**：主码为 `顾客编号`。
* **Location 表**：主码为 `场所编号`。
* **Artwork 表**：主码为 `艺术品编号`。外码1：`艺术家编号` (引用 Artist)；外码2：`顾客编号` (引用 Customer)。
* **Exhibition 表**：主码为 `(艺术品编号, 场所编号, 开始时间)`。外码1：`艺术品编号` (引用 Artwork)；外码2：`场所编号` (引用 Location)。
* **Interest 表**：主码为 `(顾客编号, 艺术家编号)`。外码1：`顾客编号` (引用 Customer)；外码2：`艺术家编号` (引用 Artist)。

**创建数据库与关系的 SQL 语句：**

```sql
CREATE DATABASE ArtGallery;
USE ArtGallery;

CREATE TABLE Artist (
    ArtistID VARCHAR(20) PRIMARY KEY,
    Name VARCHAR(50) NOT NULL,
    Specialty VARCHAR(100),
    Masterpiece VARCHAR(100)
);

CREATE TABLE Customer (
    CustomerID VARCHAR(20) PRIMARY KEY,
    Name VARCHAR(50) NOT NULL,
    Phone VARCHAR(20),
    Address VARCHAR(255)
);

CREATE TABLE Location (
    LocationID VARCHAR(20) PRIMARY KEY,
    LocationName VARCHAR(100)
);

CREATE TABLE Artwork (
    ArtworkID VARCHAR(20) PRIMARY KEY,
    Title VARCHAR(100) NOT NULL,
    CreationTime DATE,
    Category VARCHAR(50),
    Description TEXT,
    ArtistID VARCHAR(20),
    CustomerID VARCHAR(20),
    BuyTime DATE,
    Price DECIMAL(10,2),
    FOREIGN KEY (ArtistID) REFERENCES Artist(ArtistID),
    FOREIGN KEY (CustomerID) REFERENCES Customer(CustomerID)
);

CREATE TABLE Exhibition (
    ArtworkID VARCHAR(20),
    LocationID VARCHAR(20),
    StartDate DATE,
    EndDate DATE,
    PRIMARY KEY (ArtworkID, LocationID, StartDate),
    FOREIGN KEY (ArtworkID) REFERENCES Artwork(ArtworkID),
    FOREIGN KEY (LocationID) REFERENCES Location(LocationID)
);

CREATE TABLE Interest (
    CustomerID VARCHAR(20),
    ArtistID VARCHAR(20),
    PRIMARY KEY (CustomerID, ArtistID),
    FOREIGN KEY (CustomerID) REFERENCES Customer(CustomerID),
    FOREIGN KEY (ArtistID) REFERENCES Artist(ArtistID)
);
```

#### 解析

创建表时，注意先创建没有外键依赖的独立表（Artist, Customer, Location），然后再创建含有外键的表（Artwork, Exhibition, Interest）。
此外，对于“展出记录表”，由于同一件艺术品可能在同一个地点不同时间展出多次，因此建议把时间（`StartDate`）也作为联合主键的一部分。
