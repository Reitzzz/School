## Module 1 数据库导论

### 选择题知识点

| 知识点 | 必背结论 | 常见陷阱 |
|---|---|---|
| 数据与信息 | 数据是信息的符号表示；信息是数据加工解释后的含义 | 数据本身不等于信息 |
| DB / DBMS / DBS | DB 是数据集合；DBMS 是管理软件；DBS 是完整系统 | DBMS 不是数据库本身 |
| DBMS 功能 | 定义、操纵、控制访问、安全、完整性、并发、恢复、数据字典 | 只说“查询软件”太片面 |
| 数据模型三要素 | 数据结构、数据操作、完整性约束 | 容易漏完整性约束 |
| 数据模型层次 | 概念模型、逻辑模型、物理模型 | 概念模型独立于 DBMS |
| 三级模式 | 外模式、概念模式、内模式 | 一个数据库通常只有一个概念模式和一个内模式，可有多个外模式 |
| 两级映像 | 外/概念映像保证逻辑独立性；概念/内映像保证物理独立性 | 不要把两类独立性反过来 |
| 数据独立性 | 应用程序尽量不随数据结构或存储变化而改 | 逻辑独立性通常比物理独立性更难实现 |
| DDL / DML / DCL | DDL 定义结构；DML 查询更新数据；DCL 控制权限 | SELECT 通常属于 DML/DQL，不是 DDL |
| 视图 | 虚拟表，通常只保存定义 | 视图不一定物理存储全部数据 |
| DBA | 管理数据库运行、安全、备份、性能等 | DBA 不负责设计 DBMS 软件本身 |
| 三层 C/S | 客户端、应用服务器、数据库服务器 | 三层结构解决胖客户端和维护困难问题 |

### 对应选择题

1. 数据和信息的关系，正确的是（  ）。  
A. 数据一定就是信息  
B. 信息是数据经过加工和解释后的有意义内容  
C. 信息只能用数字表示  
D. 数据库只存储信息不存储数据  
**答案：B**  
**解析：** 课件强调信息 = 数据 + 数据处理。

2. DBMS 指的是（  ）。  
A. 数据库中的全部数据  
B. 数据库管理系统软件  
C. 数据库应用程序  
D. 数据库管理员  
**答案：B**  
**解析：** DBMS 是位于用户和操作系统之间的数据管理软件。

3. 下列关于 DB、DBMS、DBS 的说法正确的是（  ）。  
A. DBMS 是数据集合  
B. DB 是完整运行环境  
C. DBS 包含 DB、DBMS、应用程序、人员和硬件等  
D. DB 和 DBS 完全相同  
**答案：C**  
**解析：** DBS 是数据库系统整体。

4. 数据模型的三个要素是（  ）。  
A. 数据、程序、用户  
B. 数据结构、数据操作、完整性约束  
C. 外模式、概念模式、内模式  
D. DDL、DML、DCL  
**答案：B**

5. 概念模型主要面向（  ）。  
A. 现实世界和用户需求  
B. 磁盘块和索引结构  
C. 特定 DBMS 的 SQL 语法  
D. 操作系统文件管理  
**答案：A**

6. 在三级模式结构中，用户或应用看到的局部数据视图是（  ）。  
A. 外模式  
B. 概念模式  
C. 内模式  
D. 物理层  
**答案：A**

7. 数据库存储结构、索引、文件组织方式属于（  ）。  
A. 外模式  
B. 概念模式  
C. 内模式  
D. 用户视图  
**答案：C**

8. 外模式/概念模式映像主要保证（  ）。  
A. 物理数据独立性  
B. 逻辑数据独立性  
C. 安全性  
D. 并发性  
**答案：B**

9. 概念模式/内模式映像主要保证（  ）。  
A. 物理数据独立性  
B. 逻辑数据独立性  
C. 数据冗余  
D. 用户界面一致性  
**答案：A**

10. 下列属于 DDL 的是（  ）。  
A. SELECT  
B. INSERT  
C. UPDATE  
D. CREATE TABLE  
**答案：D**

11. 下列关于视图的说法错误的是（  ）。  
A. 视图是虚拟表  
B. 视图可以隐藏敏感数据  
C. 视图一定物理保存所有查询结果  
D. 视图可为不同用户提供不同外模式  
**答案：C**

12. 三层 C/S 架构一般包括（  ）。  
A. 用户界面层、业务逻辑层、数据库层  
B. 外模式、概念模式、内模式  
C. DDL、DML、DCL  
D. 数据、程序、硬盘  
**答案：A**

## Module 2 关系模型和关系代数

### 选择题知识点

| 知识点 | 必背结论 | 常见陷阱 |
|---|---|---|
| 关系术语 | 关系=表；元组=行；属性=列；度=列数；基数=行数 | 域的基数不是关系的基数 |
| 关系性质 | 行列无序、属性名唯一、元组不重复、属性值原子 | SQL 表可能有重复行，但关系模型是集合 |
| NULL | 表示未知或不适用 | 不是 0、空格、空集 |
| 超码 | 能唯一标识元组，可含多余属性 | 超码不一定最小 |
| 候选码 | 最小超码 | 唯一 + 最小 |
| 主码 | 被选中的候选码 | 一个关系可有多个候选码，但通常选一个主码 |
| 外码 | 引用另一个关系或本关系候选码/主码 | 外码通常可重复、可为空 |
| 实体完整性 | 主码属性不能为空 | 不是外码不能为空 |
| 参照完整性 | 外码要么为空，要么引用已有候选码/主码值 | 防止引用不存在对象 |
| 选择 σ | 按条件筛选行 | 改变行数 |
| 投影 π | 选择列并去重 | 可能改变行数 |
| 并交差 | 必须并相容 | 列数和对应域要兼容 |
| 自然连接 | 同名属性等值连接并去掉重复属性 | 同名不同义会误连 |
| 外连接 | 保留未匹配元组，缺失列补 NULL | 左外连接保留左表全部 |
| 除法 | 处理“所有/全部/每个” | 结果属性是左边减右边属性 |

### 对应选择题

1. 关系模型中，关系的“度”指的是（  ）。  
A. 元组个数  
B. 属性个数  
C. 域中值的个数  
D. 关系个数  
**答案：B**

2. 关系模型中，关系的“基数”指的是（  ）。  
A. 行数  
B. 列数  
C. 候选码个数  
D. 外码个数  
**答案：A**

3. 下列属于关系性质的是（  ）。  
A. 行的顺序有意义  
B. 列的顺序有意义  
C. 可以存在完全相同的两个元组  
D. 每个属性值应为原子值  
**答案：D**

4. NULL 表示（  ）。  
A. 数值 0  
B. 空格  
C. 空集  
D. 当前未知或不适用  
**答案：D**

5. 能唯一标识元组但可能包含多余属性的属性集是（  ）。  
A. 超码  
B. 候选码  
C. 主码  
D. 外码  
**答案：A**

6. 候选码的特点是（  ）。  
A. 可以含多余属性  
B. 唯一且最小  
C. 一定是外码  
D. 一定允许为空  
**答案：B**

7. 实体完整性要求（  ）。  
A. 外码不能重复  
B. 主码属性不能为空  
C. 所有属性都不能为 NULL  
D. 外码必须为 NULL  
**答案：B**

8. 参照完整性要求外码值（  ）。  
A. 必须唯一  
B. 必须是主码  
C. 要么为空，要么引用被参照关系中已有候选码/主码值  
D. 不能出现在多个元组中  
**答案：C**

9. 关系代数中，选择运算 σ 的作用是（  ）。  
A. 选列  
B. 选行  
C. 合并两个关系  
D. 删除重复属性  
**答案：B**

10. 投影运算 π 可能减少元组数，是因为（  ）。  
A. 投影会自动排序  
B. 投影会删除不满足条件的行  
C. 投影后重复元组要去除  
D. 投影不能用于多列  
**答案：C**

11. 并、交、差运算要求两个关系（  ）。  
A. 必须有相同名称  
B. 必须并相容  
C. 必须有相同主码  
D. 必须没有外码  
**答案：B**

12. 自然连接的特点是（  ）。  
A. 对所有属性做笛卡尔积  
B. 只保留左表元组  
C. 在公共同名属性上等值连接，并去掉重复属性  
D. 不需要任何公共属性  
**答案：C**

13. 左外连接的结果会（  ）。  
A. 只保留右表全部元组  
B. 保留左表全部元组，右表无匹配处补 NULL  
C. 丢弃所有未匹配元组  
D. 只返回右表属性  
**答案：B**

14. 关系代数除法最适合表达的语义是（  ）。  
A. “至少一个”  
B. “没有”  
C. “所有/全部”  
D. “排序”  
**答案：C**

## Module 3 结构化查询语言 SQL

### 选择题知识点

| 知识点 | 必背结论 | 常见陷阱 |
|---|---|---|
| SQL 特点 | 关系数据库标准语言，非过程化 | 用户说明需要什么，不说明怎么取 |
| SELECT 子句顺序 | SELECT-FROM-WHERE-GROUP BY-HAVING-ORDER BY | 写法顺序不能乱 |
| 逻辑处理顺序 | FROM -> WHERE -> GROUP BY -> HAVING -> SELECT -> ORDER BY | 和书写顺序不完全一样 |
| DISTINCT | 去除重复行 | SQL 默认 ALL，保留重复 |
| WHERE | 分组前筛选行 | 不能直接写聚合函数条件 |
| HAVING | 分组后筛选组 | 通常配合 GROUP BY |
| LIKE | `%` 任意长度，`_` 单个字符 | `= '王%'` 不是模糊查询 |
| NULL 判断 | IS NULL / IS NOT NULL | 不能用 = NULL |
| COUNT | COUNT(*) 数行；COUNT(列) 忽略 NULL | COUNT(DISTINCT 列) 先去重 |
| GROUP BY | SELECT 普通列必须在 GROUP BY 中 | 普通列 + 聚合函数要小心 |
| JOIN | 多表查询必须有连接条件 | N 张表通常至少 N-1 个连接条件 |
| EXISTS | 判断子查询是否有结果 | SELECT 列常写 * 即可 |
| 双重 NOT EXISTS | 表达“所有” | 不存在一个未满足对象 |
| DELETE / DROP | DELETE 删行；DROP 删表结构 | DELETE 不带 WHERE 会删全部行 |
| 视图 | CREATE VIEW；可像表一样查询 | 多表连接/聚合视图通常不可更新 |
| GRANT / REVOKE | 授权/收权 | WITH GRANT OPTION 允许转授权 |

### 对应选择题

1. SQL 的主要特点之一是（  ）。  
A. 必须说明具体访问路径  
B. 非过程化  
C. 只能用于查询，不能更新  
D. 只能嵌入高级语言使用  
**答案：B**

2. SQL 查询语句中，子句书写顺序正确的是（  ）。  
A. SELECT FROM WHERE GROUP BY HAVING ORDER BY  
B. FROM SELECT WHERE ORDER BY GROUP BY  
C. SELECT WHERE FROM GROUP BY  
D. WHERE FROM SELECT HAVING  
**答案：A**

3. SQL 查询逻辑处理顺序通常是（  ）。  
A. SELECT -> FROM -> WHERE  
B. FROM -> WHERE -> GROUP BY -> HAVING -> SELECT -> ORDER BY  
C. ORDER BY -> SELECT -> FROM  
D. GROUP BY -> FROM -> WHERE  
**答案：B**

4. 去除查询结果重复行应使用（  ）。  
A. UNIQUE  
B. DISTINCT  
C. DELETE  
D. GROUP  
**答案：B**

5. 查询姓名以“刘”开头的学生，应使用（  ）。  
A. WHERE Sname = '刘%'  
B. WHERE Sname LIKE '刘%'  
C. WHERE Sname IN '刘%'  
D. WHERE Sname IS '刘%'  
**答案：B**

6. LIKE 中 `_` 表示（  ）。  
A. 任意长度字符串  
B. 单个字符  
C. 空值  
D. 数字字符  
**答案：B**

7. 判断成绩为空值，正确写法是（  ）。  
A. Grade = NULL  
B. Grade <> NULL  
C. Grade IS NULL  
D. Grade LIKE NULL  
**答案：C**

8. `COUNT(*)` 与 `COUNT(Grade)` 的区别是（  ）。  
A. COUNT(*) 忽略空值行  
B. COUNT(Grade) 统计所有行  
C. COUNT(Grade) 只统计 Grade 非空的行  
D. 两者永远相同

9. WHERE 与 HAVING 的区别正确的是（  ）。  
A. WHERE 筛选组，HAVING 筛选行

10. 若 SELECT 中同时出现普通列 `Cno` 和聚合函数 `AVG(Grade)`，通常必须（  ）。  
A. 删除 FROM  
B. 使用 GROUP BY Cno

11. 多表连接查询时，如果没有连接条件，通常会产生（  ）。

12. `EXISTS` 子查询主要判断（  ）。

13. SQL 中表达“选修了所有课程的学生”常用（  ）。

14. `DELETE FROM Student;` 的含义是（  ）。

## Module 5 ER 实体联系模型

### 选择题知识点

| 知识点 | 必背结论 | 常见陷阱 |
|---|---|---|
| ER 模型 | 概念模型，独立于硬件和 DBMS | 不涉及具体物理存储 |
| 实体 | 可区分、需存入数据库的对象 | 实体型用矩形 |
| 属性 | 描述实体或联系的性质 | 属性用椭圆 |
| 联系 | 实体之间的关联 | 联系用菱形 |
| 联系的度 | 一元、二元、三元 | 度=参与实体类型个数 |
| 三元联系 | 一般不等价于三个二元联系 | 拆分会丢失三方绑定语义 |
| 基数/连接类型 | 1:1、1:N、M:N | 表示可能连接数量，不等于必须参与 |
| 参与约束 | 全部参与、部分参与 | Chen 表示法双线=全部参与 |
| 简单/复合属性 | 简单不可分；复合可拆成子属性 | DOB 可拆成年月日 |
| 单值/多值属性 | 多值属性用双椭圆 | 电话、技能常为多值 |
| 派生属性 | 可由其他属性计算，用虚线椭圆 | 年龄可由出生日期计算 |
| 联系属性 | 通常 M:N 联系属性挂在菱形上 | 成绩属于“选课”联系 |
| 弱实体 | 无独立主码，依赖强实体 | 双矩形、识别联系双菱形、部分键虚下划线 |
| 弱实体码 | 强实体主码 + 弱实体部分键 | 弱实体在识别联系中全部参与 |
| 超类/子类 | 子类继承超类共有属性 | 共有属性放超类，特殊属性放子类 |

### 对应选择题

1. ER 模型属于（  ）。  
A. 物理模型  
B. 概念模型  
C. 文件模型  
D. 存储模型  
**答案：B**

2. ER 图中，实体类型通常用（  ）表示。  
A. 矩形  
B. 椭圆  
C. 菱形  
D. 虚线  
**答案：A**

3. ER 图中，联系通常用（  ）表示。  
A. 矩形  
B. 菱形  
C. 双椭圆  
D. 下划线  
**答案：B**

4. 联系的度是指（  ）。  
A. 联系拥有的属性数  
B. 参与该联系的实体类型个数  
C. 联系的元组个数  
D. 联系表的列数  
**答案：B**

5. 三元联系一般（  ）。  
A. 总能等价拆成三个二元联系  
B. 不等价于三个二元联系  
C. 只能连接两个实体  
D. 不能有属性  
**答案：B**

6. Chen 表示法中，全部参与通常用（  ）表示。  
A. 单线  
B. 双线  
C. 虚线椭圆  
D. 双层矩形  
**答案：B**

7. 多值属性在 ER 图中通常用（  ）表示。  
A. 单层椭圆  
B. 双层椭圆  
C. 虚线椭圆  
D. 双层菱形  
**答案：B**

## Module 8 概念数据库设计

### 选择题知识点

| 知识点 | 必背结论 | 常见陷阱 |
|---|---|---|
| 设计方法论 | 使用过程、技术、工具、文档支持设计的结构化方法 | 复杂数据库不能靠随意画图 |
| 三阶段 | 概念设计、逻辑设计、物理设计 | 概念设计独立于所有物理考虑 |
| 概念设计产物 | ER 图、数据字典 | 不是最终磁盘文件组织 |
| 逻辑设计 | 基于特定数据模型，仍独立于具体 DBMS 和物理考虑 | ER 转关系模式属于逻辑设计 |
| 物理设计 | 基表、文件组织、索引、完整性、安全 | 关注辅助存储上的实现 |
| 局部模型 | 针对每个用户视图建立 | 之后合并为全局模型 |
| 实体识别 | 从需求名词/名词短语中找主要对象 | 仅为性质的名词常是属性 |
| 联系识别 | 从动词/动词短语中找业务行为 | 要确定 1:1/1:N/M:N 和参与约束 |
| 属性文档 | 数据类型、长度、别名、NULL、多值、复合、派生、默认值 | 数据字典补充 ER 图细节 |
| 属性域 | 属性允许值、格式和长度 | 用于保证数据完整性 |
| 主码选择 | 属性少、稳定、不易失去唯一性、短、用户易用 | 候选码不能为 NULL |
| 冗余检查 | 检查 1:1、冗余联系、时间维度 | 历史快照类冗余可能必要 |

| 用户复审 | 确认模型真实反映需求 | 设计要反复迭代 |

## Module 9 逻辑数据库设计

### 选择题知识点

| 知识点 | 必背结论 | 常见陷阱 |
|---|---|---|
| 逻辑设计目标 | ER 图 -> 关系表，并检查结构 | 不考虑具体物理存储 |
| 表来源 | ER 图、数据字典、支持文档 | 不凭空建表 |
| 1:N 转换 | 1 端主码复制到 N 端作外码 | 一对多，外键放多端 |
| 递归 1:N | 同一表加入引用自身主码的外码 | 如 ManagerNo -> Employee.EmpNo |
| 1:1 两边强制 | 可合并为一张表，另一个主码作备用键 | 不能用基数判断父子，只看参与约束 |
| 1:1 一边强制 | 可选参与端为父，强制参与端为子；父主码放子表 | 外键最好加 UNIQUE |
| M:N 转换 | 单独建联系表，两边主码作外码，通常合成主键 | 联系属性也进联系表 |
| 复杂联系 | 单独建表，参与实体主码都放入作外码 | 三元联系不要拆成二元联系 |
| 多值属性 | 单独建表，原实体主码 + 多值属性通常为主键 | 防止违反 1NF |
| 弱实体转换 | 弱实体单独成表，主键=父实体主码+部分键 | 父实体主码也是外码 |
| 超类/子类转换 | 常见做法：超类表 + 子类表，子类主码同时为外码 | 查询需连接；只建子类表可能冗余 |
| 规范化验证 | 每张表至少应到 3NF | 表结构不好可能说明 ER 转换有问题 |
| 事务验证 | 事务涉及多表时检查主外键连接路径 | 确保查询/更新能完成 |
| 完整性约束 | required data、domain、entity、referential、general constraints | 外键是否允许 NULL 要明确 |
| 父表删除策略 | NO ACTION、CASCADE、SET NULL、SET DEFAULT、NO CHECK | CASCADE 会自动删子表记录 |

## Module 10 规范化与物理数据库设计补充

### 选择题知识点

| 知识点 | 必背结论 | 常见陷阱 |
|---|---|---|
| 规范化目标 | 消除冗余，减少插入/删除/修改异常 | 规范化基于函数依赖 |
| 更新异常 | 插入异常、删除异常、修改异常 | 删除异常是误删有用信息 |
| 函数依赖 | X 值相同则 Y 值必相同，记 X -> Y | X 是决定因素 |
| 平凡依赖 | Y 是 X 子集 | 规范化重点关注非平凡依赖 |
| 完全依赖 | 依赖整个属性集，不依赖真子集 | 成绩依赖(学号,课程号) |
| 部分依赖 | 依赖组合决定因素的某个真子集 | 2NF 要消除非主属性部分依赖 |
| 传递依赖 | A -> B，B -> C，导致 A -> C | 3NF 要消除传递依赖 |
| 1NF | 属性值原子，无重复组 | 一个格子不能多个值 |
| 2NF | 1NF + 非主属性完全依赖主键 | 单属性主键通常无部分依赖问题 |
| 3NF | 2NF + 消除非主属性传递依赖 | 非主属性不能决定非主属性 |
| BCNF | 每个非平凡函数依赖的决定因素都是候选键 | BCNF 比 3NF 严格 |
| 范式强弱 | BCNF => 3NF => 2NF => 1NF | 反过来不一定成立 |
| 分解原则 | 保留公共属性利于无损连接；相关属性放一起利于保持依赖 | 无公共属性只能笛卡尔积连接 |
| 物理设计 | 辅助存储实现，关注文件组织、索引、性能、安全 | 不同于逻辑设计 |
| 派生数据存储 | 存储 vs 每次计算是权衡 | 存储会带来一致性维护成本 |
| 文件组织 | Heap、Hash、ISAM、B+tree、Clusters | 目标 DBMS 不支持则可省略选择 |
| 索引 | 提高查询，降低更新，耗空间 | 一张表通常只能有主索引或聚簇索引之一 |
| 安全机制 | 系统安全与数据安全 | 系统安全如用户名密码，数据安全如对象权限 |

## 总复习：最容易出单选的 30 个判断句

1. DB 是数据集合，DBMS 是软件，DBS 是完整系统。
2. 数据模型三要素是数据结构、数据操作、完整性约束。
3. 三级模式是外模式、概念模式、内模式。
4. 外/概念映像保证逻辑数据独立性。
5. 概念/内映像保证物理数据独立性。
6. 视图是虚拟表，通常只保存定义。
7. 候选码是唯一且最小的超码。
8. 主码属性不能为空，这是实体完整性。
9. 外码通常可以重复，也通常可以为空。
