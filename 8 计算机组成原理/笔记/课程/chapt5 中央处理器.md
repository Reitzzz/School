## 6.1 中央处理器概述

中央处理器 CPU 是计算机的核心部件，主要由 **运算器** 和 **控制器** 构成。按照冯·诺依曼计算机的思想，程序和数据都存放在存储器中，CPU 通过“取指令、分析指令、执行指令”的循环完成程序控制。

CPU 与系统中其他部件的关系：

- CPU 从主存取出指令和数据。
- CPU 通过总线与主存、I/O 设备交换信息。
- 控制器根据指令生成控制信号，建立对应的数据通路。
- 运算器在控制信号作用下完成算术、逻辑和移位等操作。

### 6.1.1 CPU 的主要功能

| 功能 | 含义 |
| --- | --- |
| 数据加工 | 完成算术运算和逻辑运算，主要由运算器实现。 |
| 程序控制 | 控制指令执行顺序，例如顺序执行、转移、调用和返回。 |
| 操作控制 | 将机器指令翻译为各部件所需的控制信号序列。 |
| 时序控制 | 控制每个微操作在正确的时间开始、持续和结束。 |
| 异常控制 | 响应异常和中断，与操作系统和外设协同工作。 |

### 6.1.2 CPU 中的主要寄存器

| 寄存器 | 名称 | 作用 |
| --- | --- | --- |
| PC / EIP | 程序计数器 | 保存下一条要执行指令的地址。 |
| IR | 指令寄存器 | 保存当前正在执行的指令。 |
| MAR / AR | 存储器地址寄存器 | 保存访问主存的地址。 |
| MDR / DR | 存储器数据寄存器 | 暂存从主存读出或写入主存的数据。 |
| AC | 累加寄存器 | 暂存运算结果或参与运算的数据。 |
| GR | 通用寄存器 | 存放操作数、中间结果或地址。 |
| PSW / EFLAGS | 程序状态字 | 保存条件码、中断允许位、运行状态等信息。 |

### 6.1.3 操作控制器

操作控制器的任务是根据指令和状态信息产生控制信号序列，使数据在各功能部件之间正确流动。

控制器常见实现方式：

- **硬布线控制器**：用组合逻辑、触发器和有限状态机直接生成控制信号，速度快，但设计复杂、修改困难。
- **微程序控制器**：把控制信号序列存入控制存储器，像执行程序一样执行微指令，结构规整、易修改，但速度较慢。

## 6.2 指令周期

### 6.2.1 基本概念

| 概念 | 含义 |
| --- | --- |
| 时钟周期 | 又称节拍脉冲或振荡周期，是 CPU 最基本的时间单位，通常可完成一次简单微操作。 |
| 机器周期 | CPU 完成一个相对完整操作所需的时间，例如一次主存读写周期。 |
| 指令周期 | CPU 从主存取出一条指令并执行完该指令所需的全部时间。 |

一个完整指令周期通常包括：

1. 取指周期：从主存取出指令。
2. 间址周期：如果指令采用间接寻址，需要先取有效地址。
3. 执行周期：完成指令规定的操作。
4. 中断周期：若出现可响应中断或异常，转入中断处理。

常见关系：

$$
1\ \text{条指令周期}=n\ \text{个机器周期}
$$

$$
1\ \text{个机器周期}=k\ \text{个时钟周期}
$$

### 6.2.2 指令执行的一般流程

一般指令执行过程可以概括为：

1. 取指令：根据 PC 访问主存，取出指令，同时更新 PC。
2. 指令译码：分析操作码、寻址方式和寄存器字段。
3. 计算操作数地址：形成有效地址。
4. 取操作数：从寄存器或主存取出操作数。
5. 执行操作：由 ALU 或其他功能部件完成运算、访存或转移。
6. 保存结果：将结果写入寄存器或主存。
7. 检查异常或中断：若有异常或中断请求，则进入异常/中断处理流程。

取指阶段常见 RTL 表示：

$$
MAR \leftarrow PC
$$

$$
MDR \leftarrow M[MAR]
$$

$$
IR \leftarrow MDR
$$

$$
PC \leftarrow PC+1
$$

对于 MIPS 这类按字节编址且指令字长为 32 位的机器，常写为：

$$
PC \leftarrow PC+4
$$

### 6.2.3 定长与变长指令周期

| 类型 | 特点 | 优点 | 缺点 |
| --- | --- | --- | --- |
| 定长指令周期 | 每条指令占用固定机器周期数和固定节拍数。 | 控制简单。 | 简单指令也要等待完整周期，效率低。 |
| 变长指令周期 | 不同指令按需要占用不同机器周期和节拍数。 | 无明显空周期，效率高。 | 控制器设计复杂。 |

单周期 MIPS 属于定长指令周期思想：所有指令在一个时钟周期内完成，$CPI=1$，但时钟周期必须按最慢指令设置。

多周期 MIPS 属于变长指令周期思想：不同指令分多个状态执行，时钟周期更短，部件可分时复用。

## 6.3 数据通路及指令操作流程

### 6.3.1 数据通路的概念

数据通路 DataPath 是指令执行过程中数据在寄存器、ALU、存储器和总线等功能部件之间传送的路径。控制器通过控制信号决定在某个时钟周期内建立哪条数据通路。

数据通路设计要回答三个问题：

- 数据从哪里来？
- 数据经过哪些功能部件？
- 数据最终写到哪里？

寄存器传输可写成：

$$
B \leftarrow Func(A)
$$

其中 $A$ 是源部件，$B$ 是目的部件，$Func$ 表示中间经过的运算或传送功能。

### 6.3.2 数据通路分类

| 类型 | 特点 | 优点 | 缺点 |
| --- | --- | --- | --- |
| 共享通路 / 总线型 | 多个部件共用同一组数据线。 | 结构简单，实现容易，成本低。 | 同一时刻只能传送一路数据，并发性差。 |
| 专用通路 | 不同部件之间设置专用连接。 | 并发度高，性能好。 | 设计复杂，硬件成本高。 |

总线型数据通路常见控制信号：

- 输出控制：$PCout$、$Rout$、$DRout$、$Zout$
- 输入控制：$PCin$、$IRin$、$ARin$、$DRin$
- 存储控制：$Read$、$Write$
- 运算控制：$ADD$、$SUB$

### 6.3.3 数据通路与时钟周期

触发器相关时间参数：

- 建立时间：$T_{setup}$
- 保持时间：$T_{hold}$
- 时钟到输出延迟：$T_{clk\_to\_q}$
- 组合逻辑关键路径延迟：$T_{logic}$

为了保证数据在下一个时钟沿前稳定，时钟周期必须满足：

$$
T_{clk} > T_{clk\_to\_q}+T_{logic}+T_{setup}
$$

为了避免保持时间违例，最短路径应满足：

$$
T_{clk\_to\_q}+T_{shortest\_path}>T_{hold}
$$

例：若 $T_{setup}=5ns$，$T_{hold}=5ns$，$T_{clk\_to\_q}=5ns$，加法器延迟 $T_{adder}=10ns$，则包含一次加法的关键路径时延为：

$$
T_{clk} > 5ns+10ns+5ns=20ns
$$

最大时钟频率近似为：

$$
f_{max}<\frac{1}{20ns}=50MHz
$$

### 6.3.4 单总线 MIPS 典型指令 RTL

| 指令 | 功能 RTL |
| --- | --- |
| `lw rt, imm(rs)` | $R[rt]\leftarrow M[R[rs]+SignExt(imm)]$ |
| `sw rt, imm(rs)` | $M[R[rs]+SignExt(imm)]\leftarrow R[rt]$ |
| `beq rs, rt, imm` | $if\ R[rs]=R[rt],\ PC\leftarrow PC+4+(SignExt(imm)\ll 2)$ |
| `addi rt, rs, imm` | $R[rt]\leftarrow R[rs]+SignExt(imm)$ |
| `add rd, rs, rt` | $R[rd]\leftarrow R[rs]+R[rt]$ |

### 6.3.5 单总线取指周期

单总线结构中，取指令可分为四个节拍：

| 节拍 | 微操作 | 控制信号 |
| --- | --- | --- |
| $T_1$ | $AR\leftarrow PC,\ X\leftarrow PC$ | $PCout,\ ARin,\ Xin$ |
| $T_2$ | $Z\leftarrow X+4$ | $+4$ |
| $T_3$ | $PC\leftarrow Z,\ DR\leftarrow M[AR]$ | $Zout,\ PCin,\ DREin,\ Read$ |
| $T_4$ | $IR\leftarrow DR$ | $DRout,\ IRin$ |

### 6.3.6 单总线 MIPS 指令执行节拍

#### `lw rt, imm(rs)`

| 节拍 | 微操作 |
| --- | --- |
| $T_5$ | $X\leftarrow R[rs]$ |
| $T_6$ | $Z\leftarrow X+SignExt(imm)$ |
| $T_7$ | $AR\leftarrow Z$ |
| $T_8$ | $DR\leftarrow M[AR]$ |
| $T_9$ | $R[rt]\leftarrow DR$ |

#### `sw rt, imm(rs)`

| 节拍 | 微操作 |
| --- | --- |
| $T_5$ | $X\leftarrow R[rs]$ |
| $T_6$ | $Z\leftarrow X+SignExt(imm)$ |
| $T_7$ | $AR\leftarrow Z$ |
| $T_8$ | $DR\leftarrow R[rt]$ |
| $T_9$ | $M[AR]\leftarrow DR$ |

#### `beq rs, rt, imm`

| 节拍 | 微操作 |
| --- | --- |
| $T_5$ | $X\leftarrow R[rs]$ |
| $T_6$ | $PSW.equal\leftarrow (X-R[rt]=0)$ |
| $T_7$ | $X\leftarrow PC$ |
| $T_8$ | $Z\leftarrow X+(SignExt(imm)\ll 2)$ |
| $T_9$ | $if\ PSW.equal,\ PC\leftarrow Z$ |

#### `addi rt, rs, imm`

| 节拍 | 微操作 |
| --- | --- |
| $T_5$ | $X\leftarrow R[rs]$ |
| $T_6$ | $Z\leftarrow X+SignExt(imm)$ |
| $T_7$ | $R[rt]\leftarrow Z$ |

#### `add rd, rs, rt`

| 节拍 | 微操作 |
| --- | --- |
| $T_5$ | $X\leftarrow R[rs]$ |
| $T_6$ | $Z\leftarrow X+R[rt]$ |
| $T_7$ | $R[rd]\leftarrow Z$ |

### 6.3.7 典型例题：`ADD (R1), R0`

题意：字长 16 位，指令 16 位定长，指令功能为：

$$
(R1)\leftarrow (R0)+M[(R1)]
$$

也就是把 $R1$ 指向的存储单元中的内容与 $R0$ 相加，再写回 $R1$ 指向的存储单元。

取指和译码阶段：

| 周期 | 微操作 | 控制信号 |
| --- | --- | --- |
| $C_1$ | $MAR\leftarrow PC$ | $PCout,\ MARin$ |
| $C_2$ | $MDR\leftarrow M[MAR],\ PC\leftarrow PC+1$ | $MemR,\ MDRinE,\ PC+1$ |
| $C_3$ | $IR\leftarrow MDR$ | $MDRout,\ IRin$ |
| $C_4$ | 指令译码 | 无显式数据传送 |

执行阶段：

| 周期 | 微操作 | 控制信号 |
| --- | --- | --- |
| $C_1$ | $MAR\leftarrow R1$ | $R1out,\ MARin$ |
| $C_2$ | $MDR\leftarrow M[MAR]$ | $MemR,\ MDRinE$ |
| $C_3$ | $A\leftarrow MDR$ | $MDRout,\ Ain$ |
| $C_4$ | $AC\leftarrow R0+A$ | $R0out,\ ADD,\ ACin$ |
| $C_5$ | $MDR\leftarrow AC$ | $ACout,\ MDRin$ |
| $C_6$ | $M[MAR]\leftarrow MDR$ | $MDRoutE,\ MemW$ |

## 6.4 时序与控制

### 6.4.1 中央处理器时序

控制信号不能只说明“做什么”，还必须说明“什么时候做”。时序系统用于产生机器周期、节拍电位和节拍脉冲，使控制器能够把微操作限定在具体时间内。

传统三级时序系统包括：

- 状态周期：对应较大的机器周期阶段，例如取指周期、计算周期、执行周期。
- 节拍电位：在一个状态周期内划分的若干时间段。
- 节拍脉冲：触发寄存器写入等动作的短脉冲。

### 6.4.2 控制方式

| 控制方式 | 特点 |
| --- | --- |
| 同步控制 | 由统一时钟控制，各操作按固定或可变节拍安排。 |
| 异步控制 | 无统一时钟，依靠请求和应答机制协调。 |
| 联合控制 | 同步控制和异步控制结合使用。 |

同步控制又可细分为：

- 机器周期数、节拍数都固定：设计最简单，但效率最低。
- 机器周期数固定、节拍数不固定：不同阶段按需要分配节拍。
- 大多数指令机器周期固定，个别复杂指令扩展周期。
- 机器周期数和节拍数都可变：灵活高效，但控制复杂。

### 6.4.3 时序发生器

时序发生器的输入通常是晶振或时钟信号，输出状态周期和节拍信号。定长指令周期时序发生器可以看成一个固定循环的有限状态机；变长指令周期时序发生器则需要根据指令类型和反馈状态决定下一状态。

## 6.5 硬布线控制器

### 6.5.1 基本原理

硬布线控制器是直接由门电路、触发器和组合逻辑构成的控制器。

输入信号包括：

- 指令译码信号。
- 时钟或状态信号。
- 条件码、零标志、中断请求等反馈信号。

输出信号包括：

- 寄存器输入/输出控制信号。
- ALU 运算控制信号。
- 存储器读写控制信号。
- 多路选择器选择信号。

可以概括为：

$$
\text{机器指令字}\rightarrow \text{控制信号序列}
$$

### 6.5.2 传统三级时序硬布线设计步骤

1. 分析数据通路，画出每条指令的指令周期流程图。
2. 明确每个机器周期和节拍中需要产生的控制信号。
3. 设计时序发生器，根据机器周期和节拍划分构建状态图。
4. 找出同一控制信号出现的所有条件。
5. 写出每个控制信号的逻辑表达式。
6. 用组合逻辑电路实现这些表达式。

例如，某个读存储器信号可能在取指周期和 `lw` 执行周期都需要产生：

$$
Read=M_{IF}\cdot T_3+lw\cdot M_{EX}\cdot T_2
$$

某个立即数字段输出信号可能在 `lw`、`sw` 和 `addi` 中出现：

$$
IR(I)out=(lw+sw)\cdot M_{cal}\cdot T_2+addi\cdot M_{EX}\cdot T_2
$$

### 6.5.3 现代时序硬布线控制器

现代控制器通常直接用有限状态机 FSM 表示指令执行过程。状态寄存器保存当前状态，组合逻辑根据当前状态、指令译码和反馈信号生成下一状态和控制信号。

设计步骤：

1. 分析数据通路和指令 RTL。
2. 绘制指令执行状态转换图。
3. 构造状态转换表。
4. 实现有限状态机的组合逻辑。
5. 实现控制器输出逻辑。

传统三级时序与现代时序对比：

| 项目 | 传统三级时序 | 现代时序 |
| --- | --- | --- |
| 同步粒度 | 机器周期同步 | 时钟周期同步 |
| 速度 | 较慢 | 较快 |
| 设计 | 简单 | 复杂 |
| 状态划分 | 取指、计算、执行等固定阶段 | 每个状态对应更具体的指令执行步骤 |

### 6.5.4 硬布线控制器特点

优点：

- 速度快。
- 适合 RISC 等指令规整、控制逻辑相对简单的处理器。
- 适用于 VLSI 实现。

缺点：

- 结构复杂且缺乏规则性。
- 设计、调试困难。
- 指令系统或指令功能修改困难。

## 6.6 微程序控制器

### 6.6.1 基本思想

微程序控制器把控制信号序列存入控制存储器中，用执行微指令的方式产生控制信号。

对应关系：

| 程序层次 | 控制层次 |
| --- | --- |
| 程序由多条机器指令组成 | 微程序由多条微指令组成 |
| 一条机器指令完成一个机器级功能 | 一条微指令产生一个时钟周期内的一组控制信号 |
| 主存保存程序 | 控制存储器保存微程序 |
| PC 指向下一条机器指令 | 微地址寄存器 $\mu AR$ 或 $\mu PC$ 指向下一条微指令 |

基本执行链条：

$$
\text{机器指令执行}\rightarrow \text{微程序执行}\rightarrow \text{微指令执行}\rightarrow \text{控制信号产生}
$$

### 6.6.2 微指令格式

一条微指令通常包括两个部分：

| 字段 | 作用 |
| --- | --- |
| 操作控制字段 | 存放微命令，每一位或每一组编码对应一个或一类控制信号。 |
| 顺序控制字段 | 决定下一条微指令地址，例如顺序执行、条件转移或按操作码转移。 |

直接表示法中，若某控制信号对应一位，则该位为 $1$ 时表示本周期该信号有效。

微指令执行的基本形式：

$$
\mu IR \leftarrow CM[\mu AR]
$$

$$
\mu AR \leftarrow NextAddress
$$

其中 $CM$ 是控制存储器，$\mu IR$ 是微指令寄存器，$\mu AR$ 是微地址寄存器。

### 6.6.3 取指微程序

单总线 CPU 的取指过程可看作 4 条微指令：

| 微指令 | 微操作 |
| --- | --- |
| $\mu I_1$ | $AR\leftarrow PC,\ X\leftarrow PC$ |
| $\mu I_2$ | $Z\leftarrow X+4$ |
| $\mu I_3$ | $PC\leftarrow Z,\ DR\leftarrow M[AR]$ |
| $\mu I_4$ | $IR\leftarrow DR$ |

如果所有机器指令共用取指微程序，则控制存储器中只需要保存一份取指微程序。

### 6.6.4 微命令编码方式

| 编码方式 | 特点 |
| --- | --- |
| 直接表示法 | 每个控制信号占一位，简单直观，速度快，但微指令字长很长。 |
| 编码表示法 | 对互斥微命令分组编码，减少字长，但需要译码，速度下降。 |
| 混合表示法 | 重要或常用控制信号直接表示，互斥信号编码表示。 |

若一组互斥控制信号有 $8$ 个，编码后至少需要：

$$
\lceil \log_2 8\rceil=3\ \text{位}
$$

若一组互斥控制信号有 $100$ 个，编码后至少需要：

$$
\lceil \log_2 100\rceil=7\ \text{位}
$$

### 6.6.5 水平型与垂直型微指令

| 类型 | 特点 | 优点 | 缺点 |
| --- | --- | --- | --- |
| 水平型微指令 | 一条微指令可并行给出多个控制信号。 | 并行能力强，执行速度快，微程序短。 | 微指令字长长，控存容量大。 |
| 垂直型微指令 | 微指令类似机器指令，需要译码产生控制信号。 | 字长短，控存容量小，易理解。 | 并行性差，微程序长，速度慢。 |

水平型微指令更适合追求速度；垂直型微指令更像压缩后的控制程序，但性能较差。

### 6.6.6 微程序控制器特点

优点：

- 结构规整。
- 设计相对简单。
- 易于修改和扩展指令系统。
- 适合 CISC 等复杂指令系统。
- 可写控制存储器可用于修复出厂后的控制逻辑问题。

缺点：

- 需要访问控制存储器，速度慢于硬布线控制器。
- 微指令译码和地址转移逻辑也会带来额外开销。

### 6.6.7 控制存储器容量计算

#### 例题 1

某 CPU 指令系统有 $250$ 条指令，每条指令由 $8$ 个 CPU 周期组成，其中取指微指令为所有指令共享。每条微指令的微操作控制部分为 $80$ 位，求控制 ROM 容量。

由于取指微指令共享，微指令单元数为：

$$
250\times(8-1)+1=1751
$$

下址字段需要表示 $1751$ 个地址，至少需要：

$$
\lceil \log_2 1751\rceil=11\ \text{位}
$$

微指令字长为：

$$
80+11=91\ \text{位}
$$

控制 ROM 容量为：

$$
1751\times 91\ \text{位}
$$

若按存储器地址空间规格取整，也可写为：

$$
2048\times 91\ \text{位}
$$

#### 例题 2

某 CPU 有 $100$ 条指令，每条指令的微程序由 $5$ 条微指令组成，取指微指令共享。系统共有 $1000$ 种不同微操作，并可分成互斥的 $10$ 组，求控制 ROM 容量。

微指令单元数为：

$$
100\times(5-1)+1=401
$$

每组互斥微操作约需：

$$
\lceil \log_2 100\rceil=7\ \text{位}
$$

操作控制字段长度为：

$$
10\times 7=70\ \text{位}
$$

下址字段至少需要：

$$
\lceil \log_2 401\rceil=9\ \text{位}
$$

微指令字长为：

$$
70+9=79\ \text{位}
$$

控制 ROM 容量为：

$$
401\times 79\ \text{位}
$$

若按地址空间规格取整，可写为：

$$
512\times 79\ \text{位}
$$

## 6.7 异常与中断处理

### 6.7.1 异常与中断分类

| 类型 | 来源 | 说明 |
| --- | --- | --- |
| 故障 Fault | 指令执行过程中产生 | 如缺页、段故障、未定义指令、越权指令、除数为零等；有些可恢复。 |
| 自陷 Trap | 程序显式触发 | 如系统调用、条件陷阱，用于从用户态进入内核态。 |
| 终止 Abort | 严重硬件错误 | 如机器校验错、总线错误、双重故障，通常不可恢复。 |
| 外部中断 | 外设或外部事件 | 如 I/O 完成、定时器中断等。 |

### 6.7.2 单重中断处理流程

中断处理的一般流程：

1. 关中断：临时禁止新的中断请求，保证中断响应和保护现场的完整性。
2. 保存断点：保存返回被中断程序的位置。
3. 中断识别：判断中断来源，并找到对应服务程序入口地址。
4. 保护现场：保存通用寄存器、状态字等运行环境。
5. 执行中断服务程序。
6. 恢复现场。
7. 开中断。
8. 中断返回。

中断返回可表示为：

$$
PC\leftarrow EPC
$$

其中 $EPC$ 用来保存异常或中断返回地址。

### 6.7.3 断点保存的注意点

对于已经执行完毕的普通外部中断，断点通常是下一条指令地址：

$$
EPC\leftarrow PC_{next}
$$

对于缺页、段错等由当前指令引发且指令尚未成功执行的异常，断点应是异常指令本身的地址：

$$
EPC\leftarrow PC_{fault}
$$

### 6.7.4 支持中断所需的数据通路扩展

为了支持异常和中断，CPU 通常需要增加：

- $IE$ 寄存器：中断允许标志，用于开关中断。
- $EPC$ 寄存器或栈：保存异常/中断返回地址。
- 中断控制逻辑：识别中断源，生成异常入口地址。
- 异常返回指令：例如 MIPS 中的 `eret`。

## 补充：MIPS 与处理器设计复习

下面内容用于串联 PPT 中 6.2 指令周期、6.3 数据通路、6.5/6.6 控制器实现的综合例题，不作为 PPT 主目录的独立章节。

### A.1 单周期 MIPS：基本特点

单周期 MIPS 中，所有指令都在一个时钟周期完成：

$$
CPI=1
$$

但时钟周期必须覆盖最慢指令的完整数据通路延迟。`lw` 往往是关键路径，因为它通常需要经过取指、读寄存器、ALU 地址计算、数据存储器访问和写回寄存器。

`lw` 的关键路径可概括为：

$$
PC\rightarrow InstructionMemory\rightarrow RegisterFile\rightarrow ALU\rightarrow DataMemory\rightarrow MUX\rightarrow RegisterFile
$$

因此时钟周期近似满足：

$$
T_{clk}>T_{clk\_to\_q}+T_{imem}+T_{regread}+T_{alu}+T_{dmem}+T_{mux}+T_{setup}
$$

### A.2 单周期 MIPS 控制信号

| 控制信号 | 作用 |
| --- | --- |
| RegDst | 选择写寄存器编号来自 `rt` 还是 `rd`。 |
| RegWrite | 控制寄存器堆写使能。 |
| ALUSrc | 选择 ALU 第二操作数来自寄存器还是立即数。 |
| ALUOp | 指定 ALU 操作类型。 |
| MemWrite | 控制数据存储器写入。 |
| MemtoReg | 选择写回数据来自 ALU 结果还是数据存储器。 |
| Branch | 表示当前指令是否为条件分支。 |
| PCSrc | 选择下一条 PC 来自 $PC+4$ 还是分支目标地址。 |

典型指令数据通路：

- R 型指令：$R[rd]\leftarrow R[rs]\ op\ R[rt]$
- `lw`：$R[rt]\leftarrow M[R[rs]+SignExt(imm)]$
- `sw`：$M[R[rs]+SignExt(imm)]\leftarrow R[rt]$
- `beq`：$if\ R[rs]=R[rt],\ PC\leftarrow PC+4+(SignExt(imm)\ll 2)$

### A.3 单周期处理器评价

优点：

- 设计直观，控制器可用纯组合逻辑实现。
- $CPI=1$，从指令数角度看很理想。

缺点：

- 时钟周期由最慢指令决定。
- 很多简单指令被迫使用过长时钟周期。
- 部件难以复用，硬件资源浪费较多。

### A.4 多周期 MIPS

#### A.4.1 基本特点

多周期 MIPS 将一条指令拆分为多个状态周期执行。不同指令使用不同数量的周期，功能部件可以分时复用。

优点：

- 时钟周期更短。
- 存储器、ALU 等部件可以复用。
- 为流水线实现打基础。

缺点：

- $CPI$ 不再固定为 $1$。
- 控制器需要状态机，设计更复杂。

#### A.4.2 多周期数据通路的变化

多周期 MIPS 相比单周期 MIPS 的主要变化：

- 指令存储器和数据存储器可合并为统一存储器，分时使用。
- 功能单元输出端增加锁存寄存器，如 $IR$、$DR$、$A$、$B$、$ALUOut$。
- ALU 可在不同周期中分别用于 $PC+4$、地址计算、分支目标计算和算术逻辑运算。

#### A.4.3 多周期 MIPS 常见状态

| 状态 | 功能 |
| --- | --- |
| $S_0$ | 取指令：$IR\leftarrow M[PC],\ PC\leftarrow PC+4$ |
| $S_1$ | 译码并读寄存器：$A\leftarrow R[rs],\ B\leftarrow R[rt]$ |
| $S_2$ | 地址计算：$ALUOut\leftarrow A+SignExt(imm)$ |
| $S_3$ | 主存访问：用于 `lw` 读数据。 |
| $S_4$ | 结果写回：`lw` 写回寄存器。 |
| $S_5$ | 地址计算：用于 `sw`。 |
| $S_6$ | 主存写入：`sw` 写内存。 |
| $S_7$ | 条件分支：比较并决定是否更新 PC。 |
| $S_8$ | R 型运算。 |
| $S_9$ | R 型结果写回。 |
| $S_{10}$ | I 型运算。 |
| $S_{11}$ | I 型结果写回。 |

多周期实现的关键是：同一条数据通路在不同状态中完成不同任务，控制信号由状态机按状态给出。

### A.5 处理器设计思路

处理器设计通常按以下步骤进行：

1. 选定指令系统。
2. 用 RTL 描述每条指令的功能。
3. 根据指令功能设计功能部件和数据通路。
4. 确定所有控制点和控制信号。
5. 分析所有指令的控制信号序列。
6. 选择控制器实现方式。
7. 若采用微程序控制，设计微指令、微程序和微地址转移逻辑。
8. 若采用硬布线控制，生成控制信号逻辑表达式并实现有限状态机。

硬件设计四原则：

- 简单性来自规则性：指令越规整，硬件越容易实现。
- 越小越快：面积小、传播路径短、门延迟少。
- 加快经常性事件：常用操作应优化。
- 好的设计需要折衷：速度、面积、功耗、复杂度之间需要平衡。

### A.6 本章易考点

1. 区分时钟周期、机器周期和指令周期。
2. 会写常见取指、访存、运算和分支指令的 RTL。
3. 理解数据通路是由控制信号在特定时序下建立的。
4. 掌握单总线结构中 `lw`、`sw`、`beq`、`addi`、`add` 的节拍流程。
5. 会根据关键路径计算时钟周期和最大频率。
6. 会写硬布线控制信号逻辑表达式。
7. 区分硬布线控制器和微程序控制器的优缺点。
8. 会计算控制存储器容量，尤其注意“取指微程序共享”。
9. 区分 Fault、Trap、Abort 和外部中断。
10. 理解中断返回地址保存到 $EPC$，并能判断保存下一条指令地址还是故障指令地址。
11. 单周期 MIPS 的 $CPI=1$，但时钟周期由最慢指令决定。
12. 多周期 MIPS 通过状态机分步执行指令，缩短时钟周期并复用部件。
