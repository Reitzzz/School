## 3.1 存储体系概述

<a id="sec-3-1-1"></a>
### 3.1.1 存储器的基本概念

- **二进制位 bit（位又称比特）**：构成存储信息的最小单位
- **字节 Byte**：数据存储的基本单位，$1B = 8bit$
- **存储单元**：存放一个存储字的基本单位
- **单元地址**：内存单元的唯一标识
- **基本操作**：读操作、写操作

<a id="sec-3-1-2"></a>
### 3.1.2 存储器分类

#### 1. 按所处位置分类

| 类型 | 又称 | 作用 | 特点 |
|------|------|------|------|
| **主存储器** | 内存 | 存放当前正在执行的程序和数据 | **CPU 可直接访问，速度较快，容量较小，价格较高** |
| **辅助存储器** | 外存 | 长期保存暂不用的程序和数据 | **CPU 通常不能直接访问，容量大，速度慢，价格低** |
| **高速缓冲存储器** | Cache | 缓解 CPU 与主存速度差距 | **容量小，速度快，价格高，通常由 SRAM 构成** |

#### 2. 主存储器分类

```text
主存储器
├── RAM：随机读写存储器，易失性
│   ├── SRAM：静态 RAM，速度快，价格高，常作 Cache
│   └── DRAM：动态 RAM，容量大，价格低，常作主存
└── ROM：只读存储器，非易失性
    ├── MROM
    ├── PROM
    ├── EPROM
    ├── E²PROM
    └── Flash ROM
```

#### 3. 辅助存储器分类

- **磁带存储器**：顺序访问，容量大，速度慢
- **磁盘存储器**：直接访问，常见如硬盘
- **光盘存储器**：容量较大，速度较慢，价格低
- **固态存储器**：如 U 盘、SSD，常基于 Flash

<a id="sec-3-1-3"></a>
### 3.1.3 主存储器的性能指标

#### 1. 存储容量

存储容量表示存储器能够容纳的二进制信息量。

$$容量 = 存储单元个数 \times 每个存储单元的位数$$

**存储容量的单位是字节（B，Byte）或位（b，Bit）。**

常用单位：

| 单位 | 换算 |
|------|------|
| $1K$ | $2^{10}$ |
| $1M$ | $2^{20}$ |
| $1G$ | $2^{30}$ |
| $1T$ | $2^{40}$ |

> **例**：某存储芯片为 `1K × 4 位`  
> 表示有 $1024$ 个存储单元，每个单元 4 位，总容量为：  
> $$1024 \times 4 = 4096bit = 512B$$

#### 2. 存储速度

| 指标 | 符号 | 含义 |
|------|------|------|
| **存取时间** | $T_A$ | 启动一次存储操作到完成该操作所需的全部时间 |
| **存储周期** | $T_M$ | 连续两次独立存储操作之间所需的最小时间间隔 |
| **存储带宽** | $BW$ | 单位时间内存储器所能传输的信息量 |

通常：

$$T_M \ge T_A$$

存储器带宽：

$$BW = \frac{W}{T_M}$$

其中 $W$ 为一次读/写的数据位数，$T_M$ 为存储周期。

#### 3. 位价

$$位价 = \frac{总价格C}{总容量S}$$

存储器的三大指标相互制约：

| 指标 | 一般规律 |
|------|----------|
| 速度 | 越快越贵 |
| 容量 | 越大越慢、越便宜 |
| 价格 | 每位价格越低，通常速度越慢 |

<a id="sec-3-1-4"></a>
### 3.1.4 存储器层次结构

#### 1. 层次结构

```text
寄存器
  ↓ 速度快，容量小，价格高
Cache
  ↓
主存储器
  ↓
辅助存储器
  ↓ 速度慢，容量大，价格低
```

也可以从本章重点看成三级结构：

```text
Cache  ←→  主存  ←→  辅存
```

- **Cache - 主存层次**：解决 CPU 与主存之间的速度矛盾
- **主存 - 辅存层次**：解决主存容量不足的问题，形成虚拟存储器

#### 2. 局部性原理

层次结构能够生效的理论基础是**局部性原理**。

| 类型 | 含义 | 程序体现 |
|------|------|----------|
| **时间局部性** | 现在访问的信息，将来很可能再次访问 | 循环结构 |
| **空间局部性** | 现在访问的信息附近的信息，将来很可能被访问 | 顺序结构、数组连续访问 |

> **通俗理解**：  
> CPU 像大厨，主存像仓库，Cache 像手边的小冰箱。大厨刚用过或马上可能用到的食材提前放进小冰箱，拿起来就快。

#### 3. 存储层次的管理方式

| 层次 | 信息块大小 | 管理者 | 对用户是否透明 |
|------|------------|--------|----------------|
| Cache - 主存 | 块，一般几十字节 | Cache 控制器硬件 | 透明 |
| 主存 - 辅存 | 页、段，通常更大 | 操作系统 + 硬件 | 透明 |

<a id="sec-3-1-5"></a>
### 3.1.5 主存中的数据存放

#### 1. 机器字长与存储字长

| 概念 | 含义 |
|------|------|
| **机器字长** | CPU **一次能够处理**的**二进制数据位数** |
| **存储字长** | 主存的**一个存储单元所包含的二进制位** |
| **数据字长** | 目前大多数计算机的主存按字节编址，存储字长也不断加大，**如16位字长、32位字长和64位字长** |

现代计算机通常**按字节（Byte）编址**：

- **字节地址**：最小寻址单位，1 个地址对应 1 字节
- **半字地址**：2 个相邻字节组成一个半字
- **字地址**：4 个相邻字节组成一个字，常见为 32 位字

> **通俗理解：按字节编址与字长的关系**  
> 现代计算机设计中包含了一个**折中智慧**：  
> - **为了精细控制（找数据）**：保留了“按字节编址”。内存就像一栋大楼，给每 1 个字节（8个位）分配一个独立的门牌号 **（字节地址）**。想找任何一个字节，都有精确的门牌号可以找到它。  
> - **为了提高速度（搬数据）**：加大了“字长”。CPU 就像一个强壮的快递员，虽然每个小房间（字节）都有门牌号，但他每次去内存读写时，为了效率，会一次性抓取 32 位（4个字节）或 64 位（8个字节）的一大把数据。  
> 
> **总结**：**“字节”** 是找东西的最小单位（门牌号）；**“字长”** 是 CPU 搬运东西的一口吞吐量。它俩不冲突，字长变大纯粹是为了让电脑跑得更快。

#### 2. 大端方式与小端方式

假设一个 32 位数据：

```text
0x12345678
```

| 存放方式 | 低地址存放 | 高地址存放 | 特点 |
|----------|------------|------------|------|
| **大端方式** | 高位字节 `12` | 低位字节 `78` | 符合人类从高位到低位的阅读习惯 |
| **小端方式** | 低位字节 `78` | 高位字节 `12` | 符合计算机低位先运算、进位传播的逻辑 |

> **记忆**：  
> 大端：大头在前，高位放低地址。  
> 小端：小头在前，低位放低地址。

#### 3. 边界对齐

| 存放方式 | 规则 | 优点 | 缺点 |
|----------|------|------|------|
| **对齐存放** | 数据起始地址必须是其自身字节数的整数倍 | 访问速度快 | 可能浪费空间 |
| **不对齐存放** | 数据紧密连续存放 | 节省空间 | 访问可能跨多个存储周期，速度慢 |

![边界对齐](https://bsyimg.luoca.net/imgtc/20260616/2d9fac4f20b6eeb58d6dd897f8a58a84.webp)

> **例**：32 位系统中  
> - `short` 占 2 字节，通常按 2 字节对齐  
> - `int` 占 4 字节，通常按 4 字节对齐  
> - `double` 占 8 字节，通常按 8 字节对齐

## 3.2 主存储器

<a id="sec-3-2-0"></a>
### 3.2.0 主存的基本结构

主存特点：

- CPU 可以直接访问
- 一般由半导体存储器构成
- **随机存取**：访问任意地址所需时间基本相同
- 相比辅存：速度快、容量小、价格高

主存储器一般由以下部分组成：

```text
地址总线 AB → MAR → 地址译码器 → 存储矩阵
数据总线 DB ↔ MDR ↔ I/O 电路 ↔ 存储矩阵
控制信号 R/W、CS、WE → 控制电路
```

| 部件 | 作用 |
|------|------|
| **MAR** | 存储器地址寄存器，保存要访问的地址 |
| **MDR** | 存储器数据寄存器，暂存读出或写入的数据 |
| **地址译码器** | 将二进制地址转换成具体的行/列选择信号 |
| **存储矩阵** | 真正保存 0/1 信息的电路阵列 |
| **读写控制电路** | 根据读/写信号控制数据流向 |
| **CS** | 片选信号，决定芯片是否参与本次操作 |
| **WE** | 写使能信号，决定是否执行写操作 |

<a id="sec-3-2-1"></a>
### 3.2.1 随机存取存储器 RAM

RAM 可以随机读写，但断电后信息丢失，因此具有**易失性**。

#### 1. SRAM：静态随机存取存储器

**定义拆解：**
- **静态 (Static)**：只要不断电，存入的信息就能长期稳定保持，**不需要定期刷新**。
- **随机存取 (Random Access)**：CPU 可以随时对任意指定地址的存储单元进行读写，且所需时间**与该单元的物理位置无关**（指哪打哪）。

##### （1）SRAM 存储位元

SRAM 使用**双稳态触发器**保存 0 和 1。

典型结构为六管 MOS 静态存储单元：

| 管子 | 作用 |
|------|------|
| $T_1, T_2$ | 工作管，交叉耦合，形成触发器，保存 0/1 |
| $T_3, T_4$ | 负载管，补充电荷 |
| $T_5 \sim T_8$ | 门控管，起开关作用，控制读写 |

- “1”状态：一个管导通，另一个截止
- “0”状态：与“1”相反
- 只要不断电，信息就能稳定保持
- 不需要刷新

> **通俗理解**：  
> SRAM 像一个带锁的开关，只要供电，开关状态就一直保持，不需要反复检查。

##### （2）SRAM 存储矩阵

多个位存储体可以排成二维矩阵，例如：

```text
64 × 64 = 4096 位 = 4K bit
```

读写过程：

1. 行地址译码器选中某一行
2. 该行所有位存储体同时送出数据到行缓冲
3. 列地址译码器再选择需要的列
4. 多个矩阵并联时，可以一次输出多位数据

> **通俗解释：**  
> 想象去一个超级大的 **储物柜墙（矩阵）** 拿东西：  
> 1. **选行：** 先找你要的那**一排**柜子（选中某一行）。  
> 2. **送缓冲：** 把这一整排柜子的东西全部先拿出来，放到面前的长桌上（送出数据到行缓冲）。  
> 3. **选列：** 在长桌上的这一排东西里，挑出你真正需要的那**一个**（列译码器选择需要的列）。  
> 4. **多个矩阵并联：** 如果你需要一次拿 8 个东西，就雇 8 个人在 8 面一模一样的储物柜墙前同时操作，每人给你 1 个东西，拼起来就是完整的 8 位数据（一次输出多位数据）。

> **例**：若 4 个 `64×64` 矩阵共享同一组地址线，每个矩阵输出 1 位，则一次可输出 4 位，构成 `4K × 4 位` 存储体。

##### （3）单译码与双译码

| 译码方式 | 原理 | 优缺点 |
|----------|------|--------|
| **单译码方式** | $n$ 位地址直接译码成 $2^n$ 根选择线 | 简单，但容量大时译码线过多 |
| **双译码方式** | 地址分成行地址和列地址，分别译码 | 大幅减少译码线数量，适合大容量芯片 |

单译码方式译码线数量：

$$2^n$$

双译码方式若行列各占一半地址线，译码线数量约为：

$$2 \times 2^{n/2}$$

##### （4）2114 SRAM 芯片

典型 2114 SRAM 芯片规格：

```text
1K × 4 位
```

| 引脚类型 | 数量/含义 |
|----------|-----------|
| 地址线 | $A_9 \sim A_0$，共 10 根，可寻址 $2^{10}=1K$ 个单元 |
| 数据线 | $D_3 \sim D_0$，共 4 根，双向数据线 |
| 片选线 | CS，选中芯片 |
| 写使能 | WE，控制读/写 |
| 电源/地 | VCC、GND |

##### （5）SRAM 的读写过程

**读操作**：

1. CPU 送出有效地址到地址总线，进入 MAR
2. 片选信号 CS 有效，地址译码器选中单元
3. WE 置为读状态，选中单元内容送入 MDR，再送数据总线
4. 数据稳定后发 READY，读操作完成

**写操作**：

1. CPU 送出有效地址，同时将待写数据送到数据总线
2. 地址进入 MAR，数据进入 MDR
3. CS 有效，WE 置为写状态
4. MDR 中数据写入指定单元
5. 撤销控制信号，发 READY，写操作完成

##### （6）SRAM 特点

| 项目 | SRAM |
|------|------|
| 存储方式 | 双稳态触发器 |
| 是否需要刷新 | 不需要 |
| 速度 | 快 |
| 集成度 | 低 |
| 容量 | 小 |
| 价格 | 高 |
| 典型用途 | Cache |

#### 2. DRAM：动态随机存取存储器

**定义拆解：**
- **动态 (Dynamic)**：利用电容存储电荷来保存信息，因为电容会漏电，所以**必须周期性地进行刷新**（充电）才能保持数据不丢失。
- **随机存取 (Random Access)**：CPU 可以随时对任意指定地址的存储单元进行读写，且所需时间**与该单元的物理位置无关**（指哪打哪）。

##### （1）DRAM 存储位元

DRAM 使用 MOS 管的**极间电容**保存信息。

| 状态 | 含义 |
|------|------|
| “1” | 电容上有电荷 |
| “0” | 电容上无电荷 |

> **通俗理解**：  
> DRAM 像一个很小的水桶。水桶有水表示 1，没水表示 0。问题是水桶会漏水，所以必须定期补水。

##### （2）再生与刷新

DRAM 有两个重要问题：

| 问题 | 原因 | 解决方式 |
|------|------|----------|
| **再生** | 读出过程可能破坏原信息 | **读出后重写** |
| **刷新** | 电容会漏电，信息会随时间丢失 | **周期性重写**所有单元 |

- **再生**：读出后立即恢复原数据
- **刷新**：即使不读，也要定期重写

##### （3）刷新周期

**刷新周期**：对整个 DRAM 全部刷新一遍所允许的最大时间。

常见刷新周期：

```text
2ms、4ms、8ms
```

教材中常以 $2ms$ 为例。

刷新一般**按行刷新**，刷新一行的时间约等于一个存储周期 $T_M$。

##### （4）DRAM 的三种刷新方式

###### ① 集中式刷新

做法：在一个刷新周期的**最后**，集中刷新**所有行**。

在集中式刷新中，这段 2ms 的时间是被切成两段来用的： <br>
- 第 1 段：**正常营业时间（取/存）** ：这段时间用来给 CPU 正常读写数据。 **它的长度是：2ms - 64μs = 1936μs**。<br>
- 第 2 段：**关门盘点时间（死时间/集中刷新）** ：眼看 2ms 的大限马上就要到了，内存赶紧“关门谢客”（CPU 此时无法读写内存），用最后这 64μs，一口气把 128 行全部刷新一遍。<br>

> **例**：16K×1 位 DRAM，内部为 $128×128$ 矩阵，存取周期 $T_M=500ns$，刷新周期为 $2ms$。  
> 刷新 128 行所需时间为：  
> $$128 \times 500ns = 64000ns = 64\mu s$$

| 优点 | 缺点 |
|------|------|
| 正常访存阶段速度不变 | 集中刷新期间不能访存，出现较长“死时间” |

###### ② 分散式刷新

做法：**在每一个存取周期内，都强制固定拿出一半的时间来刷新一行。**
**（即：每个存取周期 = 访存子周期 + 刷新子周期）**



若原存取周期为 $500ns$，则分散式刷新下周期变为：

$$500ns + 500ns = 1\mu s$$

| 优点 | 缺点 |
|------|------|
| 没有长时间死区 | 每次访存都带刷新，速度约下降一半，**刷新次数过多** |

###### ③ 异步式刷新

做法：在刷新周期内，把刷新操作**均匀分散**。

> **例**：$2ms$ 内刷新 128 行，则每隔：  
> $$\frac{2ms}{128} = 15.625\mu s$$  
> 刷新一行。

| 优点 | 说明 |
|------|------|
| 兼顾集中式与分散式 | 没有长死区，也不会过度刷新，是常用方式 |

##### （5）DRAM 特点

| 项目 | DRAM |
|------|------|
| 存储方式 | 电容电荷 |
| 是否需要刷新 | 需要 |
| 速度 | 慢于 SRAM |
| 集成度 | 高 |
| 容量 | 大 |
| 价格 | 低 |
| 典型用途 | 主存、内存条 |

---

#### 3. SRAM 与 DRAM 对比

| 比较内容 | SRAM | DRAM |
|----------|------|------|
| 存储 0/1 的方式 | 双稳态触发器 | 电容充放电 |
| 电源不断时 | 信息稳定 | 信息也会逐渐丢失 |
| 刷新 | 不需要 | 需要 |
| 速度 | 快 | 慢 |
| 集成度 | 低 | 高 |
| 容量 | 小 | 大 |
| 价格 | 高 | 低 |
| 典型用途 | Cache | 主存 |

> **记忆**：  
> SRAM：Static，静态，快、贵、小、不刷新。  
> DRAM：Dynamic，动态，慢、便宜、大、要刷新。

<a id="sec-3-2-2"></a>
### 3.2.2 只读存储器 ROM

ROM 具有**非易失性**，断电后信息仍能保存，常用于保存固化程序，如 BIOS、固件等。

#### 1. ROM 基本结构

```text
地址输入 → 地址译码器 → 存储矩阵 → 读出放大器 → 数据输出
```

| 部件 | 作用 |
|------|------|
| 地址输入 | 给出要读取的位置 |
| 地址译码器 | 定位具体存储单元 |
| 存储矩阵 | 保存固定或可重写的数据 |
| 读出放大器 | 放大微弱信号并输出 |

#### 2. ROM 分类

| 类型 | 中文名 | 类别 | 擦除方式 | 能否单字节修改 | 写机制 | 特点 | 通俗比喻 |
|------|--------|------|----------|----------------|--------|------|----------|
| **MROM** | 掩膜 ROM | 只读 | 不允许 | 否 | 掩膜位写 | 出厂时写死，适合大批量生产 | **印刷书本，买到啥是啥** |
| **PROM** | 可编程 ROM | 写一次读多次 | 不允许 | 否 | 电信号 | 用户一次性烧录 | **只能写一次的日记本** |
| **EPROM** | 紫外线可擦除 ROM | 写多次读多次 | 紫外线擦除，脱机改写<br>**(需拔下芯片放紫外灯下照射)** | 否 | 电信号 | 需紫外线擦除，脱机改写 | **需晒紫外线才能擦掉的本子** |
| **E²PROM** | 电可擦除 ROM | 写多次读多次 | 电擦除，在线改写<br>**(无需拔下芯片，直接加电信号擦除)** | 能 | 电信号 | 灵活，但成本较高 | **可逐字修改的电子笔记本** |
| **Flash ROM** | 闪存 | 写多次读多次 | 电擦除，在线改写<br>**(无需拔下芯片，直接加电信号擦除)** | 否 | 电信号 | 容量大，成本低，常用于 U 盘、SSD、BIOS | **可以按页撕掉重写的活页本** |

<a id="sec-3-3"></a>
## 3.3 主存储器的扩展

单片存储芯片的容量和字长通常有限，因此需要通过多个芯片组合成所需容量的主存。

<a id="sec-3-3-1"></a>
### 3.3.1 存储芯片容量表示

存储芯片常写成：

```text
字数 × 位数
```

例如：

```text
16K × 8 位
```

表示有 $16K$ 个地址单元，每个单元 8 位。

---

<a id="sec-3-3-2"></a>
### 3.3.2 位扩展

#### 1. 作用

**位扩展**通过**多片芯片**构成**规定字长模块**增加存储器的**字长**，即**每个地址能读写更多位**。

**通俗理解**：多个仓库（**多片存储芯片**）共同服务同一个订单（**接收相同的地址信号**）。下单一次时，会同时从多个仓库取货（**各芯片并行工作**），并拼成一个更大的包裹（**各芯片的数据位合并，拼成更宽的数据总线**），因此每个地址能存放的数据变多了（**字长增加**）。

```text
短字长芯片 → 规定字长存储器
```

各芯片**并行工作**。

#### 2. 连接原则

- 各芯片地址线对应并联
- 读写控制线 WE 对应并联
- 片选信号 CS 对应并联
- 各芯片数据线分别作为总数据线的不同位

> **例**：用 `16K×8` SRAM 芯片组成 `16K×16` 存储器。  
> 字数不变，字长从 8 位扩展到 16 位，需要：  
> $$\frac{16}{8}=2\text{ 片}$$  
> 两片地址线、CS、WE 共用；一片接 $D_7\sim D_0$，另一片接 $D_{15}\sim D_8$。

![字扩展](https://bsyimg.luoca.net/imgtc/20260616/662ba25b41837d222d79accadd1ab07e.webp)
---

<a id="sec-3-3-3"></a>
### 3.3.3 字扩展

#### 1. 作用

**字扩展**用于增加存储器的**字数**，即扩大地址空间。

**通俗理解**：新增多个仓库（**多片存储芯片**）来存放更多订单（**扩大地址空间**）。每次仍然只从一个仓库取货（**通过片选信号 CS，每次只选中并启动其中一片芯片**），包裹大小不变（**各芯片共用数据总线，单次读写的字长不变**），但可下单的地址变多了（**通过高位地址区分不同的芯片**），因此存储容量增大了（**字数增加**）。

```text
小字数芯片 → 大字数存储器
```

同一时刻通常只有一片芯片被选中工作。

#### 2. 连接原则

- 各芯片数据线对应并联
- 各芯片低位地址线对应并联
- 读写控制线 WE 对应并联
- 高位地址线经过译码器产生不同片选信号 CS

> **例**：用 `16K×16` SRAM 芯片组成 `128K×16` 存储器。  
> 字长相同，字数从 16K 扩展到 128K，需要：  
> $$\frac{128K}{16K}=8\text{ 片}$$  
> 需要 3 根高位地址线经 $3\to8$ 译码器产生 8 个片选信号。

---

<a id="sec-3-3-4"></a>
### 3.3.4 字位扩展

#### 1. 作用

**字位扩展**同时扩大字数和字长。

#### 2. 方法

通常：

```text
先位扩展，再字扩展
```

> **例**：用 `128K×16` 模块组成 `1M×32` 存储器。  
> 字数扩展倍数：  
> $$\frac{1M}{128K}=8$$  
> 字长扩展倍数：  
> $$\frac{32}{16}=2$$  
> 所需模块总数：  
> $$8 \times 2 = 16\text{ 块}$$

---

<a id="sec-3-3-5"></a>
### 3.3.5 主存与 CPU 的连接

连接主存时一般遵循以下步骤：

1. 根据 CPU 地址线数目，确定 CPU 可访问的地址范围
2. 根据目标容量，确定芯片数量和扩展方式
3. CPU 低位地址线直接连接各芯片地址线
4. CPU 高位地址线通过译码器产生片选信号
5. 数据线、读写控制线、访存请求信号等按要求连接

#### 地址分配核心思想

```text
低位地址：选芯片内部单元
高位地址：选哪一片芯片
```

> **易错点**：  
> 字扩展时，不是所有芯片同时工作，而是通过高位地址译码，只选中其中一片或一组芯片。

---

<a id="sec-3-4"></a>
## 3.4 高速存储器：多体交叉存储器

<a id="sec-3-4-0"></a>
### 3.4.0 背景

为了弥补 CPU 与主存速度差距，可以从存储器角度采用三种办法：

1. 使用更高速的存储芯片，缩短存取周期
2. 扩展存储字长，一次读出多个字
3. 使用多体交叉存储器或 Cache，提高平均访问速度

---

<a id="sec-3-4-1"></a>
### 3.4.1 多模块顺序存储器

#### 1. 顺序方式

把地址空间按连续区间分配到不同模块中：

```text
M0：低地址区域
M1：次低地址区域
M2：更高地址区域
M3：最高地址区域
```

![顺序](https://bsyimg.luoca.net/imgtc/20260617/8f4f0a63272d8452b208025dd57e6da8.webp)

| 特点 | 说明 |
|------|------|
| 容量扩展方便 | 可通过增加模块扩大容量 |
| 性能提升不明显 | 连续访问时可能集中在同一模块，无法并行 |
| 便于故障隔离 | 某模块问题较容易定位 |

> **通俗理解**：  
> 顺序存储像把仓库分成几个房间，先装满第一个房间，再装第二个。CPU 连续取数据时，可能一直在同一房间排队。

---

<a id="sec-3-4-2"></a>
### 3.4.2 多体交叉存储器

#### 1. 交叉方式

连续地址轮流分布到不同存储体中。

![交叉](https://bsyimg.luoca.net/imgtc/20260617/8d4774e8ad2c415e153141abeb5d9640.webp)

若有 4 个存储体：

| 地址 | 所在体 |
|------|--------|
| 0 | M0 |
| 1 | M1 |
| 2 | M2 |
| 3 | M3 |
| 4 | M0 |
| 5 | M1 |

编址方式：

```text
低位地址作体号，高位地址作体内地址
```

#### 2. 特点

- 存储器分为多个体
- 程序或数据在各体中交叉存放
- 多个体可以并行工作
- 可同时取出多条指令或多个数据
- 能提高存储带宽
- 可能发生体冲突


> **通俗理解**：  
> 交叉存储像发牌一样，把连续数据轮流发给不同仓库。CPU 连续取数据时，多个仓库能同时准备，速度更快。

---

<a id="sec-3-5"></a>
## 3.5 高速缓冲存储器 Cache

<a id="sec-3-5-0"></a>
### 3.5.0 Cache 的基本思想

Cache 是 CPU 和主存之间的小容量高速存储器。

```text
CPU ←→ Cache ←→ 主存
```

目标：使平均访存时间尽量接近 Cache 的访问时间。

其前提仍然是**局部性原理**：

- 最近访问过的数据，之后可能还会访问
- 最近访问数据附近的数据，之后也可能访问

---

<a id="sec-3-5-1"></a>
### 3.5.1 相联存储器

#### 1. 作用

相联存储器用于判断 CPU 要访问的主存块是否已经在 Cache 中。

#### 2. 特点

普通存储器：

```text
按地址访问
```

相联存储器：

```text
按内容特征 key 访问
```

也就是通过比较标记 Tag 来快速判断是否命中。

> **通俗理解**：  
> Cache 像小冰箱，相联存储器像库存清单。CPU 报出要找的食材编号，清单能快速判断小冰箱里有没有。

---

<a id="sec-3-5-2"></a>
### 3.5.2 Cache 基本概念

| 概念 | 含义 |
|------|------|
| **主存块** | 主存按固定大小划分的块 |
| **Cache 行** | Cache 中存放一个主存块副本的位置 |
| **块内偏移** | 块内部的具体字节或字地址 |
| **Tag 标记** | 用于识别 Cache 行中存的是哪个主存块 |
| **Valid 有效位** | 表示该 Cache 行内容是否有效 |
| **Hit 命中** | 要访问的数据在 Cache 中 |
| **Miss 未命中** | 要访问的数据不在 Cache 中，需要访问主存 |

主存和 Cache 通常以**块**为单位交换数据。

---

<a id="sec-3-5-3"></a>
### 3.5.3 地址映射

地址映射指：如何把主存块放入 Cache 行。

三种基本方式：

```text
全相联映射
直接相联映射
组相联映射
```

---

#### 1. 全相联映射

##### （1）基本思想

任意主存块可以装入 Cache 的任意一行。

```text
主存任意块 → Cache 任意行
```

> **通俗理解**：  
> **操场上的任何学生进入教室后，只要有空座就可以随便坐。**

##### （2）地址结构

```text
主存地址 = Tag + 块内偏移
```

CPU 访问时，需要将目标 Tag 与 Cache 中所有行的 Tag 同时比较。

##### （3）容量公式

若 Cache 有 $n$ 行，Tag 为 $s$ 位，块内偏移为 $w$ 位，则每块数据大小为 $2^w$ 字节，即 $8\times 2^w$ 位。

Cache 实际容量为：

$$n \times (1 + s + 8\times 2^w)\ bit$$

其中：

- $1$：有效位
- $s$：Tag 位
- $8\times 2^w$：数据块副本

##### （4）优缺点

| 优点 | 缺点 |
|------|------|
| 映射最灵活，冲突概率低，命中率高 | 需要多路并发比较，硬件复杂，替换算法复杂 |

---

#### 2. 直接相联映射

##### （1）基本思想

每个主存块只能放到 Cache 的唯一一行。

映射公式：

$$i = j \bmod n$$

其中：

- $i$：Cache 行号
- $j$：主存块号
- $n$：Cache 行数

> **通俗理解**：  
> 对号入座（按学号取余）。若教室有 8 个座位，学号 1、9、17 都只能坐 1 号座位。

##### （2）地址结构

```text
主存地址 = Tag + Cache 行号 + 块内偏移
```

##### （3）容量公式

若 Cache 有 $n$ 行，主存块地址共 $s$ 位，Cache 行号占 $r$ 位，块内偏移占 $w$ 位，则 Tag 为 $s-r$ 位。

Cache 实际容量为：

$$n \times (1 + s-r + 8\times 2^w)\ bit$$

##### （4）优缺点

| 优点 | 缺点 |
|------|------|
| 硬件简单，速度快，不需要复杂查找 | 容易冲突，Cache 利用率低，命中率较低 |

> **Cache 颠簸**：  
> **如果多个常用主存块映射到同一个 Cache 行，它们会反复替换，即使其他 Cache 行空着也不能使用。**

---

#### 3. 组相联映射

##### （1）基本思想

Cache 分成若干组，每组有若干行。

```text
主存块先按规则定位到某一组，再在组内任选一行
```

> **通俗理解**：  
> 分组对号，组内随便坐。学生必须去指定的那一排，但这一排里哪个座位都可以。

##### （2）地址结构

```text
主存地址 = Tag + 组号 + 块内偏移
```

##### （3）查找方式

1. 根据组号定位到某一组
2. 在组内进行 $k$ 路并发比较
3. 若某一路 Tag 相等且有效位为 1，则命中

##### （4）优缺点

| 优点 | 缺点 |
|------|------|
| 比直接映射冲突少，比全相联硬件简单 | 比直接映射复杂，组内满时仍需替换 |

组相联映射是直接相联和全相联之间的折中，因此实际系统中很常用。

---

<a id="sec-3-5-4"></a>
### 3.5.4 三种映射方式对比

| 映射方式 | 主存块可放位置 | 比较次数 | 硬件复杂度 | 冲突概率 | 命中率 |
|----------|----------------|----------|------------|----------|--------|
| 全相联 | 任意 Cache 行 | 所有行并发比较 | 高 | 低 | 高 |
| 直接相联 | 唯一指定行 | 1 次 | 低 | 高 | 低 |
| 组相联 | 指定组内任意行 | 组内多路比较 | 中 | 中 | 中到高 |

---

<a id="sec-3-5-5"></a>
### 3.5.5 Cache 替换算法

当 Cache 未命中且目标位置已满时，需要决定替换哪一块。

| 替换算法 | 含义 | 特点 | 能否反映近期访问情况 |
|----------|------|------|----------------------|
| **FIFO** | 先进先出 | 替换最早进入 Cache 的块，实现简单 | / |
| **LFU** | 最不经常使用 | 替换访问次数最少的块，需要计数 | **否**（无法处理历史数据积累，新调入块易被替换） |
| **LRU** | 近期最少使用 | 替换最近最久未访问的块，符合时间局部性 | **是**（较好体现时间局部性，保护近期被访问的块） |
| **随机替换** | 随机选一块 | 实现简单，效果不稳定 | / |

> **易考点**：  
> 直接相联映射中，一个主存块只有唯一位置，严格来说不需要复杂替换算法；全相联和组相联才更关注替换策略。

> **【补充例子】LFU 与 LRU 的核心区别**
> 
> 假设 Cache 只能装下 3 个块，目前的块访问序列为：**A, A, A, A, A, B, C, D**。
> 
> 1. 当访问完 C 后，Cache 中装有 `[A, B, C]`。此时 A 的访问次数很高（5次），而 B 和 C 是刚调入的新块，访问次数很低（各1次）。
> 2. 接着要访问 **D**，发生 Cache 缺失，必须替换掉 Cache 中的一个块：
>    - **如果使用 LFU**：系统会发现 B 或 C 的访问次数最少，因此会**淘汰 B 或 C**。这导致刚刚才装入 Cache 的新数据（可能接下来马上要用）被错误替换，而很久以前频繁访问、现在已不用的 A 却因为“历史数据堆积”被保留了下来。
>    - **如果使用 LRU**：系统会发现 **A** 是距离现在最久没有被访问过的块，因此会**淘汰 A**。这就成功保护了刚刚调入的新块 B 和 C，更好地体现了程序运行的“时间局部性”规律。

---

<a id="sec-3-5-6"></a>
### 3.5.6 Cache 写策略

CPU 写 Cache 时，需要考虑是否同步修改主存。

#### 1. 写穿法 Write Through

**写 Cache 的同时立即写主存。**

| 优点 | 缺点 |
|------|------|
| 主存和 Cache 一致性好，实现简单 | 每次写都会访问主存，总线流量大，速度慢 |

#### 2. 写回法 Write Back

**只修改 Cache，并设置修改位 Dirty。等该块被替换时再写回主存。**

| 优点 | 缺点 |
|------|------|
| 减少主存写次数，降低总线流量 | 控制复杂，需要修改位，主存和 Cache 可能暂时不一致 |

#### 3. 写分配与写不分配

| 策略 | 含义 |
|------|------|
| **写分配** | **写未命中时，把对应主存块调入 Cache 后再写** |
| **写不分配** | **写未命中时，直接写主存，不调入 Cache** |

常见组合：

- 写回法 + 写分配
- 写穿法 + 写不分配

---

<a id="sec-3-5-7"></a>
### 3.5.7 Cache 命中率与平均访问时间

#### 1. 命中率

设：

- $N_c$：Cache 命中次数
- $N_m$：访问主存次数，即未命中次数

命中率：

$$H = \frac{N_c}{N_c + N_m}$$

未命中率：

$$1-H = \frac{N_m}{N_c + N_m}$$

#### 2. 平均访问时间

设：

- $t_c$：命中 Cache 时的访问时间
- $t_m$：访问主存所需时间
- $H$：命中率

若未命中时需要访问主存，则平均访问时间可近似为：

$$t_a = H \times t_c + (1-H) \times t_m$$

有些题目也会按“先查 Cache，未命中再访问主存”的过程计算：

$$t_a = t_c + (1-H) \times t_m$$

> **做题提醒**：  
> 要看题目如何定义 $t_m$：是“主存访问总时间”，还是“未命中额外代价”。

#### 3. 访问效率

课件中给出：

$$访问效率 = \frac{t_c}{t_a}$$

#### 4. 影响命中率的因素

- 程序局部性
- Cache 容量
- Cache 组织方式
- 块大小
- 替换算法

> **块越大一定越好吗？**  
> 不一定。块大能利用空间局部性，但块太大会导致 Cache 行数减少，可能增加冲突和替换，反而降低命中率。

<a id="sec-3-6"></a>
## 3.6 虚拟存储器

<a id="sec-3-6-1"></a>
### 3.6.1 基本概念

#### 1. 什么是虚拟存储器

虚拟存储器建立在**主存 - 辅存**物理结构基础上，由附加硬件和操作系统存储管理软件共同组成。

它把辅存看作一个巨大的“虚拟主存”，让用户感觉自己拥有一个足够大的主存空间。

特点：

- 用户程序使用虚地址编程
- 程序和数据主要存放在辅存中
- 程序运行时，只把当前需要的页或段调入主存
- CPU 实际只能执行已经调入主存的程序
- 主存与辅存之间的调度对用户透明

---

#### 2. 虚地址与实地址

| 地址 | 又称 | 含义 |
|------|------|------|
| **虚地址** | 逻辑地址、虚存地址 | 用户编程时使用的地址，可看作辅存地址 |
| **实地址** | 物理地址、主存地址 | CPU 实际访问主存时使用的地址 |

#### 3. 虚实地址转换过程

```text
用户用虚地址编程
        ↓
程序存放在辅存中
        ↓
CPU 运行时发出虚地址
        ↓
查页表或段表
        ↓
若已在主存：虚地址 → 实地址 → 访问主存
若不在主存：访问辅存 → 调入主存 → 修改表项 → 再访问主存
```

---

<a id="sec-3-6-2"></a>
### 3.6.2 虚存与 Cache 的比较

#### 1. 相同点

| 相同点 | 说明 |
|--------|------|
| 都属于存储层次结构 | Cache 位于 CPU 与主存之间，虚存位于主存与辅存之间 |
| 都把空间划分成信息块 | Cache 用块，虚存用页或段 |
| 都利用局部性原理 | 把常用信息调入更高层 |
| 都有替换问题 | 新块进入时可能淘汰旧块 |
| 都对用户透明 | 用户通常不需要关心具体调度过程 |

#### 2. 不同点

| 比较内容 | Cache | 虚拟存储器 |
|----------|-------|------------|
| 解决问题 | 弥补 CPU 与主存速度差距 | 弥补主存容量不足 |
| 所处层次 | CPU - 主存 | 主存 - 辅存 |
| 信息块大小 | 通常几十字节 | 页、段，几百字节到几百 KB |
| 速度差距 | Cache 比主存快 | 主存比辅存快很多 |
| 访问通道 | CPU、Cache、主存之间有直接通道 | CPU 不能直接访问辅存中的虚存内容 |
| 实现方式 | 主要由硬件实现 | 主要由 OS 软件 + 硬件支持实现 |

---

<a id="sec-3-6-3"></a>
### 3.6.3 页式虚拟存储器

#### 1. 页的划分

页式虚拟存储器以**页**为信息传送单位。

- 虚存划分为大小相同的**虚页**
- 主存划分为大小相同的**实页**或页框
- 页大小通常为 $512B$ 到几 KB

虚地址结构：

```text
虚地址 = 虚页号 P + 页内地址 D
```

实地址结构：

```text
实地址 = 实页号 p + 页内地址 d
```

页内地址不变：

$$D = d$$

地址变换的核心是：

```text
虚页号 P → 实页号 p
```

---

#### 2. 页表

页表记录虚页号与实页号之间的对应关系。

| 页表字段 | 含义 |
|----------|------|
| 虚页号 | 通常作为页表索引，不一定显式保存 |
| 实页号 | 该虚页当前所在的主存页框号 |
| 装入位 | 表示该页是否已在主存中 |
| 修改位 | 表示该页调入主存后是否被修改 |
| 替换控制位 | 为替换算法服务 |

页表特点：

- 每个程序通常有自己的页表
- 页表存放在主存固定区域
- 页表起始地址由页表基址寄存器保存
- 页表由操作系统建立和维护

#### 3. 快表与慢表

| 类型 | 存放位置 | 作用 |
|------|----------|------|
| **快表 TLB** | Cache 或专用高速相联存储器 | 保存页表部分副本，加快地址变换 |
| **慢表** | 主存 | 完整页表 |

---

#### 4. 页式虚存地址变换过程

1. CPU 给出虚地址：

```text
虚地址 = P + D
```

2. 用页表基址寄存器内容加虚页号 $P$，形成页表项地址
3. 查页表，判断装入位
4. 若装入位为 1：取出实页号 $p$
5. 将实页号 $p$ 与页内地址 $D$ 拼接，形成实地址
6. 若装入位为 0：发生缺页，从辅存调入该页，修改页表后再访问

```text
页表首址 + 虚页号P → 页表项
页表项中取实页号p
实地址 = p + 页内地址D
```

> **易错点**：  
> 页式存储中，页大小固定，所以虚地址和实地址的页内地址部分不变，只变换页号。

---

<a id="sec-3-6-4"></a>
### 3.6.4 段式虚拟存储器

#### 1. 段的划分

段式虚拟存储器以**段**为信息传送单位。

段按程序的逻辑结构划分，例如：

- 主程序段
- 子程序段
- 数据段
- 堆栈段

特点：

- 每段长度可以不同
- 每段可装入主存任意位置
- 段内地址从 0 开始
- 更符合程序的逻辑结构

#### 2. 段表

段表记录虚段与主存实际位置之间的对应关系。

| 段表字段 | 含义 |
|----------|------|
| 段号 | 通常作为段表索引 |
| 段起点 | 该段在主存中的起始地址 |
| 段长 | 该段长度，用于越界检查 |
| 装入位 | 表示该段是否已在主存 |
| 修改位 | 表示该段是否被修改 |
| 替换控制位 | 为替换算法服务 |

#### 3. 段式虚存地址结构

课件中给出的一种形式：

```text
虚地址 = 基号 b + 段号 s + 段内地址 d
```

地址变换过程：

1. CPU 给出虚地址
2. 根据基号查基址寄存器，得到段表首址 $S_0$
3. 用 $S_0 + 段号s$ 形成段表索引
4. 查段表，若装入位为 1，取出段起点
5. 实地址为：

$$实地址 = 段起点 + 段内地址d$$

6. 若装入位为 0，则从辅存调入该段，修改段表后再访问

#### 4. 页式与段式对比

| 比较内容 | 页式虚存 | 段式虚存 |
|----------|----------|----------|
| 划分依据 | 固定大小 | 程序逻辑结构 |
| 信息单位 | 页 | 段 |
| 大小 | 所有页大小相同 | 各段大小可不同 |
| 地址变换 | 虚页号 → 实页号，页内地址不变 | 段号 → 段起点，再加段内地址 |
| 优点 | 管理简单，便于分配 | 符合程序逻辑，便于共享和保护 |
| 缺点 | 不反映程序逻辑 | 容易产生外部碎片，管理较复杂 |

$$容量 = 存储单元数 \times 每单元位数$$

### 2. 存储带宽

$$BW = \frac{W}{T_M}$$

### 3. 多体交叉存储器编址

```text
低位地址 → 体号
高位地址 → 体内地址
```

### 4. 直接映射公式

$$i = j \bmod n$$

### 5. Cache 命中率

$$H = \frac{N_c}{N_c + N_m}$$

### 6. 平均访问时间

常见两种写法：

$$t_a = Ht_c + (1-H)t_m$$

或：

$$t_a = t_c + (1-H)t_m$$

具体采用哪一个，取决于题目对 $t_m$ 的定义。

### 7. 页式虚存地址变换

```text
虚地址 = 虚页号P + 页内地址D
实地址 = 实页号p + 页内地址d
D = d
```

### 8. 段式虚存地址变换

$$实地址 = 段起点 + 段内地址$$

## 本章易错点总结

1. **存取时间 $T_A$ 与存储周期 $T_M$ 不同**：$T_M$ 通常大于或等于 $T_A$。
2. **SRAM 不需要刷新，DRAM 需要刷新**。
3. **DRAM 读出可能破坏信息**，因此需要再生。
4. **位扩展增加字长，字扩展增加字数**。
5. **字位扩展通常先位扩展，再字扩展**。
6. **多体交叉存储器低位作体号**，这样连续地址分散到不同体中。
7. **全相联映射灵活但硬件复杂**；直接映射简单但冲突多；组相联是折中。
8. **直接映射通常不需要复杂替换算法**，因为位置唯一。
9. **写回法不是立即写主存**，而是替换时才写回。
10. **Cache 解决速度问题，虚拟存储器解决容量问题**。
11. **页式虚存页内地址不变**，只进行虚页号到实页号的转换。
12. **段式虚存需要检查段长**，防止段内地址越界。

---

## 本章一句话总结

存储系统通过 **Cache - 主存 - 辅存** 的层次结构，利用程序的时间局部性和空间局部性，把常用信息自动调入更快的上层存储器，从而在速度、容量和价格之间取得折中。
