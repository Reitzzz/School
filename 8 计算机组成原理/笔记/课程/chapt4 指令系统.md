## 4.0 指令系统概述

<a id="sec-4-0-1"></a>
### 4.0.1 基本概念

- **指令**：规定计算机执行什么操作、对哪些对象操作，并能被计算机识别和执行的二进制代码。
- **程序**：为解决某一问题而编制的指令序列。
- **指令系统**：一台计算机能够识别并执行的全部指令的集合。

指令系统的重要性：

1. 是计算机系统性能的集中体现。
2. 是软件和硬件之间的接口。
3. 是 CPU 设计的依据，也是软件设计的基础。

<a id="sec-4-0-2"></a>
### 4.0.2 指令系统的发展与性能要求

#### 1. 发展

```text
简单指令系统 SISC → 复杂指令系统 CISC → 精简指令系统 RISC
```

- **CISC**：指令系统不断扩充，兼容性较好，但指令复杂、效率可能下降。
- **RISC**：重新设计较精简的指令集，强调指令简单、执行高效。

#### 2. 指令系统性能

| 性能 | 含义 |
|------|------|
| **完备性** | 指令系统提供的指令足够使用，不必大量依靠软件模拟 |
| **有效性** | 用该指令系统编写的程序运行效率高，占用空间小、执行速度快 |
| **规整性** | 指令格式、寻址方式、数据类型支持具有规律性 |
| **兼容性** | 常指“向上兼容”，旧机器软件可在新机器上运行 |

规整性又包括：

- **对称性**：所有指令尽量都能使用各种寻址方式。
- **匀齐性**：指令尽量支持多种数据类型。
- **一致性**：指令长度与数据长度有一定关系，便于处理和存取。

<a id="sec-4-1"></a>
## 4.1 指令格式

指令格式是用二进制代码表示指令的结构形式。一条指令通常需要说明：

- 要做什么操作？
- 操作对象在哪里？
- 怎样找到操作数？
- 下一条指令在哪里？

<a id="sec-4-1-1"></a>
### 4.1.1 操作码与地址码

机器指令通常由两部分组成：

```text
操作码字段 OP + 地址码字段 D
```

更完整地看，指令中可能包含的信息有：

| 字段 | 作用 |
|------|------|
| **OP** | 操作码，指出执行何种操作 |
| **MOD / MO** | 寻址方式字段，指出如何形成有效地址 |
| **REG** | 寄存器编号字段 |
| **A1** | 第一源操作数地址 |
| **A2** | 第二源操作数地址 |
| **A3** | 目的操作数地址，即运算结果写入位置 |
| **A4** | 下一条指令地址 |

#### 指令格式的简化

实际机器中不会总把 $A_1,A_2,A_3,A_4$ 全部写入指令，而是常通过以下方式压缩：

1. 用 **PC/IP** 自动指出下一条指令地址，简化 $A_4$。
2. 用 **ACC 累加器** 隐含第一源操作数和目的操作数，简化 $A_1,A_3$。
3. 将指令简化为：

```text
OP + D
```

其中，$D$ 称为**形式地址**，不一定就是操作数的真实地址。

<a id="sec-4-1-2"></a>
### 4.1.2 常用指令格式

| 格式 | 结构 | 含义 | 例子/特点 |
|------|------|------|----------|
| **零地址指令** | `OP` | 操作数地址隐含在 SP、ACC 或寄存器中 | 停机、空操作、开关中断、堆栈操作 |
| **一地址指令** | `OP A1` | 常用 ACC 隐含另一个操作数 | $ACC \ OP\ [A_1] \rightarrow ACC$ |
| **二地址指令** | `OP A1 A2` | 两个地址分别指出两个操作数，其中一个也可作目的地址 | $[A_1] \ OP\ [A_2] \rightarrow [A_1]$ |
| **三地址指令** | `OP A1 A2 A3` | 两个源操作数和一个目的操作数都显式给出 | $[A_1] \ OP\ [A_2] \rightarrow [A_3]$ |

> 零地址、一地址指令常见于微型机；二地址、三地址指令常见于大中型机或教学模型。

<a id="sec-4-1-3"></a>
### 4.1.3 指令字长与助记符

#### 1. 指令字长

| 类型 | 特点 | 优点 | 缺点 | 例子 |
|------|------|------|------|------|
| **定长指令** | 所有指令字长固定 | 控制简单，取指通常只需一次访存 | 信息量少，寻址空间可能较小 | MIPS |
| **变长指令** | 指令字长可变 | 信息量大，寻址空间大 | 控制复杂，取指可能多次访存 | x86 |

#### 2. 助记符

用符号表示机器指令中的操作，形成汇编语言。例如：

| 助记符 | 含义 |
|------|------|
| `ADD` | 加法 |
| `SUB` | 减法 |
| `MOV` | 数据传送 |
| `JMP` | 无条件转移 |
| `IN` / `OUT` | 输入 / 输出 |
| `STA` | 写入内存 |
| `LDA` | 从内存读入 |

汇编语言需要经过汇编程序翻译成机器指令后才能执行。

<a id="sec-4-1-4"></a>
### 4.1.4 操作码扩展

#### 1. 基本思想

不同地址数的指令对地址码字段的需求不同：

- 二地址、三地址指令需要较多地址字段，操作码字段较短。
- 一地址、零地址指令需要较少地址字段，可以把空出的地址位扩展为操作码。

因此，可用某些操作码状态作为**扩展标识**，使短地址格式拥有更多操作码。

#### 2. 设计原则

- 各类指令的操作码编码不能重叠，否则译码器无法区分。
- 常用指令可分配较短操作码，不常用指令可用扩展操作码。
- 扩展操作码能提高编码利用率，但会增加译码和控制逻辑复杂度。

#### 3. 典型例题

设某指令系统指令字长为 16 位，每个地址码为 6 位。要求设计：

- 二地址指令 15 条
- 一地址指令 34 条
- 求最多还能设计多少条零地址指令？

分析：

1. 二地址格式：
   $$OP + A_1 + A_2$$
   地址码共 $6+6=12$ 位，所以操作码有 $16-12=4$ 位，可表示 $2^4=16$ 种状态。
2. 已用 15 种状态表示二地址指令，还剩 1 种状态作为扩展标识。
3. 一地址指令全集：
   $$1 \times 2^6 = 64 \text{ 条}$$
4. 已用 34 条一地址指令，还剩 $64-34=30$ 种状态继续扩展。
5. 每种扩展状态后面还可接一个 6 位字段表示零地址指令：
   $$30 \times 2^6 = 1920$$

所以最多还能设计 **1920 条零地址指令**。

<a id="sec-4-1-5"></a>
### 4.1.5 指令编码与操作数类型

#### 1. 指令编码要求

- 操作码越短越好。
- 所含信息量越多越好。
- 使用频繁的指令尽量使用短操作码，使剩余字段能表达更多寻址方式和寄存器编号。

#### 2. 霍夫曼编码思路

1. 建立指令使用频度表，并按频度从大到小排序。
2. 合并最小概率的信息单元，形成霍夫曼树。
3. 沿树枝分配编码，得到各指令编码。
4. 对编码进行规整，便于控制器和译码器设计。

#### 3. 操作数类型

按操作数存放位置分：

| 类型 | 操作数位置 |
|------|----------|
| **存储器类型** | 操作数在主存中，$D$ 提供地址信息 |
| **寄存器类型** | 操作数在 CPU 通用寄存器中 |
| **立即数类型** | 操作数直接在指令的地址字段中 |
| **I/O 接口类型** | 操作数在 I/O 接口中 |

按操作数性质分：

- **地址**：存储器地址，本质上是无符号整数。
- **数字**：定点整数、定点小数、浮点数、十进制数。
- **字符**：字符编码数据。
- **逻辑数据**：真假两种状态。

## 4.2 寻址方式

寻址方式是指**寻找并确定本条指令所需操作数地址，以及确定下一条要执行指令地址的方法**。

```text
寻址方式
├── 指令寻址：确定下一条指令地址
└── 数据寻址：确定本条指令操作数地址
```

<a id="sec-4-2-1"></a>
### 4.2.1 指令寻址方式

#### 1. 顺序寻址

由 **PC/IP** 指示当前或下一条指令地址。每取出一条指令后：

$$PC+1 \rightarrow PC$$

特点：

- 适合顺序执行的程序。
- 地址由程序计数器自动形成，不必在指令中显式给出下一条指令地址。

#### 2. 跳跃寻址

由当前指令给出下一条指令地址，将新地址送入 PC/IP：

$$D \rightarrow PC$$

常见于：

- 转移指令
- 子程序调用
- 中断处理

<a id="sec-4-2-2"></a>
### 4.2.2 数据寻址的基本概念

指令中的地址码字段通常不直接表示操作数真实地址。

- **形式地址**：指令地址码字段给出的地址信息，记为 $D$。
- **有效地址**：操作数实际所在位置的地址，记为 $EA$。

有效地址由寻址方式和形式地址共同决定：

$$EA = f(MOD, REG, D)$$

可抽象为：

```text
OP* | MOD | REG | D
```

其中：

- `OP*`：基础操作码
- `MOD`：寻址方式
- `REG`：寄存器编号
- `D`：形式地址或偏移量

<a id="sec-4-2-3"></a>
### 4.2.3 十种操作数寻址方式

#### 总表

| 序号 | 寻址方式 | 操作数位置 | 有效地址/操作数关系 | 访存特点 | 常见用途 |
|------|----------|------------|---------------------|----------|----------|
| 1 | **隐含寻址** | 隐含在 ACC、SP 或其他寄存器中 | 地址不显式给出 | 指令短 | 单操作数、累加器、堆栈类指令 |
| 2 | **立即寻址** | 指令地址字段中 | 操作数 $=D$ | 执行阶段不访存取数 | 常数操作数 |
| 3 | **直接寻址** | 主存中 | $EA=D$ | 需访问主存取操作数 | 简单内存访问 |
| 4 | **间接寻址** | 主存中 | $EA=(D)$ | 至少两次访存 | 扩大寻址范围，访问指针 |
| 5 | **寄存器寻址** | CPU 寄存器中 | 操作数 $=(REG)$ | 不访存取数，速度快 | 高频临时数据 |
| 6 | **寄存器间接寻址** | 主存中 | $EA=(REG)$ | 访问一次主存取操作数 | 指针、数组访问 |
| 7 | **变址寻址** | 主存中 | $EA=(IX)+D$ | 需访问主存取操作数 | 数组、数据表 |
| 8 | **基址寻址** | 主存中 | $EA=(BR)+D$ | 需访问主存取操作数 | 程序定位、段/页定位 |
| 9 | **相对寻址** | 主存中 | $EA=(PC)+D$ | 需访问主存取目标 | 转移指令 |
| 10 | **堆栈寻址** | 栈顶主存单元 | $EA=(SP)$ | 由 SP 隐含 | 子程序、中断现场保护 |

> 记忆线索：  
> **立即看 D，直接找 D，间接先到 D 取地址；寄存器看 REG，寄存器间接从 REG 取地址；变址/基址/相对都是“某寄存器 + D”；堆栈看 SP。**

#### 1. 隐含寻址

操作数地址不在地址码字段中显式给出，而是隐含在操作码或约定寄存器中。

常见隐含位置：

- **ACC**：累加器
- **SP**：堆栈指针
- 某些固定寄存器

例：

```asm
NEG
NOT
CLA
```

特点：

- 指令很短。
- 硬件约定强，灵活性较弱。

#### 2. 立即寻址

操作数直接放在指令的地址码字段中：

$$操作数 = D$$

也可写作：

```text
OP D
D = DATA
```

例：

```asm
ADD A, #01H
MOV A, #01H
```

特点：

- 取指时操作数随指令一并取出。
- 执行阶段不需要访问主存取操作数，速度快。
- 适合常数，但立即数长度受指令字长限制。

#### 3. 直接寻址

地址码字段直接给出操作数所在主存单元地址：

$$EA = D$$

操作数为：

$$(EA) = (D)$$

例：

```asm
ADD A, [3050H]
MOV A, [3050H]
```

特点：

- 简单直观。
- 地址字段长度限制了直接寻址范围。

#### 4. 间接寻址

地址码字段 $D$ 中存放的不是操作数地址，而是**操作数地址所在的主存地址**：

$$EA = (D)$$

操作数为：

$$(EA)=((D))$$

例：

```asm
ADD A, @[3050H]
MOV A, @[3050H]
```

特点：

- 可以扩大寻址范围。
- 适合指针类访问。
- 需要多次访问主存，速度较慢。

#### 5. 寄存器寻址

操作数直接存放在指令规定的寄存器中，指令给出寄存器编号：

$$操作数 = (REG)$$

例：

```asm
ADD A, Ri
MOV A, Ri
```

特点：

- 操作数在 CPU 内部，速度快。
- 指令短，只需给出寄存器编号。
- 寄存器数量有限。

#### 6. 寄存器间接寻址

寄存器中存放的是操作数所在主存单元的地址：

$$EA = (REG)$$

操作数为：

$$(EA)=((REG))$$

例：

```asm
ADD A, @Ri
MOV A, @Ri
```

特点：

- 比间接寻址少一次访问主存。
- 指令短，寻址灵活。
- 常用于指针、数组、链表等结构。

#### 7. 变址寻址

形式地址 $D$ 作为偏移量，与变址寄存器内容相加形成有效地址：

$$EA = (IX) + D$$

课件中常以 `SI`、`DI` 为变址寄存器：

$$EA = (SI \text{ 或 } DI) + D$$

例：

```asm
ADD A, [SI + D]
MOV A, [DI + D]
```

特点：

- 适合访问数组和数据表。
- 通常可把 $D$ 看作表首地址或固定偏移，把变址寄存器看作下标。
- 使用灵活，寻址空间较大。

#### 8. 基址寻址

形式地址 $D$ 作为偏移量，与基址寄存器内容相加形成有效地址：

$$EA = (BR) + D$$

课件中常以 `BX`、`BP` 为基址寄存器：

$$EA = (BX \text{ 或 } BP) + D$$

例：

```asm
ADD A, [BX + D]
MOV A, [BP + D]
```

特点：

- 适合程序重定位。
- 常用于系统程序中的程序定位，如段表、页表起始地址。
- 基址寄存器给出一个基准位置，形式地址给出段内或页内偏移。

#### 9. 相对寻址

形式地址 $D$ 作为相对偏移量，与 PC/IP 内容相加形成目标地址：

$$EA = (PC) + D$$

或：

$$EA = (IP) + D$$

特点：

- 主要用于转移指令。
- 偏移量可正可负，通常用补码表示。
- 可相对当前 PC 向前或向后转移。

例：

```asm
JR SUB1 - $
```

其中 `$` 常表示当前指令地址或当前位置。

#### 10. 堆栈寻址

操作数位于堆栈中，栈顶地址由堆栈指针寄存器 **SP** 隐含指出：

$$EA = (SP)$$

堆栈特点：

- 由若干连续主存单元组成。
- 按 **先进后出 FILO** 工作。
- 栈底固定，栈顶随入栈、出栈变化。
- 栈顶地址由 SP 指出。

一般计算机中，堆栈从高地址向低地址扩展，即栈底地址大于或等于栈顶地址。

常见操作：

| 操作 | 功能 | 若数据字长为 1B，典型动作 |
|------|------|---------------------------|
| `PUSH Ri` | 将寄存器内容压入堆栈 | $SP-1 \rightarrow SP,\ Ri \rightarrow (SP)_M$ |
| `POP Ri` | 从栈顶弹出数据送入寄存器 | $(SP)_M \rightarrow Ri,\ SP+1 \rightarrow SP$ |

用途：

- 子程序调用保存返回地址。
- 中断时保存现场。
- 临时保存寄存器内容。

<a id="sec-4-2-4"></a>
### 4.2.4 寻址方式例题

设某机：

- 指令形式地址 $D=100$
- $PC=1000$
- 基址/变址寄存器内容 $(R)=2000$
- 主存内容：$(100)=200,\ (200)=500,\ (1100)=100,\ (2100)=200$

则不同寻址方式下：

| 寻址方式 | 有效地址 $EA$ | 操作数 |
|----------|---------------|--------|
| 立即寻址 | 无需形成主存有效地址 | $D=100$ |
| 直接寻址 | $EA=D=100$ | $(100)=200$ |
| 间接寻址 | $EA=(D)=(100)=200$ | $(200)=500$ |
| 相对寻址 | $EA=(PC)+D=1000+100=1100$ | $(1100)=100$ |
| 变址/基址寻址 | $EA=(R)+D=2000+100=2100$ | $(2100)=200$ |

若出现**变址间址**：

$$EA=((R)+D)$$

即先求出 $(R)+D$，再把该地址单元中的内容作为有效地址。

## 4.3 指令类型

| 类型 | 功能 | 常见指令 |
|------|------|----------|
| **数据传送指令** | 在寄存器、主存、I/O 之间传送数据 | `MOV`、`LD`、`ST` |
| **算术逻辑运算指令** | 加、减、乘、除，与、或、非、异或等 | `ADD`、`SUB`、`MUL`、`DIV`、`AND`、`OR`、`NOT`、`XOR` |
| **移位操作指令** | 算术移位、逻辑移位、循环移位 | 左移、右移、带进位循环移位 |
| **程序控制类指令** | 改变程序执行顺序 | `JMP`、条件转移、`CALL`、`RET` |
| **堆栈操作指令** | 入栈、出栈 | `PUSH`、`POP` |
| **输入输出指令** | CPU 与外设端口交换数据 | `IN`、`OUT` |
| **处理器控制指令** | 控制处理器状态 | `WAIT`、`HALT`、`NOP`、开/关中断 |
| **特权指令** | 只允许操作系统或系统软件使用 | `ESC` 等 |

### 1. 数据传送指令

实现以下对象之间的数据传送：

- 寄存器 $\leftrightarrow$ 寄存器
- 寄存器 $\leftrightarrow$ 存储单元
- 存储单元 $\leftrightarrow$ 存储单元

### 2. 算术逻辑运算指令

算术运算：

- 加
- 减
- 乘
- 除

逻辑运算：

- 与
- 或
- 非
- 异或

有些机器还提供位操作指令，如位测试、位清零、位求反。

### 3. 移位操作指令

移位可分为：

| 类型 | 特点 |
|------|------|
| **算术移位** | 保持符号位含义，常用于有符号数乘除 2 |
| **逻辑移位** | 空出位补 0，常用于无符号数或逻辑数据 |
| **循环移位** | 移出的位再送回另一端 |
| **带进位循环移位** | 通过进位标志 `CF` 参与循环 |

### 4. 程序控制类指令

#### 无条件转移

无条件转至目的地址执行：

```asm
JMP D
```

功能：

$$D \rightarrow PC$$

#### 条件转移

条件满足时转移，否则顺序执行：

```asm
JR NC D
```

功能：

- 条件满足：$D \rightarrow PC$
- 条件不满足：$PC+1 \rightarrow PC$

#### 调用与返回

调用指令：

```asm
CALL D
```

典型功能：

$$SP-1 \rightarrow SP$$
$$PC \rightarrow (SP)_M$$
$$D \rightarrow PC$$

返回指令：

```asm
RET
```

典型功能：

$$(SP)_M \rightarrow PC$$
$$SP+1 \rightarrow SP$$

## 本章小结

- 机器指令由**操作码字段**和**地址码字段**组成。
- 地址码字段可包含源操作数地址、目的操作数地址、下一条指令地址等信息，但实际机器常用 PC、ACC、SP 等隐含机制简化格式。
- 扩展操作码可以提高编码利用率，但会增加硬件译码和控制复杂度。
- 寻址方式分为**指令寻址**和**数据寻址**。指令寻址主要有顺序寻址和跳跃寻址。
- 数据寻址的核心是由形式地址 $D$ 和寻址方式得到有效地址 $EA$。
- 十种操作数寻址方式为：隐含、立即、直接、间接、寄存器、寄存器间接、变址、基址、相对、堆栈。
- 指令类型可按功能分为数据传送、算术逻辑、移位、程序控制、堆栈、输入输出、处理器控制、特权指令等。
